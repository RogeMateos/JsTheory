Applying CSS Classes Dynamically with JavaScript

Change element appearance by manipulating classes instead of inline styles

🎯 Simple Definition for Interviews

What's the main idea?

Use JavaScript to add or remove CSS classes instead of modifying styles directly.

This way, CSS handles the "how it looks" and JavaScript handles the "when to change".

💡 Key Concept: Separation of Concerns

Don't do this ❌

job.style.display = 'none'
job.style.display = 'flex'

Here you're mixing CSS and JavaScript logic. It's hard to maintain.

Do this instead ✅

job.classList.add('is-hidden')

JavaScript decides when to change, CSS defines how it looks.

The mental rule

CSS = appearance

JavaScript = behavior

1️⃣ Why You Shouldn't Use .style Directly

Non-recommended example

job.style.display = 'none'  // hide
job.style.display = 'flex'  // show

Problems with this approach

  • Mixes concerns (logic and presentation)
  • Less maintainable (changing CSS means changing JS)
  • Harder to scale to large projects
  • More repetitive
  • Less readable

Better approach

Define a class in CSS:

.is-hidden {
  display: none;
}

Then add or remove that class from JavaScript.

2️⃣ Defining a CSS Class to Hide Elements

Create a reusable class

.is-hidden {
  display: none;
}

What do we gain?

Now any element with that class will be hidden:

<div class="job is-hidden">Hidden offer</div>

Remove the class and the element shows again.

3️⃣ Using classList

The classList property

classList lets us manipulate an element's classes easily.

Most important methods

Method What it does
add() Adds a class
remove() Removes a class
toggle() Adds or removes based on existence
contains() Checks if it exists
replace() Replaces one class with another

4️⃣ Real Example: Filtering Job Listings

The scenario

You have several job offers, each with a data-modality attribute:

<div class="job" data-modality="remote">Frontend Developer</div>
<div class="job" data-modality="hybrid">React Developer</div>
<div class="job" data-modality="in-office">UI Developer</div>

The user selects a filter:

const selectedValue = 'remote'

We want to show only the offers that match the selected modality.

5️⃣ Solution with add() and remove()

Complete code

jobs.forEach((job) => {
  const modality = job.getAttribute('data-modality')
  const isShown = selectedValue === '' || selectedValue === modality

  if (isShown) {
    job.classList.remove('is-hidden')
  } else {
    job.classList.add('is-hidden')
  }
})

Step-by-step explanation

  1. Loop through each offer

    jobs.forEach((job) => {}) - Iterate over each element

  2. Read its data-modality

    const modality = job.getAttribute('data-modality') - Returns "remote", "hybrid", "in-office"

  3. Calculate if it should be shown

    const isShown = selectedValue === '' || selectedValue === modality

    If no filter → show all

    If matches → show

    If doesn't match → hide

  4. Add or remove the class

    If should show → classList.remove('is-hidden')

    If should hide → classList.add('is-hidden')

6️⃣ More Elegant Solution with toggle()

Same logic, more compact

jobs.forEach((job) => {
  const modality = job.getAttribute('data-modality')
  const isShown = selectedValue === '' || selectedValue === modality

  job.classList.toggle('is-hidden', !isShown)
})

Very important: What does toggle() do with a second parameter?

job.classList.toggle('is-hidden', !isShown)

If the second parameter is true → adds the class

If the second parameter is false → removes the class

Why do we use !isShown?

isShown = "Should it be shown?"

is-hidden = "Should it be hidden?"

One means show and the other hide, they're opposite. That's why we negate with !

Mental translation

If should be shown:

isShown = true

!isShown = false

job.classList.toggle('is-hidden', false) → removes is-hidden


If should not be shown:

isShown = false

!isShown = true

job.classList.toggle('is-hidden', true) → adds is-hidden

7️⃣ Advantages of Using Classes Instead of style

1. Separation of concerns

CSS decides how something looks

JavaScript decides when to change it

2. Easier to maintain

If tomorrow you want to change how elements are hidden:

.is-hidden {
  visibility: hidden;
  opacity: 0;
}

You only touch CSS. No need to modify JavaScript.

3. Cleaner code

With classes: job.classList.add('is-hidden')

With styles: job.style.display = 'none'

The first expresses intent more clearly.

4. Reusability

The .is-hidden class can be used anywhere in the project.

8️⃣ Other Useful classList Methods

contains() - Check if element has a class

if (job.classList.contains('is-hidden')) {
  console.log('The element is hidden')
}

replace() - Replace one class with another

job.classList.replace('is-hidden', 'is-visible')

Useful when only one of the two should exist.

Add multiple classes at once

job.classList.add('featured', 'highlighted', 'premium')

Remove multiple classes at once

job.classList.remove('featured', 'highlighted', 'premium')

9️⃣ Complete and Realistic Example

HTML

<select id="filter">
  <option value="">All</option>
  <option value="remote">Remote</option>
  <option value="hybrid">Hybrid</option>
  <option value="in-office">In-Office</option>
</select>

<div class="job-list">
  <div class="job" data-modality="remote">Frontend Developer</div>
  <div class="job" data-modality="hybrid">React Developer</div>
  <div class="job" data-modality="in-office">UI Developer</div>
  <div class="job" data-modality="remote">JavaScript Engineer</div>
</div>

CSS

.is-hidden {
  display: none;
}

JavaScript

const filter = document.querySelector('#filter')
const jobs = document.querySelectorAll('.job')

filter.addEventListener('change', () => {
  const selectedValue = filter.value

  jobs.forEach((job) => {
    const modality = job.getAttribute('data-modality')
    const isShown = selectedValue === '' || selectedValue === modality

    job.classList.toggle('is-hidden', !isShown)
  })
})

Complete flow

  1. User changes the select
  2. We read the selected value
  3. We loop through all offers
  4. We check the data-modality of each one
  5. We calculate if it should be shown
  6. We add or remove .is-hidden

🔟 Accessibility: Important Detail

When you hide with display: none

The element:

  • Disappears visually ✅
  • Is hidden from screen readers ✅

You usually don't need to add aria-hidden="true" because display: none already does it.

But there are exceptions

When you hide with techniques like:

  • opacity: 0
  • visibility: hidden
  • Moving off-screen

Then you should pay more attention to accessibility and use aria-hidden.

Hide with explicit accessibility

job.classList.add('is-hidden')
job.setAttribute('aria-hidden', 'true')

Show again

job.classList.remove('is-hidden')
job.removeAttribute('aria-hidden')

1️⃣1️⃣ Important Note: Optimization

What we're doing now

We're hiding elements that stay in the DOM. This works well for small interfaces.

Future improvements

Option 1: Filter in JavaScript properly

Instead of rendering everything and hiding, build only the elements that should appear.

Option 2: Filter from the backend

The server returns only the results needed.

This saves: memory, processing, unnecessary renders, bandwidth.

1️⃣4️⃣ Pro Version of the Concept

UI States, not styles

When you use classList, you're not changing the design directly.

You're saying: "This element is now in the is-hidden state".

That's more professional because you work with UI states, not loose styles.

Common state classes in real projects:

  • is-hidden - Hidden element
  • is-active - Active element (selected)
  • is-open - Modal or menu open
  • is-disabled - Disabled element
  • is-selected - Selected element
  • is-loading - Loading data
  • is-error - Error state

The professional pattern

JavaScript changes the state with classList.

CSS defines how that state looks.

HTML just marks the structure.

1️⃣5️⃣ Final Phrase to Remember

💡 Always remember

"Don't change styles from JavaScript if you can change states with classes."

This makes your code:

  • More readable
  • More maintainable
  • More scalable
  • More professional
