Difference between ?. and ?? (Optional Chaining vs Nullish Coalescing)

Two different operators that always appear together in modern JavaScript

🎯 Simple Definition for Interviews

Optional Chaining (?.)

?. = "if it exists, continue"

Prevents errors when something might not exist.

Nullish Coalescing (??)

?? = "if it's null or undefined, use this"

Provides a default value.

1️⃣ Optional Chaining (?.)

What does it do?

Prevents errors when trying to access properties that might not exist.

const user = null

// Without ?.:
console.log(user.name)  // ❌ Error: Cannot read properties of null

// With ?.:
console.log(user?.name) // ✅ undefined (no error)

Mental translation

?. = "if it exists, access it. If it doesn't exist, return undefined"

2️⃣ Nullish Coalescing (??)

What does it do?

Provides a default value when something is null or undefined.

const name = null

console.log(name ?? "Anonymous")  // "Anonymous"

const age = 0
console.log(age ?? 18)  // 0 (because 0 is not null/undefined)

Mental translation

?? = "if this is null or undefined, use the right value"

📊 Direct Comparison

Optional Chaining (?.)
const user = {
  profile: {
    name: "Miguel"
  }
}

user?.profile?.name
// → "Miguel"

user?.profile?.city
// → undefined (no error)
Nullish Coalescing (??)
const username = null

username ?? "Guest"
// → "Guest"

const price = 0

price ?? 100
// → 0

Key point

?. prevents access errors

?? provides an alternative value

🔥 Real Example: Used Together

The most common case

const user = {
  profile: {
    name: "Roge"
  }
}

const username = user?.profile?.name ?? "Anonymous"
console.log(username)  // "Roge"

How JavaScript interprets it

  1. Tries to access user.profile.name
  2. If it doesn't exist, returns undefined (due to ?.)
  3. Then ?? checks: is it undefined?
  4. If it is undefined, uses "Anonymous"

⚠️ When Information Is Missing

Example when user is null

const user = null

const username = user?.profile?.name ?? "Anonymous"
console.log(username)  // "Anonymous"

Why does it work?

user?.profile?.name    // → undefined
undefined ?? "Anonymous" // → "Anonymous"

🚨 Common Confusion: ?? vs ||

?? and || are not the same

|| considers many values as "falsy":

false
0
""
null
undefined

Example with ||

const price = 0

console.log(price || 10)  // 10
// ❌ Incorrect: 0 is a valid value

Example with ??

const price = 0

console.log(price ?? 10)  // 0
// ✅ Correct: 0 is not null/undefined

⚡ Important

?? only checks null and undefined

|| checks any falsy value

💡 Practical Example: API Response

API data that might be incomplete

const response = {
  data: {
    user: {
      name: "Miguel",
      profile: {
        city: "Madrid"
      }
    }
  }
}

const city = response?.data?.user?.profile?.city ?? "Unknown city"
console.log(city)  // "Madrid"

If data is missing

const response = {
  data: null
}

const city = response?.data?.user?.profile?.city ?? "Unknown city"
console.log(city)  // "Unknown city"

🎯 Quick Decision Table

Situation Use Example
Access property that might not exist ?. user?.name
Provide default value ?? name ?? "Guest"
Safe access + default value ?. and ?? user?.name ?? "Guest"

🔥 Very Common in React

Typical example in components

// Props that might not come
const username = props?.user?.name ?? "Anonymous"

// API data
const avatar = data?.user?.profile?.avatar ?? defaultAvatar

// Optional objects
const city = user?.address?.city ?? "Unknown"

This combination is extremely common in modern applications.

📝 Ultimate Mental Rule

Memorize this:

?. = prevents errors (safe access)

?? = alternative value (default)

?. and ?? = safe access + default value

Complete example

const city = user?.address?.city ?? "Unknown city"

// Translation:
// "If user.address.city exists use it,
//  if it doesn't exist use 'Unknown city'"

✅ Conclusion

Two operators, two purposes

  • ?. → Prevents the application from breaking
  • ?? → Provides a safe fallback

Together they're a powerful combination for writing robust code.

💡 Professional tip

This combination is one of the most important patterns in modern JavaScript and React.

You'll see this constantly in professional code:

data?.user?.profile?.avatar ?? defaultAvatar
