Using this in JavaScript

Why it’s confusing

this doesn’t point to the function itself—it points to whoever invoked it. The value changes based on where and how the call happens, which can lead to surprises if you don’t control it.

Core idea

Think of this as the "owner" of the current execution. In regular functions the owner is chosen at call time; in arrow functions the owner is inherited from where the function was defined.

🧠 The Visual Fundamental Idea

Regular function

👉 this = whoever executes the function

Arrow function

👉 this = the this of the environment where it was created

🧠 The ultimate analogy

Imagine this as the "boss":

  • Regular function → The boss is whoever calls you to the office
  • Arrow function → The boss is whoever hired you originally

💥 The phrase you must remember

Regular function → this is dynamic

Arrow → this is lexical

handler (root object)
│

│

     │

⚡ The flow of this:

In REGULAR functions: this is decided at execution time

In arrow functions: this is inherited from the scope where it was defined

In this case, both point to handler because the arrow function is inside a regular function executed by handler.

What Does "Executing a Function" Mean?

A function does nothing until someone calls it

Defining ≠ Executing

1️⃣ Defining a function
function greet() {
  console.log("Hello");
}

// You're just storing it in memory here
// It doesn't run yet
2️⃣ Executing a function
greet();

// The parentheses () mean:
// 👉 "Execute what's inside"
// NOW the code runs

🔥 So... what does "who executes" mean?

It means:

From which object or context is the function being called?

Because that determines the value of this.

Step by step: person.greet()

const person = {
  name: "Roge",
  greet: function () {
    console.log("Hi, I'm", this.name);
  }
};

person.greet();

🔎 Breakdown

1️⃣ person.greet

This means:

  • 👉 Go to the object person
  • 👉 Find the property greet

2️⃣ person.greet()

The () means:

  • 👉 Execute the function
  • 👉 But execute it as a method of person

The important part:

When a function is called using the dot (object.function()):

👉 The object on the left side of the dot is who executes it

In this case: person executes it

Therefore: this === person

📌 Why do we say "who executes"?

Because JavaScript internally does something like this:

person.greet()

// It's interpreted as:
// "Call greet with person as the context"
// Or: "Execute this function and use person as this"

📦 Visualize it this way

Think of it as a command:

person → "Hey greet, execute yourself"

Then inside greet:
👉 this points to whoever gave the command: person

🔥 Now watch what happens if we change how we call it

const fn = person.greet;

fn();

// Now:
// fn() → No dot
// No object on the left
// 👉 Nobody specific is executing it
// 👉 this is no longer person

🎯 The mental rule you need

If there's a dot:

object.method()
// 👉 this = object

If there's NO dot:

function()
// 👉 this = window (in browser)
// 👉 or undefined (in strict mode)

🧠 A simple analogy

Imagine the function is an employee.

If the boss says:

Person: execute this
// The employee knows their boss is person

If someone yells from nowhere:

Execute!
// The employee doesn't know who the boss is

💡 Ultra-clear summary

"Executing" means:

  • 👉 Calling the function using ()
  • 👉 And the value of this depends on HOW you call it

It doesn't depend on where it's written.

It depends on how you call it.

💥 Dynamic vs Lexical: The Fundamental Difference

💥 "Regular function → this is dynamic"

What does dynamic mean?

That it changes depending on how the function executes.

  • It's not fixed when you define it
  • It's decided at the moment of invocation

🔎 Clear example

function show() {
  console.log(this.name);
}

const obj1 = { name: "Roge", show };
const obj2 = { name: "Carlos", show };

obj1.show(); // Roge
obj2.show(); // Carlos

👉 It's the same function.

👉 But this changes.

That's dynamic.

💥 "Arrow → this is lexical"

What does lexical mean?

"Lexical" means:

It depends on where the function was written.

  • It doesn't change no matter how you call it
  • It keeps the this of the environment surrounding it

🔎 Clear example

const name = "Global";

const obj = {
  name: "Roge",
  show: () => {
    console.log(this.name);
  }
};

obj.show();

// Result in browser:
// Global

Why?

Because the arrow was defined in global scope.

So it inherits that this.

It doesn't matter that you call it as obj.show().

🎯 Brutally clear visual difference

Regular function

obj.method()
👉 this = obj

If you do:
const fn = obj.method;
fn();
👉 this changes
Arrow Function

const obj = {
  method: () => {
    console.log(this);
  }
};

👉 this is NOT obj
👉 It's the this of where it was created
👉 And it never changes

🧠 A powerful analogy

Regular function

It's like a freelance actor.

Works for whoever hires them that day.

Arrow

It's like a permanent employee.

Always answers to the same boss (the context where it was born).

🔥 The example that makes it all clear

const person = {
  name: "Roge",
  regular: function () {
    console.log("Regular:", this.name);
  },
  arrow: () => {
    console.log("Arrow:", this.name);
  }
};

person.regular();  // Regular: Roge
person.arrow();    // Arrow: undefined

🧠 Dynamic vs Lexical Comparison Table

                      Regular function    Arrow
When is it decided?   At execution         At definition
Can it change?        Yes                  No
Type of this          Dynamic              Lexical

🎯 Final phrase to remember

Regular function → this depends on how you call it.

Arrow → this depends on where you write it.

📊 Mental Diagram: Structure of this

How this works in a nested structure

OBJECT
└── method()  ← regular function
    ├── this = object ✅
    └── arrow()  ← arrow function
        └── this = (inherited from method) ✅

📌 Correct reading:

  • 🔵 method() → this = object (because the object called it)
  • 🟡 arrow() → copies the this from method() (because it's inside)

The arrow doesn't look at the object, it looks up ⬆️

Example with result

const handler = {
  name: "Brais",
  greeting() {
    const arrowGreeting = () => {
      console.log(`Hello, ${this.name}`);
    };
    arrowGreeting();
  }
};

handler.greeting(); // ✅ Hello, Brais

Global context vs. objects

Quick rule

In the browser’s global scope, this is window; in Node.js it’s typically global. Inside an object method, this points to that object if it makes the call.

Global context
function getName() {
  console.log(this.name);
}

global.name = 'Global Name'; // Node.js
getName(); // "Global Name"

// In the browser
window.name = 'Global Name';
getName(); // "Global Name"
Inside an object
const user = {
  name: 'MyObject Name',
  getName: function() {
    console.log(this.name);
  }
};

user.getName(); // "MyObject Name"

Arrow functions and inherited this

No own context

Arrow functions don’t create their own this; they inherit it from the surrounding scope.

const myObject = {
  name: 'MyObject Name',
  getName: () => {
    console.log(this.name);
  }
};

global.name = 'Global Name';
myObject.getName(); // "Global Name" (inherited from outer scope)

  • 🟡 arrow() → copies this from method()

Magic phrase (memorize it)

Practical rule

  • ✅ Arrow → callbacks, setTimeout, map, filter
  • ❌ Arrow → object methods
  • ✅ Regular function → methods that use this

Changing context explicitly

function getName() {
  console.log(this.name);
}

const myObject = { name: 'MyObject Name' };

getName.call(myObject);  // "MyObject Name"
getName.apply(myObject); // "MyObject Name"

function getName() {
  console.log(this.name);
}

const myObject = { name: 'MyObject Name' };
const boundGetName = getName.bind(myObject);

boundGetName(); // Always "MyObject Name"

Nested functions and fixing with bind

const account = {
  owner: 'Ada',
  printOwner() {
    function inner() {
      console.log(this.owner);
    }
    inner.call(this); // or inner.bind(this)()
  }
};

account.printOwner(); // "Ada"
