Optional Chaining (?.)

Safely access properties that might not exist

🎯 Simple Definition for Interviews

Optional Chaining (?.)

The ?. operator means: "Only access this if it exists"

Prevents errors when trying to access properties of null or undefined.

❌ The Problem It Solves

When the element doesn't exist

Imagine you're searching for a button in the DOM:

const button = document.querySelector('#important-button')
button.addEventListener('click', () => {
  console.log('Click')
})

If that button doesn't exist in the HTML:

button = null

// JavaScript tries to execute:
null.addEventListener()

// ❌ Error:
// Uncaught TypeError: Cannot read properties of null

The application breaks 💥

If you try to access a property of null or undefined, JavaScript throws an error and the code stops.

📖 Classic Solution (Before ES2020)

Check with if

You had to validate first if it exists:

const button = document.querySelector('#important-button')

if (button) {
  button.addEventListener('click', () => {
    console.log('Click')
  })
}

What does it mean?

  • If button exists → execute the code
  • If button is null → do nothing

It works, but generates a lot of repeated code.

✅ The Modern Solution: Optional Chaining

The ?. operator

Simply add ?. before accessing the property:

const button = document.querySelector('#important-button')

button?.addEventListener('click', () => {
  console.log('Click')
})

What does it do?

  • If button exists → executes addEventListener
  • If button is null → does nothing and no error

✨ Same result, much less code.

📊 Comparison: Without vs With Optional Chaining

❌ Without Optional Chaining
const button = document.querySelector('#btn')

if (button) {
  button.addEventListener('click', handler)
}
✅ With Optional Chaining
const button = document.querySelector('#btn')

button?.addEventListener('click', handler)

Same result, fewer lines, more readable.

🔍 Also Works with Properties

Safely access object properties

const button = document.querySelector('#important-button')

console.log(button?.textContent)  // Button text
console.log(button?.id)           // Button ID
console.log(button?.disabled)     // If it's disabled

If the button doesn't exist

Returns undefined without error.

The application does NOT break.

⛓️ Chaining (Very Powerful)

You can use ?. multiple times

const container = document.querySelector('#container')

const width = container?.firstChild?.getBoundingClientRect()?.width

What does it mean?

  1. If container exists
  2. And firstChild exists
  3. And getBoundingClientRect() exists
  4. → return width

If something doesn't exist → returns undefined without errors.

💡 Practical Example: API Response

API data that might not exist

const response = {
  data: {
    user: {
      name: 'Miguel',
      profile: {
        city: 'Madrid'
      }
    }
  }
}

// Without optional chaining (dangerous):
console.log(response.data.user.profile.city)  // ✅ 'Madrid'

// If profile doesn't exist:
console.log(response.data.user.profile.city)  // ❌ Error

With optional chaining (safe)

// Safe even if some level doesn't exist:
console.log(response.data?.user?.profile?.city)  // ✅ 'Madrid' or undefined

🎯 Simple Mental Rule

?. = "only if it exists"

When you see ?., think: "Only access if this exists"

user?.address?.city

// Means:
"Give me the city only if user and address exist"

🔥 Where You'll See It (Very Common)

Places where optional chaining appears:

  • DOM: Selecting elements that might not exist
  • APIs: Data that might be incomplete
  • React: Props that might be undefined
  • Objects: Optional properties

Typical example in React:

// Get user name from props:
console.log(props?.user?.profile?.name)

⚡ Optional Chaining with Arrays

Also works with indexes

const items = [
  { name: 'Item 1' },
  { name: 'Item 2' }
]

// Safe:
console.log(items?.[0]?.name)   // 'Item 1'
console.log(items?.[5]?.name)   // undefined (no error)

If items doesn't exist or doesn't have that index → undefined without error.

✅ Conclusion

?. prevents errors when something might be null or undefined

It allows you to write code that is:

  • ✅ Safer (no unexpected errors)
  • ✅ Shorter (less if/else)
  • ✅ More readable (clear intent)
