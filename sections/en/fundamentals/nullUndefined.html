Null and Undefined

🧠 Visual Fundamental Idea

Both represent absence of value, but have completely different meanings:

undefined → JavaScript assigns it automatically when there's no value

null → You assign it intentionally to indicate "no value"

1. Undefined

A variable that has been declared but has no value:


let user
console.log(user) // undefined

let address
console.log(address) // undefined

⚠️ Important: undefined is what JavaScript automatically assigns to variables that haven't been initialized.

2. Null

Represents the intentional absence of a value:


let response = null // Intentionally without value
console.log(response) // null

💡 Key Difference: null is assigned by you explicitly, while undefined is assigned automatically by JavaScript.

📊 Difference between undefined and null

undefined (Automatic)
let undefined_var // No value assigned
console.log(undefined_var) // undefined
null (Intentional)
let no_value = null // Intentionally empty
console.log(no_value) // null

Key Differences:

Type Checking:

typeof null returns "object", which is a quirk in JavaScript due to legacy reasons.

typeof undefined returns "undefined".

Equality Comparison:

Loose Equality (==): null == undefined is true because they are considered equal in value when type is not considered.

Strict Equality (===): null === undefined is false because they are different types.


console.log(undefined == null);  // true (loose equality)
console.log(undefined === null); // false (strict equality)

console.log(typeof undefined)    // "undefined"
console.log(typeof null)         // "object"

🎯 Mental Rule to Remember

undefined: JavaScript assigns it automatically when there's no value

null: You assign it intentionally to indicate "no value"

It's rare but you can also assign undefined manually, although it's not recommended.

Best Practices:

  • Use === for Comparisons: It's best practice to use strict equality to avoid issues with type coercion.
  • Use undefined for uninitialized variables (JavaScript does this automatically).
  • Use null to intentionally and explicitly signify "no value."
  • Prefer === over == to avoid unintended type coercion.
