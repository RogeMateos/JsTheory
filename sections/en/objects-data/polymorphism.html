Polymorphism in JavaScript

0) Chapter Objective

By the end of this topic you will be able to:

  • Understand what polymorphism really is (no fluff)
  • Implement it with classes and inheritance
  • See the most important case: real polymorphism = treating different objects the same, without if/switch
  • Understand how it applies in JavaScript with duck typing

1) What is Polymorphism?

Simple and useful definition

Polymorphism = same method, different behaviors.

👉 Mental example:

All animals can makeSound()

But each one does it differently:

  • cat → "meow"
  • dog → "woof"
  • cow → "moo"

The important part (senior vision)

Polymorphism is not "making classes for the sake of it".

It's this:

✅ Being able to write generic code that works with many different types, without asking for the type.

2) The Typical Problem (without polymorphism)

A junior usually does this:


function makeSound(animal) {
  if (animal.type === "cat") return "Meow";
  if (animal.type === "dog") return "Woof";
  return "???";
}

What's wrong here?

Every time you add a new animal (Cow, Bird...) you have to touch this function again.

That breaks a key principle:

Open for extension, closed for modification (Open/Closed Principle).

3) Solution with Polymorphism (with classes)

Step 1: Create a base class (simulating "abstract")

⚠️ IMPORTANT

In JavaScript there are no real abstract classes, so we simulate them.

Goal:

  • Don't allow new Animal()
  • Force makeSound() to be implemented by children

class Animal {
  constructor(name) {
    // 🔒 Block to prevent instantiating Animal directly
    if (new.target === Animal) {
      throw new Error("Animal is abstract and cannot be instantiated");
    }

    this.name = name;
  }

  makeSound() {
    // Force the child to implement it
    throw new Error("makeSound() must be implemented in the subclass");
  }
}

📌 new.target is key here:

  • If you try to instantiate Animal, it throws an error
  • If you instantiate a subclass like Cat, it doesn't fail

Step 2: Create subclasses (Cat and Dog)


class Cat extends Animal {
  makeSound() {
    return "Meow 🐱";
  }
}

class Dog extends Animal {
  makeSound() {
    return "Woof 🐶";
  }
}

✅ Here's the polymorphism:

  • same method (makeSound)
  • different behaviors (each class decides)

Step 3: Create instances


const cat = new Cat("MoureCat");
const dog = new Dog("MoureDog");

console.log(cat.name, cat.makeSound());
console.log(dog.name, dog.makeSound());

Output:


MoureCat Meow 🐱
MoureDog Woof 🐶

4) Here comes REAL polymorphism (the important part)

This is the example you must understand for sure:


const animals = [
  new Cat("Luna"),
  new Dog("Rocky"),
  new Cat("Mimi"),
];

for (const animal of animals) {
  console.log(animal.name, "says", animal.makeSound());
}

What's special about it?

  • Your loop DOESN'T KNOW if it's a cat or a dog
  • No if, no switch
  • Just calls the same method

💡 That's polymorphism:

the code "treats different objects uniformly".

5) What happens if I DON'T implement the method?

Example:


class Bird extends Animal {}

Now:


const bird = new Bird("Tweety");
console.log(bird.makeSound());

✅ What should happen?

Throws error:


makeSound() must be implemented in the subclass

📌 This is exactly what you want:

force the implementation of the contract

6) Real JavaScript Polymorphism (Duck Typing)

This is VERY important

👉 In JavaScript many times you don't care about inheritance.

You care about the contract.

Example:


function playSound(entity) {
  if (typeof entity.makeSound !== "function") {
    throw new Error("This object doesn't implement makeSound()");
  }

  console.log(entity.makeSound());
}

Usage:


playSound(new Cat("A"));
playSound({
  makeSound() {
    return "Beep Beep 🤖";
  }
});

✅ This object doesn't extend Animal, but it works

Senior message:

In JavaScript, polymorphism is "if it has the method, it's valid".

7) Senior Bonus: A Professional Improvement

If you want to avoid the if in playSound(), you can use a guard clause or fail fast with a clear error.

And if you want something more elegant, you can say:


const makeSoundable = (obj) => typeof obj?.makeSound === "function";

function playSound(entity) {
  if (!makeSoundable(entity)) {
    throw new Error("This object doesn't implement makeSound()");
  }
  console.log(entity.makeSound());
}

8) When to use polymorphism (real Front-End cases)

✅ Cases where it's worth it:

A) Component rendering by type

Example:

  • each block type has a render() method
  • your system doesn't ask for type → just executes .render()
B) Validators

Many validators with the same interface:

  • validate()
  • formatError()
C) Strategies

Different ways to calculate price:

  • calculate()
  • each class implements its strategy

9) Exercises to Reinforce

Exercise 1 (basic)

Create Cow that inherits from Animal and does:


class Cow extends Animal {
  makeSound() {
    return "Moo 🐮";
  }
}

const cow = new Cow("Lola");
console.log(cow.makeSound()); // "Moo 🐮"

Exercise 2 (interview level)

Create a function:


function playAllSounds(animals) {
  for (const animal of animals) {
    console.log(animal.name, "says", animal.makeSound());
  }
}

// Usage:
const zoo = [
  new Cat("Luna"),
  new Dog("Rocky"),
  new Cow("Lola")
];

playAllSounds(zoo);

Exercise 3 (pro)

Create a polymorphic payment system:


// Abstract PaymentMethod (simulated)
class PaymentMethod {
  constructor() {
    if (new.target === PaymentMethod) {
      throw new Error("PaymentMethod is abstract");
    }
  }

  pay(amount) {
    throw new Error("pay() must be implemented");
  }
}

class CardPayment extends PaymentMethod {
  pay(amount) {
    return `Paid ${amount}€ with card 💳`;
  }
}

class PaypalPayment extends PaymentMethod {
  pay(amount) {
    return `Paid ${amount}€ with PayPal 🅿️`;
  }
}

class CryptoPayment extends PaymentMethod {
  pay(amount) {
    return `Paid ${amount}€ with crypto ₿`;
  }
}

// Your loop just does:
const methods = [
  new CardPayment(),
  new PaypalPayment(),
  new CryptoPayment()
];

methods.forEach((m) => console.log(m.pay(100)));

✅ Chapter Summary

What you must remember

  • Polymorphism = same method, different behaviors
  • Used to avoid if/switch by type
  • In JS it can be done with:
    • Inheritance + override
    • Duck typing (if it has the method, it works)
  • Real benefit:
    • more maintainable code
    • more extensible (add new classes without touching central logic)

Common Errors Checklist

⚠️ Typical errors to avoid

  • ❌ Using if (type === ...) instead of polymorphism
  • ❌ Not implementing abstract methods in subclasses
  • ❌ Creating classes when a simple function would suffice
  • ❌ Forgetting to validate that the object has the method (duck typing)
