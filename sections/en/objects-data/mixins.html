Mixins in JavaScript (Composition vs Inheritance) — Step by step

0) Objective

You'll learn to:

  • Understand what a mixin is
  • Apply it correctly (to prototype, not to the class)
  • Reuse abilities (fly, fire...) in multiple classes without extra inheritance

Step 0) Quick context: why mixins?

With inheritance, if you want "fly" in multiple classes, you end up creating weird hierarchies:


Animal -> FlyingAnimal -> Bird
Animal -> FlyingAnimal -> Dragon

Problem

That scales poorly.

✅ Solution: Mixins

With mixins, you create separate "abilities" and give them to whoever you want.

That's composition.

Step 1) Create the "mixin" (the ability)

A mixin is usually an object with methods.


const FlyMixin = {
  fly() {
    console.log(`${this.name} is flying`);
  },
};

📌 Pro note

We use this.name because we assume the object/class where we apply it will have name.

Step 2) Create a base class (Animal)

Now we define a class that has name.


class Animal {
  constructor(name) {
    this.name = name;
  }

  makeSound() {
    console.log("Generic sound");
  }
}

Step 3) Create concrete classes (Bird and Dragon)

For now, without flying.


class Bird extends Animal {}
class Dragon extends Animal {}

Step 4) The typical mistake (so you understand)

If you do this:


Object.assign(Bird, FlyMixin);

🚨 Problem

You're putting fly on the Bird class, not on its instances.

Meaning:

  • ✅ Bird.fly() might exist
  • ❌ new Bird().fly() does NOT exist

Step 5) The correct way: apply the mixin to the prototype ✅

This is what's done in real life when you want each instance to have it:


Object.assign(Bird.prototype, FlyMixin);

Now let's test:


const bird = new Bird("Mour Bird");
bird.fly(); // Mour Bird is flying

✅ It works

Because bird looks for methods in Bird.prototype.

Step 6) Reuse the ability in another class (Dragon)

Here's the magic of mixins: same ability, different class.


Object.assign(Dragon.prototype, FlyMixin);

const dragon = new Dragon("Mour Dragon");
dragon.fly(); // Mour Dragon is flying

Step 7) Add another mixin to see real composition

Now we create another ability: fire.


const FireMixin = {
  breatheFire() {
    console.log(`${this.name} breathes fire 🔥`);
  },
};

We apply it ONLY to the dragon:


Object.assign(Dragon.prototype, FireMixin);

dragon.breatheFire(); // Mour Dragon breathes fire 🔥

✅ Result

  • Bird flies
  • Dragon flies + breathes fire

Without creating more intermediate classes.

Step 8) Golden rule (what you need to remember)

✅ If you want the method to exist on the instance:

Use:


Object.assign(Class.prototype, Mixin);

❌ If you do it on the class:


Object.assign(Class, Mixin);

That does NOT go to your instances.

Step 9) Important pitfall: method "overwriting"

If two mixins bring the same method name, the last one wins:


Object.assign(Dragon.prototype, MixinA, MixinB);
// If both have fly(), MixinB.fly wins

✅ Good habit

Clear names or controlled composition.

Complete final code (all together)


const FlyMixin = {
  fly() {
    console.log(`${this.name} is flying`);
  },
};

const FireMixin = {
  breatheFire() {
    console.log(`${this.name} breathes fire 🔥`);
  },
};

class Animal {
  constructor(name) {
    this.name = name;
  }

  makeSound() {
    console.log("Generic sound");
  }
}

class Bird extends Animal {}
class Dragon extends Animal {}

Object.assign(Bird.prototype, FlyMixin);
Object.assign(Dragon.prototype, FlyMixin, FireMixin);

const bird = new Bird("Mour Bird");
bird.fly();

const dragon = new Dragon("Mour Dragon");
dragon.fly();
dragon.breatheFire();

Mini exercises (to practice)

Exercise 1

Create a SwimMixin with swim() and apply it to Fish.


const SwimMixin = {
  swim() {
    console.log(`${this.name} is swimming`);
  },
};

class Fish extends Animal {}
Object.assign(Fish.prototype, SwimMixin);

const fish = new Fish("Nemo");
fish.swim(); // Nemo is swimming

Exercise 2

Make Bird have fly() but also a sing() with a SingMixin.


const SingMixin = {
  sing() {
    console.log(`${this.name} is singing 🎵`);
  },
};

Object.assign(Bird.prototype, FlyMixin, SingMixin);

const bird = new Bird("Tweety");
bird.fly();  // Tweety is flying
bird.sing(); // Tweety is singing 🎵

Exercise 3

Create a LoggerMixin that has logInfo() and shows the name + class.


const LoggerMixin = {
  logInfo() {
    console.log(`[${this.constructor.name}] ${this.name}`);
  },
};

Object.assign(Dragon.prototype, LoggerMixin);

const dragon = new Dragon("Smaug");
dragon.logInfo(); // [Dragon] Smaug

✅ Summary

What you must remember

  • Mixin: object with methods that can be "mixed" into classes
  • Composition > Inheritance: more flexible, fewer hierarchies
  • Apply to prototype: Object.assign(Class.prototype, Mixin)
  • Reusability: same ability in multiple classes without inheritance
  • Method collision: the last mixin wins if there are duplicate names

Common Errors Checklist

⚠️ Typical errors to avoid

  • ❌ Applying the mixin to the class instead of the prototype
  • ❌ Not considering name collisions between mixins
  • ❌ Forgetting that mixins depend on properties like this.name
  • ❌ Using mixins when simple inheritance would be clearer
