Constructor Functions and prototype (Pre-ES6 Era)

🏭 The Metaphor: Person is a factory

Understanding static methods vs instance methods

Static methods: are factory tools

  • Used like: Person.createFromJSON(...)
  • Don't depend on a specific person

Instance methods: are abilities that all manufactured persons have

  • Used like: bruce.greet()
  • Depend on this (the concrete object)

A) Constructor (properties per instance)


function Person(name, age) {
  this.name = name;
  this.age = age;
}

B) Instance method (shared) → goes in prototype


Person.prototype.greet = function () {
  return `Hello, I'm ${this.name}`;
};

✅ Why in prototype

Person.prototype.greet → found by instances through the prototype chain

All instances share the same function (memory savings)

C) Static method → goes on the Person function


Person.createAnonymous = function () {
  return new Person("Anonymous", 0);
};

✅ Static method

Person.createAnonymous → belongs to the "factory", not the "products"

D) Usage


const bruce = new Person("Bruce", 30);

console.log(bruce.greet());           // ✅ "Hello, I'm Bruce" (instance method)
console.log(Person.createAnonymous()); // ✅ Person { name: 'Anonymous', age: 0 }

console.log(bruce.createAnonymous);    // ❌ undefined (not an instance method)
console.log(Person.greet);             // ❌ undefined (greet is not static)

⚠️ Common mistake: "I added the method and it doesn't appear"

If you do this:


Person.greet = function () { ... }  // ❌ Static (common error)

Then:


bruce.greet() // ❌ TypeError: bruce.greet is not a function

Solution: Must go in Person.prototype.greet

Simple rule

  • Person.something = static
  • Person.prototype.something = instance

E) prototype vs __proto__ (understanding the connection)


const bruce = new Person("Bruce", 30);

// Verification:
console.log(Object.getPrototypeOf(bruce) === Person.prototype);
// true

📌 Mini-diagram

  • Person.prototype → the object that will be the "parent" (prototype) of instances created with new Person()
  • Object.getPrototypeOf(bruce) → points to Person.prototype

⚠️ Avoid __proto__

__proto__ is considered legacy/compat

Use instead:

  • Object.getPrototypeOf(obj) to get the prototype
  • Object.setPrototypeOf(obj, proto) to set it (with caution, it's slow)

F) Why put methods in prototype (performance/memory)

❌ Define inside the constructor:


function Person(name) {
  this.name = name;
  this.greet = function () {
    return `Hello, I'm ${this.name}`;
  };
}

const a = new Person("A");
const b = new Person("B");

console.log(a.greet === b.greet); // false
// 👉 Each instance creates a new copy of greet (more memory)

✅ Define in prototype:


function Person(name) {
  this.name = name;
}

Person.prototype.greet = function () {
  return `Hello, I'm ${this.name}`;
};

const a = new Person("A");
const b = new Person("B");

console.log(a.greet === b.greet); // true
// 👉 All instances share the same function

💡 This true is the "click" for many juniors

Proves that both objects use the same function in memory.

G) Modern version (class) and equivalencies


class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() { // ✅ instance method (lives in Person.prototype)
    return `Hello, I'm ${this.name}`;
  }

  static createAnonymous() { // ✅ static method (lives in Person)
    return new Person("Anonymous", 0);
  }
}

const bruce = new Person("Bruce", 30);
console.log(bruce.greet());           // "Hello, I'm Bruce"
console.log(Person.createAnonymous()); // Person { name: 'Anonymous', age: 0 }

📌 Real equivalencies

  • greet() in class → goes to prototype
  • static createAnonymous() → goes to constructor/class

class is syntactic sugar over the same prototype system

⚠️ Important: NOT deprecated

Constructor functions and prototype are NOT deprecated

  • Today class is preferred for readability and standard
  • But prototype is still the real engine underneath
  • In legacy projects you'll see constructor functions constantly

H) Practical exercises

1️⃣ Create Person.fromObject({name, age}) as a static method


// Your code here
Person.fromObject = function(obj) {
  return new Person(obj.name, obj.age);
};

// Test:
const p = Person.fromObject({name: "Ana", age: 25});
console.log(p.greet()); // "Hello, I'm Ana"

2️⃣ Add isAdult() as an instance method


// Your code here
Person.prototype.isAdult = function() {
  return this.age >= 18;
};

// Test:
const minor = new Person("Luis", 15);
const adult = new Person("Ana", 25);
console.log(minor.isAdult()); // false
console.log(adult.isAdult()); // true

3️⃣ Demonstrate that the instance method is shared


const a = new Person("A", 20);
const b = new Person("B", 30);

console.log(a.greet === b.greet); // true (if in prototype)
console.log(a.isAdult === b.isAdult); // true

I) Mental checklist (3 golden rules)

  • ✅ Unique properties per instance → inside the constructor
  • ✅ Shared methods → in prototype
  • ✅ "Factory" methods/properties → static (on the function/class)
