Abstract Classes in JavaScript (simulated) + Inheritance + Polymorphism

0) What you'll learn

  • What an abstract class is (concept)
  • Why JavaScript doesn't have a real abstract class (at runtime)
  • How to simulate:
    • preventing instantiation of the base class
    • forcing methods to be implemented in subclasses
  • How to apply this with extends, super() and polymorphism

Step 0) Quick concept (no fluff)

An abstract class serves to:

  • Define a base structure (common properties)
  • Define a contract (methods that must exist)
  • Prevent someone from using it as a "real" object (new)

Mental example:

  • "Animal" is not a concrete animal
  • "Dog" and "Cat" are

Step 1) Start with a normal class (and see the problem)


class Animal {
  makeSound() {
    console.log("I make a sound");
  }
}

const a = new Animal();
a.makeSound();

The problem

✅ This works.

❌ But if "Animal" should be abstract... this should NOT be allowed.

Step 2) Block new Animal() with new.target

Idea: if someone tries to instantiate Animal exactly, we throw an error.


class Animal {
  constructor() {
    if (new.target === Animal) {
      throw new Error("Cannot instantiate Animal directly (abstract class).");
    }
  }

  makeSound() {
    console.log("I make a sound");
  }
}

// const a = new Animal(); // ❌ Error

What is new.target

  • It's the class/function being instantiated with new
  • If you do new Animal(), then new.target === Animal

Step 3) Add shared state: name

Now yes: "all animals have a name".


class Animal {
  constructor(name) {
    if (new.target === Animal) {
      throw new Error("Cannot instantiate Animal directly (abstract class).");
    }

    this.name = name;
  }

  makeSound() {
    console.log("I make a sound");
  }
}

But something important is missing here...

Step 4) Validate parameters ("pro" level but simple)

A good tutorial teaches good habits:


class Animal {
  constructor(name) {
    if (new.target === Animal) {
      throw new Error("Cannot instantiate Animal directly (abstract class).");
    }

    if (!name) {
      throw new Error("Name is required to create an Animal.");
    }

    this.name = name;
  }

  makeSound() {
    console.log("I make a sound");
  }
}

Step 5) Convert makeSound() to "abstract"

We want to force Dog/Cat to implement it.

The typical way in JS is:


class Animal {
  constructor(name) {
    if (new.target === Animal) {
      throw new Error("Cannot instantiate Animal directly (abstract class).");
    }
    if (!name) {
      throw new Error("Name is required to create an Animal.");
    }
    this.name = name;
  }

  makeSound() {
    throw new Error("makeSound() must be implemented by the subclass.");
  }
}

✅ This turns the method into a "contract"

If you don't implement it, it breaks.

Step 6) Create a subclass: Dog extends Animal

Here 2 key concepts appear:

  • extends (inheritance)
  • super(name) (calls the parent constructor)

class Dog extends Animal {
  constructor(name) {
    super(name);
  }

  makeSound() {
    console.log(`${this.name} says: Woof!`);
  }
}

const dog = new Dog("Rocky");
dog.makeSound(); // Rocky says: Woof!

Step 7) Another subclass: Cat

Same contract (makeSound()), different behavior.


class Cat extends Animal {
  constructor(name) {
    super(name);
  }

  makeSound() {
    console.log(`${this.name} says: Meow!`);
  }
}

const cat = new Cat("Milo");
cat.makeSound(); // Milo says: Meow!

Step 8) Polymorphism demonstration (the really important part)

Polymorphism = same method, different implementations, uniform usage


const animals = [new Dog("Rocky"), new Cat("Milo")];

animals.forEach((a) => a.makeSound());

Output:


Rocky says: Woof!
Milo says: Meow!

💡 The important part

You treat everyone as "Animal", but each one responds differently.

Step 9) Tests that our "abstraction" works

1) Instantiating Animal fails


const a = new Animal("Base"); // ❌ Error

2) Subclass without implementing makeSound fails when called


class Fish extends Animal {
  constructor(name) {
    super(name);
  }
  // no makeSound()
}

const f = new Fish("Nemo");
f.makeSound(); // ❌ Error: must be implemented by the subclass

Step 10) Complete final version (production-ready)


class Animal {
  constructor(name) {
    if (new.target === Animal) {
      throw new Error("Cannot instantiate Animal directly (abstract class).");
    }

    if (!name) {
      throw new Error("Name is required to create an Animal.");
    }

    this.name = name;
  }

  makeSound() {
    throw new Error("makeSound() must be implemented by the subclass.");
  }
}

class Dog extends Animal {
  constructor(name) {
    super(name);
  }

  makeSound() {
    console.log(`${this.name} says: Woof!`);
  }
}

class Cat extends Animal {
  constructor(name) {
    super(name);
  }

  makeSound() {
    console.log(`${this.name} says: Meow!`);
  }
}

// ✅ OK
const dog = new Dog("Rocky");
dog.makeSound();

const cat = new Cat("Milo");
cat.makeSound();

// ✅ Polymorphism
const animals = [dog, cat];
animals.forEach((a) => a.makeSound());

// ❌ Should fail
// const a = new Animal("Base");

Bonus: This is cleaner in TypeScript

📌 Note for TypeScript

In TS there is a real abstract class and the compiler forces you to implement abstract methods.

Equivalent TypeScript example:


abstract class Animal {
  constructor(public name: string) {}

  abstract makeSound(): void;
}

class Dog extends Animal {
  makeSound(): void {
    console.log(`${this.name} says: Woof!`);
  }
}

// const a = new Animal("Base"); // ❌ Compilation error

✅ Summary

What you must remember

  • Abstract class: not instantiated directly, only serves as a base
  • new.target: tells us which class is being instantiated
  • extends: creates inheritance from one class to another
  • super(): calls the parent constructor
  • Abstract methods: we throw an error if they're not implemented
  • Polymorphism: same method, different behaviors

Common Errors Checklist

⚠️ Typical errors to avoid

  • ❌ Forgetting to call super() in the subclass constructor
  • ❌ Calling super() after using this
  • ❌ Not validating required parameters in the constructor
  • ❌ Not implementing "abstract" methods in subclasses
