Prototypes in JavaScript

Understanding the mechanism of inheritance and property lookup

1️⃣ What Problem Do Prototypes Solve?

When you access obj.something, the JavaScript engine performs a lookup:

Search Process:

  1. Does something exist in the object?
  2. If not, look in its prototype ([[Prototype]])
  3. If not, go up the chain (prototype chain)
  4. If it doesn't appear, return undefined

Clear Example


const person = { name: "Bryce" };

console.log(person.name);       // "Bryce" (own property)
console.log(person.toString);   // function... (comes from Object.prototype)
console.log(person.xyz);        // undefined

💡 The Powerful Idea

There are methods that "aren't" in the object but work. They come from the prototype.

2️⃣ Every Object Has [[Prototype]]

Every object in JavaScript has an internal prototype called [[Prototype]].

See the Prototype (Modern Way)


const person = { name: "Bryce" };

console.log(Object.getPrototypeOf(person) === Object.prototype);
// true

👉 Important

Object.prototype is like the "base" of normal objects in JavaScript.

⚠️ About __proto__

__proto__ is legacy. It works, but is not recommended.

Modern way:

  • Object.getPrototypeOf(obj) to get the prototype
  • Object.setPrototypeOf(obj, proto) to set it (with caution)
  • Object.create(proto) to create objects with a given prototype

3️⃣ Where "Magic" Methods Come From


const person = { name: "Bryce", age: 37 };

console.log(person.toString());
// "[object Object]"

console.log(person.hasOwnProperty("name"));
// true

📌 Explanation

These methods aren't in person, they're in Object.prototype.

The engine finds them by following the prototype chain.

Check Own Properties


console.log(person.hasOwnProperty("toString"));
// false (comes from prototype)

console.log(person.hasOwnProperty("name"));
// true (own property)

4️⃣ Real Inheritance with Object.create

This is where prototypes show their true power.


const personProto = {
  greet() {
    return `Hello, I'm ${this.name}`;
  }
};

const bryce = Object.create(personProto);
bryce.name = "Bryce";
bryce.age = 37;

console.log(bryce.greet());
// "Hello, I'm Bryce"

✅ This IS Prototypes

greet isn't in bryce, it's in personProto, but is found through the chain.

Verify


console.log(bryce.hasOwnProperty("greet"));
// false

console.log(Object.getPrototypeOf(bryce) === personProto);
// true

5️⃣ Sharing Methods (The Practical Reason)

If you create 1000 people:

❌ Without prototypes:

If you define greet inside each object → 1000 functions in memory

✅ With prototypes:

If greet lives in the prototype → 1 shared function


const personProto = {
  greet() {
    return `Hello, I'm ${this.name}`;
  }
};

const a = Object.create(personProto);
a.name = "A";

const b = Object.create(personProto);
b.name = "B";

console.log(a.greet === b.greet);
// true (same shared function!)

💡 The "Click" for Juniors

That true proves that both objects share the same method in memory.

6️⃣ Understanding this in Prototype Methods

Many juniors wonder: "how does the method know who this is?"


const personProto = {
  greet() {
    return `Hello, I'm ${this.name}`;
  }
};

const bryce = Object.create(personProto);
bryce.name = "Bryce";

const ana = Object.create(personProto);
ana.name = "Ana";

console.log(bryce.greet()); // "Hello, I'm Bryce"
console.log(ana.greet());   // "Hello, I'm Ana"

📌 Explanation

The method executes with the "receiver":

  • bryce.greet() → this === bryce
  • ana.greet() → this === ana

7️⃣ Connecting with class (Modern Way)

Today we write this with class, which is syntactic sugar over prototypes.


class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    return `Hello, I'm ${this.name}`;
  }
}

const bryce = new Person("Bryce", 37);

console.log(bryce.greet());
// "Hello, I'm Bryce"

console.log(Object.getPrototypeOf(bryce) === Person.prototype);
// true

👉 Important

Methods in a class live in Person.prototype.

JavaScript is still prototypal, but today we write it with class.

8️⃣ Key Difference: prototype vs [[Prototype]]

⚠️ Very Important (Common Confusion)

prototype is NOT a property of any object.

prototype is a property of functions (when used as constructor) and classes.

✅ Clear Differences

  • Person.prototype → object used as prototype for instances created with new Person()
  • bryce.__proto__ / Object.getPrototypeOf(bryce) → the actual prototype of that instance

Demonstration


function Person(name) {
  this.name = name;
}

Person.prototype.greet = function() {
  return `Hello, I'm ${this.name}`;
};

const bryce = new Person("Bryce");

console.log(Object.getPrototypeOf(bryce) === Person.prototype);
// true

console.log(Person.prototype.hasOwnProperty("greet"));
// true

console.log(bryce.hasOwnProperty("greet"));
// false

9️⃣ Special Case: Object.create(null)

Sometimes "null prototype" is intentional.


const dict = Object.create(null);
dict.apple = 1;
dict.orange = 2;

console.log(dict.toString);
// undefined (doesn't inherit from Object.prototype)

console.log(Object.getPrototypeOf(dict));
// null

✅ Use Cases

  • Objects used as "pure dictionaries"
  • Avoid collisions with inherited method names
  • Better performance in lookups when you don't need inherited methods

Comparison


const normalObj = {};
const pureDict = Object.create(null);

console.log(normalObj.toString);   // function
console.log(pureDict.toString);    // undefined

🔟 Warnings and Best Practices

⚠️ Object.setPrototypeOf (Performance)

Changing the prototype at runtime can affect performance/engine optimizations.


// ❌ Avoid this
const obj = { name: "test" };
Object.setPrototypeOf(obj, someProto);

✅ Better: Create with the correct prototype from the start.


// ✅ Recommended way
const obj = Object.create(someProto);
obj.name = "test";

👉 Recommendations

  • Use class to define "types" (it's clearer)
  • Use Object.create() when you need explicit inheritance
  • Use Object.getPrototypeOf() instead of __proto__
  • Avoid Object.setPrototypeOf() in production code

1️⃣1️⃣ Complete Prototype Chain


class Animal {
  eat() {
    return "eating...";
  }
}

class Dog extends Animal {
  bark() {
    return "woof!";
  }
}

const myDog = new Dog();

console.log(myDog.bark());  // "woof!"
console.log(myDog.eat());   // "eating..."

// Complete chain:
console.log(Object.getPrototypeOf(myDog) === Dog.prototype);
// true

console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype);
// true

console.log(Object.getPrototypeOf(Animal.prototype) === Object.prototype);
// true

console.log(Object.getPrototypeOf(Object.prototype));
// null

📌 The Complete Chain

myDog → Dog.prototype → Animal.prototype → Object.prototype → null

1️⃣2️⃣ Final Mental Summary

Key Concepts

Every object has [[Prototype]]

  • Accessed with Object.getPrototypeOf(obj)
  • Usually points to Object.prototype

prototype is a property of functions/classes

  • Defines what prototype instances will have
  • new Person() → instance with [[Prototype]] = Person.prototype

Advantages of prototypes

  • Share methods between instances
  • Memory savings
  • Inheritance and code reusability

Modern way

  • Use class for clarity
  • Use Object.create() when you need control
  • Avoid __proto__ and setPrototypeOf
