Symbol in JavaScript classes (pseudo-private, collisions and modern alternative with #private)

0) In this tutorial you'll learn:

  • What Symbol is and why it exists
  • How to use Symbol inside a class
  • Why it "seems private" but isn't real privacy
  • How to protect a value with Object.defineProperty
  • What to use nowadays: #private (ES2020+)

1) What is a Symbol?

Symbol is a primitive data type introduced in ES2015 (ES6).

Its main purpose is to allow creating unique identifiers, especially for use as property keys without collision risk.

✅ Key characteristic

Each Symbol() you create is unique even with the same description:


const A = Symbol("id");
const B = Symbol("id");

console.log(A === B); // false

📌 Important

This means it's perfect for creating keys that nobody will accidentally overwrite with "id", "name", etc.

2) What is Symbol really for?

Real case: avoiding collisions

Imagine you and a library want to add an id property to an object.

  • If both use "id" → collision
  • If you use Symbol("id") → no collision ever

3) Using Symbol in a class

Let's create a User class with:

  • name visible
  • id hidden using Symbol

✅ Complete example


const ID = Symbol("id"); // private/symbolic key

class User {
  constructor(name) {
    this.name = name;
    this[ID] = Math.random(); // save the id using Symbol as key
  }
}

const user = new User("Roge");

console.log(user.name); // Roge
console.log(user.id);   // undefined (because "id" as string doesn't exist)
console.log(user[ID]);  // ✅ yes, accesses (if you have the Symbol)

4) Why does user.id give undefined?

Because id and [ID] are different keys:

  • user.id → looks for a property called "id"
  • user[ID] → looks for a property whose key is the Symbol

It's like they're two different names.

5) "Seems private"... but it's NOT really private

Here comes the important part for your tutorial:

✅ Symbol doesn't create real privacy

It only creates hiding, because:

  • Doesn't appear normally with . (dot notation)
  • Doesn't appear in Object.keys()
  • But it can be discovered

⚠️ Can be seen with introspection


const symbols = Object.getOwnPropertySymbols(user);

console.log(symbols); // [ Symbol(id) ]
console.log(user[symbols[0]]); // accesses the hidden id

📌 Conclusion

Symbol is "semi-private": it hides, but doesn't protect.

6) So... can the value be modified?

Yes, because Symbol doesn't prevent reassigning the value:


user[ID] = 123;
console.log(user[ID]); // 123

WATCH OUT: the Symbol is immutable, but the value inside the property is NOT.

7) How to make it more "protected" (writable: false)

If you want the value not to be easily reassignable, define the property manually:


const ID = Symbol("id");

class User {
  constructor(name) {
    this.name = name;

    Object.defineProperty(this, ID, {
      value: Math.random(),
      writable: false,      // ❌ cannot be reassigned
      enumerable: false,    // doesn't appear in keys
      configurable: false,  // cannot be redefined
    });
  }

  get id() {
    return this[ID]; // controlled access
  }
}

const user = new User("Roge");

console.log(user.id); // ok

user[ID] = 999;       // fails (in strict throws error)
console.log(user.id); // stays the same

✅ Result

This already simulates quite well a private property "in old times".

8) Better modern option: #private (real private)

Since ES2020+ (and already widely supported) we have real privates with #.

This IS real privacy:


class User {
  #id;

  constructor(name) {
    this.name = name;
    this.#id = crypto.randomUUID();
  }

  get id() {
    return this.#id;
  }
}

const user = new User("Roge");

console.log(user.id);  // ✅ works
console.log(user.#id); // ❌ SyntaxError: Private field '#id' must be declared in an enclosing class

✅ Advantages of #private

  • Nobody can access from outside
  • Cannot be discovered with introspection
  • It's the recommended modern standard

9) When to use Symbol nowadays

Although it's no longer the best for privacy, Symbol is still useful.

✅ Use it when:

  • You need to avoid collisions in shared objects
  • You're making libraries/public utilities
  • You want metadata invisible to the normal user

10) Bonus (very pro): Symbol.iterator

This case is very useful and demonstrates Symbols with real value today:


class Collection {
  constructor(items) {
    this.items = items;
  }

  [Symbol.iterator]() {
    return this.items.values();
  }
}

const c = new Collection([1, 2, 3]);

for (const value of c) {
  console.log(value);
}

Output:


1
2
3

📌 Important

This makes your class work in for...of.

✅ Summary

What you must remember

  • ✅ Symbol creates unique keys → avoids collisions
  • ✅ Hides properties (don't show with . or Object.keys)
  • ⚠️ Not real privacy: can be discovered with getOwnPropertySymbols
  • ✅ If you want real privacy use #private
  • ✅ Symbol is still very useful for features like Symbol.iterator

Common Errors Checklist

⚠️ Typical errors to avoid

  • ❌ Believing Symbol provides real privacy
  • ❌ Not understanding that Symbol("id") !== Symbol("id")
  • ❌ Using Symbol when #private would be more appropriate
  • ❌ Forgetting that the value stored in Symbol can be modified
