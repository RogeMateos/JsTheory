Proxy in JavaScript

0) What is a Proxy in JavaScript?

A Proxy is a special object that sits "in between" your code and a real object.

📌 Its goal is to intercept operations like:

  • reading properties (get)
  • writing properties (set)
  • deleting (deleteProperty)
  • checking existence (has)
  • executing functions (apply)
  • etc.

📌 Think of a Proxy as a security guard

Every time someone tries to enter (read/edit) the object, the guard checks if it's allowed, blocks it, or logs something.

1) Create a base class (BankAccount)


class BankAccount {
  constructor(balance) {
    this.balance = balance;
  }
}

const account = new BankAccount(100);

console.log(account.balance); // 100

So far normal: without control, anyone can read and modify:


account.balance = -9999; // nobody prevents it 😬

2) Create a Proxy "handler"

The Proxy needs a handler, an object with special functions.

🧠 Basic handler


const handler = {
  get(target, property) {
    console.log("GET");
  },
  set(target, property, value) {
    console.log("SET");
  }
};

📌 Important

The handler defines what to do when someone accesses or changes something.

3) Wrap the real object with Proxy

Here comes the important part:


const securedAccount = new Proxy(account, handler);
  • account = the real object (target)
  • handler = rules/interceptors

4) Test: intercept read and write


console.log(securedAccount.balance);
securedAccount.balance = 50;

📌 This prints:


"GET"
"SET"

But... why undefined when reading?

Because in your get() you're not returning the value.

5) Solution: return the value in get()

🔑 Golden rule

If you intercept a get, you normally must return the value.


const handler = {
  get(target, property) {
    console.log("GET", property);
    return target[property]; // 👈 return real value
  },

  set(target, property, value) {
    console.log("SET", property, value);
    target[property] = value; // 👈 apply real change
    return true;              // 👈 mandatory in strict mode
  }
};

const securedAccount = new Proxy(account, handler);

console.log(securedAccount.balance); // GET balance -> 100
securedAccount.balance = 50;         // SET balance 50
console.log(securedAccount.balance); // GET balance -> 50

✅ Now it works perfectly

6) The complete Proxy: logs + balance validation

Now let's do the "pro" thing:

✅ We want:

  • Log every time a property is accessed
  • Don't allow negative balance

class BankAccount {
  constructor(balance) {
    this.balance = balance;
  }
}

const handler = {
  get(target, property) {
    console.log(`📌 Accessing: ${property}`);
    return target[property];
  },

  set(target, property, value) {
    console.log(`✍️ Modifying: ${property} -> ${value}`);

    if (property === "balance" && value < 0) {
      throw new Error("❌ Balance cannot be negative");
    }

    target[property] = value;
    return true;
  }
};

const account = new BankAccount(100);
const securedAccount = new Proxy(account, handler);

console.log(securedAccount.balance); // 📌 Accessing: balance -> 100

securedAccount.balance = 50;         // ✍️ Modifying: balance -> 50
console.log(securedAccount.balance); // -> 50

securedAccount.balance = -10;        // ❌ Error: Balance cannot be negative

🔥 What Proxy parameters mean

get(target, property)

  • target: the real object
  • property: the name of the property being read (e.g.: "balance")

✅ Example:


securedAccount.balance;

equals to:


property = "balance"

set(target, property, value)

  • target: the real object
  • property: property to be changed
  • value: new value

✅ Example:


securedAccount.balance = 50;

equals to:


property = "balance"
value = 50

✅ When to use Proxy in real life?

Very useful when you want cross-cutting control without dirtying the class.

Real examples:

🔐 Security
  • block access to password
  • prevent external modifications to sensitive properties
✅ Validations
  • don't allow incorrect types (string instead of number)
  • don't allow negatives
  • don't allow null
📊 Auditing / Logging
  • track reads/writes
  • internal analytics
🧊 Immutability (Redux-style)
  • prevent values from changing

🧠 Best practices (senior level)

✅ 1) DON'T put too much logic inside the proxy

Better to delegate to functions:


function validateBalance(value) {
  if (value < 0) throw new Error("Negative balance");
}

✅ 2) Use Reflect to maintain standard behavior

This is very pro because it respects internal things:


const handler = {
  get(target, prop) {
    console.log("GET", prop);
    return Reflect.get(target, prop);
  },

  set(target, prop, value) {
    if (prop === "balance" && value < 0) {
      throw new Error("Negative balance");
    }
    return Reflect.set(target, prop, value);
  }
};

🧪 Exercises to master it

✅ Exercise 1

Make a Proxy that:

  • logs "Reading property X"
  • logs "Writing property X"

✅ Exercise 2

Make a Proxy for a user object that prevents:

  • reading password
  • setting email if it doesn't include @

const handler = {
  get(target, prop) {
    if (prop === "password") {
      throw new Error("Cannot access password");
    }
    return target[prop];
  },

  set(target, prop, value) {
    if (prop === "email" && !value.includes("@")) {
      throw new Error("Invalid email");
    }
    target[prop] = value;
    return true;
  }
};

const user = { email: "test@example.com", password: "secret123" };
const securedUser = new Proxy(user, handler);

✅ Exercise 3

Make a Proxy that doesn't allow deleting properties:

Intercept:


delete obj.name

(using deleteProperty)


const handler = {
  deleteProperty(target, prop) {
    throw new Error(`Cannot delete property ${prop}`);
  }
};

const obj = { name: "Roge" };
const protected = new Proxy(obj, handler);

delete protected.name; // ❌ Error: Cannot delete property name

✅ Summary

What you must remember

  • Proxy: interceptor between your code and an object
  • Handler: object with traps (get, set, deleteProperty, etc.)
  • get: must return the value
  • set: must return true
  • Use Reflect: to maintain standard behavior
  • Use cases: validation, security, logging, immutability

Common Errors Checklist

⚠️ Typical errors to avoid

  • ❌ Not returning value in get
  • ❌ Not returning true in set
  • ❌ Putting too much logic in the handler
  • ❌ Not using Reflect for complex operations
