IIFE - Immediately Invoked Function Expression

What are IIFEs

IIFE (Immediately Invoked Function Expression) is a function that executes at the same moment it's defined. You don't need to call it explicitly afterward.


// Normal Function - First you define it, then you call it
function greet() {
  console.log('Hello from normal function');
}
greet(); // Output: "Hello from normal function"

// IIFE - Defined AND executed at the same time
(function() {
  console.log('Hello from IIFE');
})();
// Output: "Hello from IIFE"
// No need to call it by name, it executed itself

Syntax and Variants

Anatomy of an IIFE


// STEP 1: A normal anonymous function
function() {
  console.log('This is a function');
}
// ❌ This throws an error: Function statements require a function name

// STEP 2: Convert it to an expression with parentheses
(function() {
  console.log('Now it\'s a function expression');
})
// ✅ No error anymore, but it doesn't execute either

// STEP 3: Invoke it immediately
(function() {
  console.log('Now it executes!');
})();
// ✅ Output: "Now it executes!"

/*
STRUCTURE:
  (function() {    ← Parentheses convert to expression
    // code
  })               ← Close the expression
  ();              ← Invoke the function immediately
*/

IIFE with Arrow Function


// Syntax with arrow function (ES6+)
(() => {
  console.log('IIFE with arrow function');
})();
// Output: "IIFE with arrow function"

// Compact version (single expression)
(() => console.log('Compact IIFE'))();
// Output: "Compact IIFE"

Two Valid Forms of Parentheses


// FORM 1: Parentheses outside (MORE COMMON)
(function() {
  console.log('External parentheses');
})();

// FORM 2: Parentheses inside (LESS COMMON)
(function() {
  console.log('Internal parentheses');
}());

// Both work exactly the same
// The first one is more popular in the community

The Semicolon Problem

JavaScript tries to insert semicolons automatically (ASI - Automatic Semicolon Insertion), but sometimes it fails with IIFEs.


// ❌ THE PROBLEM
const greeting = 'Hello'

(function() {
  console.log('IIFE');
})();

/*
Error: TypeError: "Hello" is not a function

WHAT HAPPENED?
JavaScript interprets this as:
const greeting = 'Hello'(function() { ... })();
It tries to call 'Hello' as a function!
*/

// ✅ SOLUTION 1: Semicolon BEFORE the IIFE
const greeting2 = 'Hello';  // ← Semicolon here

(function() {
  console.log('Correct IIFE');
})();

// ✅ SOLUTION 2: DEFENSIVE semicolon at the start
const message = 'World'

;(function() {  // ← Defensive semicolon
  console.log('IIFE with defensive ;');
})();

// 🎯 PRACTICAL RULE:
// If you don't use semicolons habitually:
// → Always start IIFEs with defensive semicolon
// ;(function() { ... })();

IIFEs with Parameters


// Pass arguments to an IIFE
(function(name) {
  console.log('Hello,', name);
})('Roge');
// Output: "Hello, Roge"

// Multiple parameters
(function(name, age, city) {
  console.log(`${name} is ${age} years old and lives in ${city}`);
})('Ana', 28, 'Madrid');
// Output: "Ana is 28 years old and lives in Madrid"

// IIFE that returns a value
const result = (function(a, b) {
  return a * b;
})(4, 5);

console.log('Result:', result);
// Output: "Result: 20"
// IMPORTANT: result is NOT a function, it's the value 20

Practical Use Cases

1. Variable Encapsulation


// ❌ WITHOUT IIFE - Pollutes the global scope
var counter = 0;
var apiKey = 'secret-123';

// These variables are exposed globally
console.log(window.counter);  // 0 (globally accessible)

// ✅ WITH IIFE - Encapsulated variables
(function() {
  var counter = 0;
  var apiKey = 'secret-123';

  function increment() {
    counter++;
    console.log('Counter:', counter);
  }

  increment();  // Output: "Counter: 1"
})();

// console.log(counter);  // ❌ Error: counter is not defined

2. Module Pattern


const AppModule = (function() {
  // Private variables
  let users = [];
  const API_KEY = 'abc123';

  // Private functions
  function validateUser(name) {
    return name && name.length > 0;
  }

  // Public API (what gets exported)
  return {
    addUser(name) {
      if (validateUser(name)) {
        users.push(name);
        console.log(`User ${name} added`);
        return true;
      }
      return false;
    },

    getUsers() {
      return [...users];  // Returns copy
    },

    userCount() {
      return users.length;
    }
  };
})();

// Module usage
AppModule.addUser('Ana');     // Output: "User Ana added"
console.log(AppModule.getUsers());  // Output: ['Ana']
// console.log(AppModule.API_KEY);   // ❌ undefined (private)

3. Async/Await in IIFE


// ✅ Async IIFE to execute async code immediately
(async function() {
  try {
    console.log('Loading data...');

    const response = await fetch('https://api.example.com/users/1');
    const user = await response.json();

    console.log('User loaded:', user.name);

  } catch (error) {
    console.error('Error:', error);
  }
})();

// With arrow function
(async () => {
  const data = await fetch('https://api.example.com/posts/1');
  const post = await data.json();
  console.log('Post:', post.title);
})();

4. Private Counter


const counter = (function() {
  let count = 0;  // Private variable

  return function() {
    count++;
    return count;
  };
})();

console.log(counter());  // Output: 1
console.log(counter());  // Output: 2
console.log(counter());  // Output: 3
// console.log(count);   // ❌ Error: count is not defined

Common Mistakes


// ❌ ERROR 1: Forgetting external parentheses
function() {
  console.log('Error');
}();
// SyntaxError: Function statements require a function name

// ✅ CORRECT:
(function() {
  console.log('Correct');
})();

// ❌ ERROR 2: Forgetting invocation parentheses
(function() {
  console.log('This never executes');
});
// No error, but the function NEVER executes

// ✅ CORRECT:
(function() {
  console.log('Now it executes');
})();  // ← The () are crucial

// ❌ ERROR 3: Passing parameters incorrectly
(function(name) {
  console.log('Hello', name);  // undefined
})();
// Missing the argument

// ✅ CORRECT:
(function(name) {
  console.log('Hello', name);
})('Roge');  // Output: "Hello Roge"

Modern JavaScript vs IIFEs

Before vs Now


// ❌ BEFORE (Pre-ES6): IIFEs for encapsulation
(function() {
  var config = { apiUrl: 'https://api.example.com' };
  var apiKey = 'secret123';

  function initialize() {
    console.log('App initialized');
  }

  window.MyApp = { initialize };
})();

// ✅ NOW (ES6+): Native modules
// file: config.js
export const config = { apiUrl: 'https://api.example.com' };
const apiKey = 'secret123';  // Private (not exported)

export function initialize() {
  console.log('App initialized');
}

// file: app.js
import { config, initialize } from './config.js';

Block Scope with let/const


// ❌ BEFORE: IIFE to create scope
(function() {
  var temp = 'Only exists here';
  console.log(temp);
})();

// ✅ NOW: Block scope with {}
{
  const temp = 'Only exists here';
  console.log(temp);
}
// Simpler, less syntax

When to STILL Use IIFEs

IIFEs are still useful in these cases:

  • Inline scripts in HTML: In <script> tags without module type
  • Browser console: When writing code directly in console
  • Bookmarklets: Small scripts in bookmarks
  • Legacy code: When working with old code without build tools
  • Polyfills and libraries: For compatibility

// Example: Inline script in HTML
<script>
  (function() {
    // Avoids polluting global scope
    const myVariable = 'private';
    console.log(myVariable);
  })();
</script>

// Example: One-time config initialization
const CONFIG = (function() {
  const env = process.env.NODE_ENV || 'development';

  return env === 'development'
    ? { apiUrl: 'http://localhost:3000', debug: true }
    : { apiUrl: 'https://api.production.com', debug: false };
})();

Summary

Key Points:

  • Definition: Immediately Invoked Function Expression - function that executes when defined
  • Syntax: (function() { ... })() or (() => { ... })()
  • Uses: Encapsulation, avoid global scope pollution, create private modules
  • Semicolon: Use defensive ; at start if you don't use ; habitually
  • Modern: ES6 modules replace many uses, but IIFEs are still useful
