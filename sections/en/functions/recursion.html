Recursion

Key Idea

Recursion = a function that asks itself for help…
but leaves a note about "when to stop".

  • Without that note → chaos 😅
  • With that note → it all works.

Real-world example (VERY simple)

🪜 Climbing stairs

Imagine you're on step 5 and want to reach the ground (0).

You think about it like this:

  • "To get down from 5… I first get down from 4"
  • "To get down from 4… I first get down from 3"
  • "To get down from 3… I first get down from 2"
  • "To get down from 2… I first get down from 1"
  • "To get down from 1… I'm already down" ✅

👉 That's recursion

Now in code (without overcomplicating it)

function goDownStep(n) {
  if (n === 0) return;   // 🛑 note to stop
  console.log("I'm on step", n);
  goDownStep(n - 1);  // I call myself
}

goDownStep(3);

What happens in your head:

goDownStep(3)
→ goDownStep(2)
→ goDownStep(1)
→ goDownStep(0) 🛑

🧠 GOLDEN RULE (memorize it)

A recursive function ALWAYS has 2 parts:

  1. 🛑 Base case → when to stop
  2. 🔁 Recursive step → I call myself, but closer to the end

If one is missing → it's not proper recursion.

🍕 Another ultra-simple example

function eatSlices(n) {
  if (n === 0) {
    console.log("No pizza left");
    return;
  }

  console.log("I eat one slice");
  eatSlices(n - 1);
}

eatSlices(3);

Output:

I eat one slice
I eat one slice
I eat one slice
No pizza left

🧩 Factorial (should not scare you now)

function factorial(n) {
  if (n === 1) return 1;      // 🛑
  return n * factorial(n-1); // 🔁
}

Think of it like this:

"The factorial of 5 is
5 × the factorial of 4
and the factorial of 4 already knows what to do…"

🎯 Magic phrase for interviews

"Recursion is when a function solves a problem by delegating a smaller version of the same problem to itself, and stops at a base case."
