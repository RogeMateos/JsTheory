Practical Project: HTML + JavaScript + DOM

Real-world project setup with the DOM

Key concept (before starting)

The DOM only exists in the browser.

JavaScript can run in many environments (Node.js, browser, etc.), but document only exists when JS runs inside a web page.

1️⃣ Create the basic project structure

We create a folder with two files:

dom-example/
 ├── dom-example.html
 └── dom-example.js

2️⃣ Create the HTML (dom-example.html)

This HTML will be simple but real, enough to practice DOM.

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Example HTML</title>

    <!-- Load external JS -->
    <script src="./dom-example.js" defer></script>
  </head>

  <body>
    <h1 id="title">My title</h1>
    <button id="btn">My button</button>
  </body>
</html>

🧩 What's happening here

  • <!doctype html> → indicates modern HTML
  • <meta charset="UTF-8"> → supports accents and special characters
  • id="title" and id="btn" → allow us to access these elements from JS
  • defer → ensures the DOM is loaded before executing JS

👉 Modern best practice: use defer in external scripts.

3️⃣ Serve the HTML in the browser (Live Server)

Why isn't opening the file enough?

Although you could open the HTML directly, working with a local server is the right approach.

Steps:

  1. Install the Live Server extension in VS Code
  2. Right-click on dom-example.html
  3. Select "Open with Live Server"

Result:

  • ✅ Browser opens
  • ✅ URL like: http://127.0.0.1:5500/dom-example.html
  • ✅ You see the title and button

✅ You now have a real web page.

4️⃣ First contact with JavaScript and the DOM

Open dom-example.js:

console.log("My script loaded");

Where does this log appear?

  • ❌ NOT in the VS Code terminal
  • ✅ YES in the browser → Inspect → Console

🔑 Golden rule:

If JS is loaded from HTML, it executes in the browser.

5️⃣ Access the document (document)

Now the DOM exists.

console.log(document);

What you're seeing

  • document represents the entire HTML page
  • It's an object with nodes, properties, and methods
  • It's the entry point to the DOM

6️⃣ Access a DOM element

Let's find the <h1> using its id.

const title = document.querySelector("#title");
console.log(title);

What querySelector returns

  • Returns the first matching element
  • If it doesn't exist → returns null

That's why it's always good practice to check:

if (!title) {
  console.error("Element #title not found");
}

7️⃣ Read and modify DOM content

Read the text

console.log(title.textContent);

Output:

My title

Modify the text

title.textContent = "My new title";

🔄 When you refresh the page:

  • The text changes in real time
  • The original HTML is not modified, only the DOM in memory

8️⃣ Real interaction: user events

Now let's react to a user action.

const btn = document.querySelector("#btn");

btn.addEventListener("click", () => {
  title.textContent = "You clicked ✅";
});

What's happening here

  1. We listen for the click event
  2. When it occurs:
    • The function executes
    • The DOM is modified

This is JavaScript interacting with the web

9️⃣ Complete final code (JS)

console.log("My script loaded");

const title = document.querySelector("#title");
const btn = document.querySelector("#btn");

if (!title || !btn) {
  console.error("Missing elements in HTML");
} else {
  console.log("Initial text:", title.textContent);

  title.textContent = "My new title";

  btn.addEventListener("click", () => {
    title.textContent = "You clicked ✅";
  });
}

🔥 Common error: "document is not defined"

❌ This DOESN'T work:

node dom-example.js

❓ Why it fails

  • Node.js doesn't have DOM
  • document only exists in the browser
  • The HTML creates the context

✅ HTML loads the JavaScript, not the other way around.

🧠 Key ideas to remember

  • ✅ The DOM is a representation of HTML in memory
  • ✅ JavaScript accesses the DOM using document
  • ✅ querySelector returns real DOM elements
  • ✅ Modifying textContent changes the page in real time
  • ✅ Events connect the user with code
  • ✅ The browser console is your best friend
  • ✅ defer ensures the DOM is ready before executing JS
