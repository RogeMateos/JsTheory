DOM Element Manipulation in JavaScript

How to modify elements once selected

Tutorial objective

Learn to modify DOM elements once we've selected them:

  • ✅ Change text
  • ✅ Change HTML structure
  • ✅ Understand what a reference is
  • ✅ Use correct and safe APIs
  • ✅ Avoid typical beginner mistakes

This point is key, because this is where JavaScript starts to visually affect the page.

Previous context: selection ≠ modification

So far we know how to select DOM elements (getElementById, querySelector, etc.).

The next natural step is:

"Okay, I have the element… now how do I change it?"

This is where DOM manipulation comes in.

Example HTML (base scenario)

This isn't an HTML class, but we need visual context.

<h1 id="title">Original title</h1>

<div id="container">
  <button>Click</button>
</div>

Step 1 – Select an element (the reference idea)

const title = document.getElementById("title");

Key concept (very important)

  • ❌ title is not the text
  • ❌ title is not a copy
  • ✅ title is a reference to a DOM object (an Element)

This explains why we can modify it even though it's declared with const.

Important clarification about const

const title = document.getElementById("title");

title = null;            // ❌ NOT allowed (reassignment)
title.textContent = "";  // ✅ YES allowed (mutating the object)

const prevents reassigning the variable, not modifying the object.

Step 2 – Modify text with textContent (recommended way)

title.textContent = "Hello, JavaScript";

What does textContent do?

  • Changes the internal text of the element
  • Doesn't interpret HTML
  • It's safe and predictable

When to use it

  • ✅ When you only want to change text
  • ✅ When content can come from variables or the user
  • ✅ When you don't want security risks

👉 General rule:

If it's text → textContent

Step 3 – Manipulate containers (internal structure)

Now let's work with the container.

const container = document.querySelector("#container");

This element isn't "just text", but a container of other elements.

Step 4 – innerHTML: what it is and what it's for

container.innerHTML = "<p>This is a new paragraph</p>";

What's happening here?

  1. All internal content of the container is deleted
  2. It's recreated using the HTML string
  3. The browser interprets that HTML

When it can be useful

  • Quick prototypes
  • Simple examples
  • HTML totally controlled by you

⚠️ Important warning (very senior)

  • ❌ innerHTML removes event listeners
  • ❌ innerHTML can cause XSS if content isn't safe

Problem example:

const button = document.querySelector("#container button");
button.addEventListener("click", () => console.log("hello"));

container.innerHTML = "<p>New</p>"; // button and its listener disappear

Step 5 – Recommended alternative: create nodes with the DOM API

This is the correct and professional way.

const container = document.querySelector("#container");

const p = document.createElement("p");
p.textContent = "This is a new paragraph";

container.replaceChildren(p);

Advantages

  • ✅ You don't execute HTML as a string
  • ✅ More secure
  • ✅ You don't lose control of the DOM
  • ✅ Easier to maintain and debug

👉 Modern best practices avoid innerHTML whenever possible.

textContent vs innerHTML (quick summary)

Situation Use
Text only textContent
Controlled dynamic HTML createElement
Quick prototype innerHTML (with care)

Extra note: innerText vs textContent

  • textContent → fast, doesn't depend on CSS
  • innerText → depends on visibility and styles

👉 For tutorials and logic: use textContent.

Step 6 – Safe handling of elements that may not exist

const title = document.getElementById("title");

if (title) {
  title.textContent = "Hello";
}

This prevents errors when the DOM changes or the script is reused.

Complete final example (recommended version)

// Selection
const title = document.getElementById("title");
const container = document.querySelector("#container");

// Modify text
if (title) {
  title.textContent = "Hello, JavaScript";
}

// Modify structure without innerHTML
if (container) {
  const p = document.createElement("p");
  p.textContent = "This is a new paragraph";

  container.replaceChildren(p);
}

Typical mistakes to avoid

  • ❌ Thinking that const makes the DOM immutable
  • ❌ Using innerHTML for everything
  • ❌ Inserting user data with innerHTML
  • ❌ Losing event listeners without knowing why

Mini-exercises (recommended)

  1. Change the <h1> text when clicking a button
  2. Replace the content of #container with:
    • a <p>
    • and below a <button> that changes the <p> text
  3. Do the same without using innerHTML

Key idea to close

Manipulating the DOM isn't "randomly changing things".

It's working with references, mutating objects and using the correct API for each case.

✅ Summary

  • Variables with const can point to mutable DOM objects
  • textContent to change text safely
  • innerHTML can be dangerous (XSS, loss of listeners)
  • createElement + replaceChildren is the professional way
  • Always verify the element exists before modifying it
  • Use textContent instead of innerText for logic
