Event Bubbling and Event Delegation

Understanding how events propagate in JavaScript

🎯 Simple Definition for Interviews

Event Bubbling (Event Propagation)

When you click on an element, the event travels up through the DOM tree.

It's like throwing a stone in a pond: the waves go up from the clicked element toward its parents.

Event Delegation (Event Delegation)

Instead of putting a listener on each element, you put ONE SINGLE listener on the parent and let bubbling tell you which element was clicked.

It's like a doorman: instead of having a doorman at each door, you have one at the entrance who says "which door did people enter through".

🌊 Event Bubbling (Event Propagation)

What happens when you click?

The event doesn't stay in the element where you clicked. It travels up toward the parent elements.

<div class="container">
  <button class="button">Click me</button>
</div>

Order of bubbling

When you click the button:

1. Click on button
2. Goes up to div.container
3. Goes up to body
4. Goes up to html
5. Reaches document

Practical example

// If you put listeners at all levels:

document.addEventListener('click', () => {
  console.log('1. document')
})

document.body.addEventListener('click', () => {
  console.log('2. body')
})

document.querySelector('.container').addEventListener('click', () => {
  console.log('3. container')
})

document.querySelector('.button').addEventListener('click', () => {
  console.log('4. button')
})

// When you click the button, you'll see in console:
// 4. button
// 3. container
// 2. body
// 1. document

⚡ Key point

Bubbling happens always, even if there are no listeners above.

It's a browser behavior, not a JavaScript behavior.

🧠 Event Delegation (Event Delegation)

❌ The problem without delegation

Imagine you have a list of 100 buttons:

<ul class="jobs-list">
  <li><button class="button-apply">Apply</button></li>
  <li><button class="button-apply">Apply</button></li>
  <li><button class="button-apply">Apply</button></li>
  <!-- ... 97 more buttons -->
</ul>

Traditional approach (inefficient)

const buttons = document.querySelectorAll('.button-apply')

buttons.forEach((button) => {
  button.addEventListener('click', function () {
    button.textContent = 'Applied!'
    button.disabled = true
  })
})

// Problem: 100 listeners for 100 buttons
// And if you dynamically add a new button... it won't have a listener

✅ Solution: Event Delegation

Instead of listeners on each button, one single listener on the parent container.

const jobsList = document.querySelector('.jobs-list')

jobsList.addEventListener('click', function (event) {
  // Find the closest button to the clicked element
  const button = event.target.closest('.button-apply')

  // If it's not a button, exit
  if (!button) return

  // If it is a button, do something
  button.textContent = 'Applied!'
  button.disabled = true
})

🎯 Why does it work?

  • You click on the button
  • The event bubbles up
  • It reaches the container that has the listener
  • The listener asks: "Is it a .button-apply?"
  • If yes → execute the code

🧰 Important tools: event.target vs event.currentTarget

What is event.target?

The element where you actually clicked.

<div class="container">
  <button class="button">Click me</button>
</div>
document.querySelector('.container').addEventListener('click', (event) => {
  console.log(event.target) // ← The button
})

What is event.currentTarget?

The element that has the listener.

document.querySelector('.container').addEventListener('click', (event) => {
  console.log(event.currentTarget) // ← The container
})

📝 Mental summary

target = Where you clicked

currentTarget = Where the listener is

🎯 .closest() — The key tool for delegation

⚠️ The problem

If the button has an element inside (like a span), event.target will be the span, not the button:

<button class="button-apply">
  <span>Apply</span>
</button>
// If you click on the span:
event.target // ← It's the <span>, not the <button>

// This fails:
if (event.target.classList.contains('button-apply')) {
  // It doesn't enter because event.target is the span
}

✅ Solution: .closest()

.closest() travels up the DOM until it finds the element you're looking for.

const button = event.target.closest('.button-apply')

// This works even if you clicked on the span
// Because .closest() travels up until it finds .button-apply

How .closest() works

event.target = <span>
     ↓
.closest('.button-apply')
     ↓
Travels up until it finds an element with that class
     ↓
Returns <button class="button-apply">

⚡ stopPropagation() — Stop the bubbling

What does it do?

Stops the event from continuing to travel up the DOM.

button.addEventListener('click', (event) => {
  event.stopPropagation()
  // The event does NOT continue traveling
  // The parent's listener does NOT execute
})

✔️ When to use it

  • Modals (so they don't close when you click inside)
  • Dropdowns (to keep them open)
  • Isolated components

❌ When to avoid it

If you use stopPropagation() too much, you can break global logic:

// Global listener to close menu
document.addEventListener('click', closeMenu)

// If you stop bubbling here...
button.addEventListener('click', (event) => {
  event.stopPropagation()
})

// ❌ The global listener never executes

🏆 Professional Delegation Pattern

Separate logic

// 1. Function that handles the logic
function handleApplyClick(button) {
  button.textContent = 'Applied!'
  button.disabled = true
}

// 2. Delegated listener that uses that function
const jobsList = document.querySelector('.jobs-list')

jobsList.addEventListener('click', (event) => {
  const button = event.target.closest('.button-apply')
  if (!button) return

  handleApplyClick(button)
})

Why is it better?

  • ✅ Cleaner code
  • ✅ Easy to test
  • ✅ Reusable
  • ✅ Maintainable

📊 Comparison: When to use what

🟢 Use Delegation
  • Dynamic lists
  • 10+ elements
  • Scalable apps
  • UI that changes
🔵 Use individual listeners
  • 1–3 elements
  • Static elements
  • Quick prototypes
  • Unique elements
