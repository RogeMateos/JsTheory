More Events in JavaScript

input, blur, submit, preventDefault, and keydown

🔄 Introduction

Beyond click and change

So far we've seen the click and change events, but there are many more events we can use to interact with the user. We won't be able to cover them all, but we'll look at some important ones and explain the concept of preventDefault.

♿ A note on accessibility

🏷️ The label is essential

For accessibility purposes, every input element should have an associated label tag so that screen readers and other assistive technologies can correctly identify the field's purpose.

This element is the most important when creating accessible forms.

<label for="input-name">Name</label>
<input type="text" id="input-name" />

You can also nest the input inside the label:

<label>
  Name
  <input type="text" id="input-name" />
</label>

In this course's examples we skip the label tags to keep the code simpler and avoid repetition, but in production you should always use them.

⌨️ The input event

When does it fire?

The input event fires when the user types in an input.

<input type="text" id="input-name" />

✅ Example

const inputName = document.getElementById('input-name')

inputName.addEventListener('input', function () {
  console.log('Typing...')
})

⚠️ Keep in mind

"Typing" also includes when the user is deleting text. The input event fires on any change to the field's content.

👁️ The blur event

When does it fire?

The blur event fires when the user loses focus on the input. It's very useful, for example, to validate that the user has filled in all form fields before submitting.

<input type="text" id="input-name" />

✅ Example

const inputName = document.getElementById('input-name')

inputName.addEventListener('blur', function () {
  console.log('Lost focus')
})

🔄 The opposite event: focus

The opposite of blur is focus, which fires when the input receives focus from the user.

📤 The submit event

When does it fire?

The submit event fires when the user submits the form.

<form id="form">
  <input name="name" type="text" id="input-name" />
  <button type="submit">Submit</button>
</form>

✅ Listening for submit

const form = document.getElementById('form')

form.addEventListener('submit', function (event) {
  console.log('Form submitted')
})

🤔 How do you submit a form?

There are mainly two ways:

  • Clicking the submit type button inside the form.
  • Pressing the Enter key while an input inside the form has focus.

❌ The problem: the page reloads

If you try the code above, you'll find that on submit the page reloads and adds the input's name value to the URL.

This is the browser's default behavior and, even though we've listened for the submit event in JavaScript, the browser still reloads the page.

🛑 event.preventDefault()

✅ The solution

To prevent the reload, we can use the event's preventDefault method:

form.addEventListener('submit', function (event) {
  event.preventDefault()
  console.log('Form submitted')
})

💡 What does it actually do?

This means we want to prevent the default behavior of the event.

This isn't unique to forms. For example, links by default navigate the browser to the link's URL when clicked, but we can also prevent that behavior.

🎹 The keydown event

When does it fire?

The keydown event fires when the user presses a key.

<input type="text" id="input-name" />

✅ Example

// By listening directly on the document, we can listen for all keys
// pressed regardless of where the focus is
document.addEventListener('keydown', function (event) {
  console.log('Key pressed:', event.key)
})

🔄 The opposite event: keyup

The opposite of keydown is keyup, which fires when the user releases a key.

📋 Keyboard event properties

The event provides important information about the key:

  • event.key: The key that was pressed.
  • event.code: The key code.
  • event.shiftKey: Whether the Shift key is being held.
  • event.ctrlKey: Whether the Ctrl key is being held.
  • event.altKey: Whether the Alt key is being held.
  • event.metaKey: Whether the Meta key is being held (Cmd on Mac).
