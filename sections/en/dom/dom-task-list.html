Tutorial: Create a Task List with JavaScript and the DOM (from scratch)

Practical mini application with pure JavaScript and the DOM

Introduction

In this exercise we'll create a mini task list application using pure JavaScript and the DOM. This isn't advanced web development or frameworks: the goal is to understand how JavaScript interacts with HTML.

By the end of this tutorial you'll know how to:

  • Select DOM elements
  • Listen to events (click, Enter)
  • Create and delete HTML elements dynamically
  • Avoid common mistakes when working with inputs
  • Understand why these techniques are key in frontend

🎯 Exercise objective

Build a very simple app where:

  • The user writes a task in an input
  • Presses a button or Enter
  • The task is added to a list
  • The input is cleared automatically
  • If you click on a task, it gets deleted
  • Empty tasks are not allowed

🧱 Step 1: Minimal HTML structure

We create a file called tasklist.html.

What does our interface need?

  • A title
  • A text input
  • A button
  • A list (ul) where tasks will go
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Task List</title>

    <!-- defer ensures DOM is loaded before executing JS -->
    <script defer src="tasklist.js"></script>
  </head>
  <body>
    <h1>My Tasks</h1>

    <input
      id="taskInput"
      type="text"
      placeholder="Write a task"
    />

    <button id="addTaskBtn">Add task</button>

    <ul id="taskList"></ul>
  </body>
</html>

🔎 Important note (very senior):

We use defer in the script to ensure the DOM is loaded before accessing elements. This avoids many typical bugs in real projects.

🧠 Step 2: Which elements will we interact with?

From JavaScript we need to access:

  • The input → read and clear text
  • The button → detect click
  • The list → add and delete tasks

We create tasklist.js.

const taskInput = document.getElementById("taskInput");
const addTaskBtn = document.getElementById("addTaskBtn");
const taskList = document.getElementById("taskList");

💡 Best practice:

We save references once in constants.

⚙️ Step 3: Main function – add task

All logic should live in a reusable function.

function addTask() {
  const text = taskInput.value.trim();

  // If input is empty, do nothing
  if (text === "") return;

  const li = document.createElement("li");
  li.textContent = text;

  taskList.appendChild(li);

  // Clear the input
  taskInput.value = "";
  taskInput.focus();
}

What's happening here?

  1. We read the input value
  2. We use trim() to avoid empty texts
  3. We dynamically create a <li>
  4. We add it to the <ul>
  5. We clear the input and return focus

👉 This is pure DOM in action.

🖱️ Step 4: Click event on the button

Now we connect the button with the function.

addTaskBtn.addEventListener("click", addTask);

✔️ The button doesn't contain logic, it just triggers the action.

⌨️ Step 5: Add task by pressing Enter

We want the user to be able to press Enter inside the input.

taskInput.addEventListener("keydown", (e) => {
  if (e.key === "Enter") {
    addTask();
  }
});

📌 We use keydown and not keypress (better support and current practice).

🗑️ Step 6: Delete tasks by clicking

Here we use a very important technique in frontend:
👉 event delegation

Instead of adding a listener to each <li>, we add just one to the <ul>.

taskList.addEventListener("click", (e) => {
  if (e.target.tagName === "LI") {
    e.target.remove();
  }
});

Why is this best practice?

  • Works even with dynamically created elements
  • Fewer listeners = better performance
  • Widely used in real projects

🧪 Final result

Now we can:

  • Add tasks with button or Enter
  • See them appear dynamically
  • Delete them with a click
  • Prevent empty tasks

All this without frameworks, just JavaScript and DOM.

⚠️ Common errors (and how to avoid them)

Error Reason Solution
Shows [object HTMLInputElement] You're using the node, not its value Use .value
Empty tasks are created You don't validate the text Use trim()
Doesn't work on load DOM not ready Use defer
Enter doesn't work Wrong event Use keydown

🧠 Conclusion

This exercise isn't about "making a website", but understanding why JavaScript is so powerful in frontend:

  • It manipulates the DOM
  • It responds to user events

Every modern framework (React, Vue, Angular) builds on these foundations.
