Introduction to REST APIs (Step by Step)

When we start developing applications, we quickly encounter a reality: there are many languages, many frameworks, and many tools.

Then a key question arises:

👉 How do different systems communicate with each other?

This is where APIs come into play.

1. What is an API?

An API (Application Programming Interface) is a contract that allows two systems to communicate with each other.

  • A frontend (for example, a JavaScript app)
  • A backend (for example, in Python, Java, or Node.js)

They don't need to be written in the same language.
They only need to speak the same language.

That language is standards.

2. Types of APIs (overview)

There are different types of APIs:

  • SOAP (widely used 15–20 years ago)
  • REST (the most common in web development)
  • GraphQL
  • gRPC

In this tutorial we will focus on REST APIs, because they are the most used in modern web applications.

3. What is a REST API?

REST is not a specific technology, it is an architectural style.

In practice, a REST API usually meets these characteristics:

  • Uses the HTTP protocol
  • Accesses data through URLs
  • Works with resources (not with actions)
  • Is stateless
  • Normally exchanges data in JSON format

4. HTTP and URLs: the foundation

When you visit a website, you're already using HTTP:

  • Protocol: https://
  • Address: www.example.com

REST APIs use exactly the same thing.

Examples of URLs in an API:

  • /users
  • /users/42
  • /products
  • /orders/123

Each URL represents a resource.

5. What is a resource (key concept)

A very common mistake when starting is to think that a URL is a function.

In REST, a URL represents a noun, not a verb.

Correct examples:

  • /users
  • /users/10
  • /todos

Incorrect examples:

  • /getUsers
  • /createUser
  • /deleteProduct

👉 Actions are defined by the HTTP method, not the URL name.

6. HTTP Methods and their meaning

HTTP methods indicate what we want to do with the resource.

The most important ones:

  • GET → Retrieve data
  • POST → Create a resource
  • PUT → Replace a complete resource
  • PATCH → Partially modify
  • DELETE → Delete a resource

Examples:

  • GET /users → get all users
  • GET /users/5 → get user 5
  • POST /users → create a user
  • PATCH /users/5 → modify user 5
  • DELETE /users/5 → delete user 5

7. JSON: the format for data exchange

REST APIs usually exchange data using JSON
(JSON = JavaScript Object Notation).

JSON is:

  • Plain text
  • Lightweight
  • Easy to read
  • Language independent

JSON example:

{
  "id": 1,
  "name": "Roge",
  "email": "roge@email.com"
}

Although it looks like a JavaScript object, it's not a JS object, it's text with rules.

8. Request and Response (how communication flows)

REST communication always follows this flow:

  1. The client sends a request
  2. The server processes the request
  3. The server responds with a response

Real example

Request:

  • Method: GET
  • URL: /users/1

Response:

  • Status: 200 OK
  • Body:
{
  "id": 1,
  "name": "Roge"
}

9. Status Codes (very important)

Status codes indicate what happened with the request.

Some essential ones:

  • 200 OK → Everything correct
  • 201 Created → Resource created
  • 204 No Content → Success without content
  • 400 Bad Request → Incorrect data
  • 401 Unauthorized → Not authenticated
  • 403 Forbidden → No permissions
  • 404 Not Found → Doesn't exist
  • 500 Internal Server Error → Server error

👉 The frontend shouldn't guess what happened: the status code tells it.

10. Stateless

A REST API is usually stateless.

This means that:

  • Each request is independent
  • The server doesn't "remember" previous requests
  • All necessary information travels in each request

Example:

  • The authentication token is sent in each request
  • The server doesn't depend on a session in memory

This makes REST APIs scalable and simple.

11. Common headers

In addition to the body, requests include headers.

Some very common ones:

  • Content-Type: application/json
  • Accept: application/json
  • Authorization: Bearer TOKEN

Many real problems come from misconfigured headers.

12. Complete REST API example

Get tasks

GET /todos

Response:

[
  { "id": 1, "title": "Buy bread", "done": false },
  { "id": 2, "title": "Study REST", "done": true }
]

Create a task

POST /todos

Request body:

{
  "title": "Go to gym",
  "done": false
}

Response:

  • Status: 201 Created
{
  "id": 3,
  "title": "Go to gym",
  "done": false
}

13. Why REST works so well

REST has become the de facto standard because:

  • It's based on HTTP (already existing)
  • It's simple to understand
  • It's flexible
  • It works the same across any language
  • It's ideal for web and mobile applications

A JavaScript frontend can communicate without problems with a backend in Python, Java, or Go thanks to these standards.

14. Final summary

  • An API is a contract between systems
  • REST is a style for designing APIs
  • Uses HTTP, URLs and standard methods
  • Works with resources
  • Normally exchanges data in JSON
  • It's simple, scalable and widely used in the modern web
