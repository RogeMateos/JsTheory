1) Quick preparation: which endpoint we'll use

PokeAPI works with endpoints. The one we need to search for a Pokémon is:

GET https://pokeapi.co/api/v2/pokemon/{name-or-id}/

Examples:

  • .../pokemon/pikachu/
  • .../pokemon/25/

Note: You don't need authentication (no API key) for this endpoint.

2) Step 1 — Your first request with fetch (the "minimal" version)

This is the most basic:

async function getPokemonBasic() {
  const res = await fetch("https://pokeapi.co/api/v2/pokemon/pikachu/");
  const data = await res.json();
  console.log(data);
}

getPokemonBasic();

What's happening:

  • fetch(...) makes the HTTP request
  • res.json() transforms the body into a JavaScript object (JSON)
  • console.log(data) lets you see the "massive" information

3) Step 2 — Understanding JSON: navigating properties (dot notation)

Once you have data, you can access properties with the dot:

async function showName() {
  const res = await fetch("https://pokeapi.co/api/v2/pokemon/pikachu/");
  const data = await res.json();

  console.log("Name:", data.name); // "pikachu"
}

showName();

Key idea:

If the JSON has a name property, in JS you access it with data.name.

4) Step 3 — Accessing arrays: abilities and forEach

In the JSON, abilities is an array. Each element has a structure similar to:

  • ability.name (inside each item)

Example:

async function showAbilities() {
  const res = await fetch("https://pokeapi.co/api/v2/pokemon/pikachu/");
  const data = await res.json();

  console.log("Abilities of:", data.name);

  data.abilities.forEach((item) => {
    console.log("-", item.ability.name);
  });
}

showAbilities();

What you learn here:

  • data.abilities is an array
  • forEach iterates through each element
  • inside the element you navigate to item.ability.name

5) Step 4 — Making it a reusable function ("pro" base)

In a serious tutorial, we don't want to repeat fetch everywhere. We create a reusable function:

const API_BASE = "https://pokeapi.co/api/v2";

function normalizePokemonQuery(value) {
  return value.trim().toLowerCase();
}

async function getPokemon(rawQuery) {
  const query = normalizePokemonQuery(rawQuery);

  if (!query) {
    throw new Error("Enter the name or id of a Pokémon.");
  }

  const url = `${API_BASE}/pokemon/${encodeURIComponent(query)}/`;
  const res = await fetch(url);

  // Important: fetch does NOT throw error for 404/500 automatically
  if (!res.ok) {
    if (res.status === 404) throw new Error(`"${query}" doesn't exist in PokeAPI.`);
    if (res.status === 429) throw new Error("Too many requests. Wait and try again.");
    throw new Error(`HTTP Error ${res.status} (${res.statusText})`);
  }

  return res.json();
}

Why this is better:

  • trim() and toLowerCase() avoid failures from typing "Pikachu " or "PIKACHU"
  • encodeURIComponent avoids problems with special characters
  • res.ok is the difference between "demo" and "production"
  • throw new Error(...) lets you control it with try/catch

6) Step 5 — Using try/catch (real error handling)

Now we consume the function:

async function demo() {
  try {
    const data = await getPokemon("Pikachu");

    console.log("Name:", data.name);
    console.log("Abilities:");
    data.abilities.forEach((item) => console.log("-", item.ability.name));
  } catch (err) {
    console.error("Request failed:", err.message);
  }
}

demo();

Important differences:

  • 404 → we show it as a "human" error
  • 429 → "you're making too many requests"
  • network error → also falls here (eg: no internet)

7) Step 6 — Don't couple your UI to a huge JSON (transformation)

In real apps, you don't want to pass the complete "massive" object to your UI. Better to create a "view model" (clean object):

function mapPokemonToViewModel(pokemon) {
  return {
    id: pokemon.id,
    name: pokemon.name,
    height: pokemon.height,
    weight: pokemon.weight,
    abilities: pokemon.abilities.map((a) => a.ability.name),
    sprite: pokemon.sprites?.front_default ?? null,
  };
}

Usage:

async function demoViewModel() {
  try {
    const data = await getPokemon("pikachu");
    const pokemon = mapPokemonToViewModel(data);

    console.log(pokemon);
    // pokemon.abilities is now an array of strings
  } catch (err) {
    console.error(err.message);
  }
}

demoViewModel();

This gives you:

  • minimal and clear data
  • less risk of "breaking" UI if something changes
  • easier code for a junior

8) Step 7 — Extra: canceling requests (AbortController)

If you make a search and the user types fast, this can happen:

  • you request "pi"
  • then "pika"
  • but "pi" responds later and overwrites the correct result

Solution: cancel the previous request.

let controller = null;

async function searchPokemon(query) {
  try {
    if (controller) controller.abort();
    controller = new AbortController();

    const data = await getPokemonWithSignal(query, controller.signal);
    return mapPokemonToViewModel(data);
  } catch (err) {
    if (err.name === "AbortError") return null; // ignore
    throw err;
  }
}

async function getPokemonWithSignal(rawQuery, signal) {
  const query = normalizePokemonQuery(rawQuery);

  if (!query) throw new Error("Enter the name or id of a Pokémon.");

  const url = `${API_BASE}/pokemon/${encodeURIComponent(query)}/`;
  const res = await fetch(url, { signal });

  if (!res.ok) {
    if (res.status === 404) throw new Error(`"${query}" doesn't exist in PokeAPI.`);
    if (res.status === 429) throw new Error("Too many requests. Wait and try again.");
    throw new Error(`HTTP Error ${res.status} (${res.statusText})`);
  }

  return res.json();
}

9) Common errors (and how to avoid them)

❌ "My catch doesn't execute with 404"

Cause: Because fetch doesn't throw for 404.

Solution: if (!res.ok) throw ...

❌ "I get undefined in sprites"

Cause: Some fields can be null.

Solution: pokemon.sprites?.front_default ?? null

❌ "User types with spaces or capitals and it fails"

Solution: trim() + toLowerCase()

❌ "Too many requests"

Cause: 429 can appear if you spam.

Solution: debounce, cache, paginate, or wait.
