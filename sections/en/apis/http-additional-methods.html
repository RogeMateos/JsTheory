Additional HTTP methods: PATCH and OPTIONS

So far we've seen the most common HTTP methods:

  • GET → Get data
  • POST → Create a resource
  • PUT → Update a complete resource
  • DELETE → Delete a resource

But the HTTP protocol defines more methods, and two of the most important that are also used in REST APIs are:

  • PATCH
  • OPTIONS

Let's see what they do and when to use them, with a simple example.

1️⃣ PATCH – Partially update a resource

What does "partially update" mean?

Partially updating a resource means modifying only a specific part of the resource, without having to send all its data.

📌 Real example:

You have a post with many fields:

  • id
  • title
  • body
  • author
  • date

And you only want to change the title.

PATCH vs PUT (key difference)

PUT (complete update)

  • The entire object is sent
  • If a field is missing, it may be overwritten or lost
  • Ideal when you replace the entire resource

PATCH (partial update)

  • Only what changes is sent
  • The rest of the resource remains the same
  • Ideal for small and specific changes

👉 This difference also helps developers understand the operation's intent just by seeing the HTTP method.

2️⃣ Practical example: update only the post title

Step 1: Correct URL

When we update a resource, we no longer use just /posts, but:

/posts/10 → to update the post with id 10

Step 2: HTTP Method

We use PATCH, because the update is partial.

Step 3: Request Body

Since we only want to change the title, we don't send the complete object.

Conceptual body example:

{
  "title": "New post title"
}

That's it.
We don't send body, nor author, nor anything else.

Step 4: Server Response

The server:

  • Keeps all original data
  • Updates only the title field
  • Returns the complete updated resource

📌 Expected result:

  • The post still has the same content
  • The title is now the new one

3️⃣ Complete code with fetch (PATCH)

async function updatePostTitle(postId, newTitle) {
  const url = `https://jsonplaceholder.typicode.com/posts/${postId}`;

  const response = await fetch(url, {
    method: 'PATCH',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      title: newTitle
    })
  });

  if (!response.ok) {
    throw new Error(`HTTP error ${response.status}`);
  }

  const updatedPost = await response.json();
  console.log('Updated post:', updatedPost);
  return updatedPost;
}

// Use the function
updatePostTitle(1, 'My awesome new title');

4️⃣ OPTIONS – Discover what methods an endpoint accepts

What does OPTIONS do?

OPTIONS is a method that asks the server:
"What operations can I do on this endpoint?"

It doesn't modify data, it only returns information about:

  • What HTTP methods are allowed (GET, POST, PUT, PATCH, DELETE...)
  • What headers are accepted
  • If it allows CORS

When is it used?

  • CORS preflight: The browser automatically sends an OPTIONS request before making POST/PUT/DELETE from another domain
  • API exploration: To know what you can do without having to try
  • Debugging: To validate CORS configuration

5️⃣ Example with OPTIONS

async function checkEndpointOptions(url) {
  const response = await fetch(url, {
    method: 'OPTIONS'
  });

  // See what methods are allowed
  const allowedMethods = response.headers.get('Allow');
  console.log('Allowed methods:', allowedMethods);

  // See CORS headers
  const corsHeaders = response.headers.get('Access-Control-Allow-Methods');
  console.log('CORS allows:', corsHeaders);
}

checkEndpointOptions('https://jsonplaceholder.typicode.com/posts/1');

Typical OPTIONS response:

Allow: GET, POST, PUT, PATCH, DELETE, OPTIONS
Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization

6️⃣ HTTP methods summary table

Method Purpose Body Idempotent
GET Read data No Yes
POST Create resource Yes No
PUT Complete replacement Yes Yes
PATCH Partial update Yes No*
DELETE Remove No Yes
OPTIONS Query methods No Yes

* PATCH can be idempotent depending on implementation

7️⃣ When to use each method (practical guide)

Use GET when:

  • You only want to read information
  • You won't modify anything on the server

Use POST when:

  • You create a new resource
  • You execute an action that is not idempotent

Use PUT when:

  • You replace a complete resource
  • You have all the resource data

Use PATCH when:

  • You only modify some fields
  • You don't want to send the complete object

Use DELETE when:

  • You want to delete a resource

Use OPTIONS when:

  • You need to know what methods an endpoint accepts
  • You're debugging CORS issues

8️⃣ Key summary

  • PATCH is ideal for partial updates (you only send what changes)
  • PUT is for replacing the complete resource
  • OPTIONS tells you what you can do on an endpoint
  • Using the correct method makes your code clearer and more semantic
