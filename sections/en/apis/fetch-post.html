Creating a POST with fetch

Step-by-step tutorial (as you would in a real project)

Step 0) What you will achieve

You will send data to a server to create a resource (a "post") using:

  • fetch(url, { method: "POST", headers, body })
  • JSON.stringify() to convert your JS object to JSON
  • response.ok + response.json() to handle the response properly

1) Let's clarify concepts (to avoid confusion)

✅ "JSON" vs "JavaScript Object"

  • JS Object: lives in memory { title: '...' }
  • JSON: is a string with a specific format '{"title":"..."}'

That's why in the request body, you almost always send JSON.stringify(obj).

✅ "Content-Type" is not "content"

  • Header: Content-Type
  • Typical value: application/json

Mental example:

  • Content-Type = "I'm sending you the body in JSON format"
  • Accept = "I prefer you to respond in JSON" (optional but good practice)

2) Understand the idea: same URL, different method

In a REST API, the URL represents the resource and the HTTP method represents the action.

  • GET /posts → list posts
  • POST /posts → create a post
  • GET /posts/101 → get one
  • PUT /posts/101 → replace
  • PATCH /posts/101 → partial update
  • DELETE /posts/101 → delete

📌 The URL represents a resource (posts) and the HTTP method represents the action.

Same URL, different behavior by method.

3) Define the resource URL

We'll use JSONPlaceholder (test API):

const URL = "https://jsonplaceholder.typicode.com/posts";

4) Create the "post" object in JavaScript (this is NOT JSON yet)

Normally the backend generates the id, so you send the basics:

const newPost = {
  userId: 1,
  title: "This is my post title",
  body: "This is my post body",
};

Why don't I send the id?

In a POST, normally the backend creates the ID (autoincrement / UUID).

In a real API, the backend responds with:

  • the created resource
  • and/or a Location header (e.g. /posts/101)
  • typical status: 201 Created

📌 JSONPlaceholder returns id: 101 as a simulation.

5) Convert that object to JSON to send it in the body

The body of an HTTP request is text (normally).
To send JSON, you convert your object to a JSON string: 

const bodyAsJson = JSON.stringify(newPost);

6) Prepare the fetch with method, headers and body

Why headers

"Content-Type": "application/json" means: "I'm sending you JSON".

const response = await fetch(URL, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Accept": "application/json",
  },
  body: bodyAsJson,
});

7) Very important: control HTTP errors with response.ok

fetch does NOT fail just because the server responds with 400/500.
You have to check it yourself. 

if (!response.ok) {
  throw new Error(`HTTP ${response.status} - ${response.statusText}`);
}

Justification (senior):

  • If you don't control response.ok, your app can treat a 400 response as "success".
  • This then translates to UI bugs ("it was created" when it wasn't).

8) Read the JSON from the response (what the server "created")

const createdPost = await response.json();
console.log(createdPost);

9) Complete code (good version for tutorial)

async function createPost() {
  const URL = "https://jsonplaceholder.typicode.com/posts";

  const newPost = {
    userId: 1,
    title: "This is my post title",
    body: "This is my post body",
  };

  const response = await fetch(URL, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Accept": "application/json",
    },
    body: JSON.stringify(newPost),
  });

  if (!response.ok) {
    throw new Error(`HTTP ${response.status} - ${response.statusText}`);
  }

  const createdPost = await response.json();
  return createdPost;
}

// Try it
createPost()
  .then((data) => console.log("Created:", data))
  .catch((err) => console.error("Error:", err.message));

10) What you should see in console (and why id: 101 appears)

You'll see an object like:

  • userId: 1
  • title: ...
  • body: ...
  • id: 101

JSONPlaceholder simulates that it creates it and returns a "new" id.

11) Important note: JSONPlaceholder does NOT save changes (fake API)

Even though it returns id: 101, if you then do GET /posts you'll still see up to 100.

It's not your bug: it's the test API that doesn't persist data.

It's a test API:

  • Responds as if it had created it.
  • But doesn't actually write to a database.
  • That's why a subsequent GET doesn't show it.

12) Minimum validation before sending the POST

Validation is not optional if you want quality:

function validatePostInput(post) {
  if (!post.userId) throw new Error("userId is required");
  if (!post.title?.trim()) throw new Error("title is required");
  if (!post.body?.trim()) throw new Error("body is required");
}

And you use it:

validatePostInput(newPost);

Justification:

Better to fail fast on the frontend than send garbage to the backend and wait.

13) Robust version with complete error handling

async function createPostSafe() {
  const URL = "https://jsonplaceholder.typicode.com/posts";

  const newPost = {
    userId: 1,
    title: "Title",
    body: "Body",
  };

  const response = await fetch(URL, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(newPost),
  });

  // 👇 key: control HTTP errors
  if (!response.ok) {
    // try to read error body if it exists
    let errorBody = null;
    try { errorBody = await response.json(); } catch {}
    throw new Error(
      `HTTP Error ${response.status} ${response.statusText} - ${JSON.stringify(errorBody)}`
    );
  }

  return response.json();
}

14) "Real" example of UI usage (typical pattern)

This helps a junior a lot: seeing how it's used with loading states.

async function onSubmit() {
  try {
    setLoading(true);
    setError(null);

    const created = await createPostSafe();
    setResult(created);
  } catch (e) {
    setError(e.message);
  } finally {
    setLoading(false);
  }
}

Justification:

  • Requests have 3 states: loading / success / error.
  • If you don't model these states, the UI becomes inconsistent.

15) Details that elevate the code (senior extras)

a) Timeout (fetch doesn't come with timeout by default)

A request can hang. Use AbortController:

async function fetchWithTimeout(url, options = {}, ms = 8000) {
  const controller = new AbortController();
  const id = setTimeout(() => controller.abort(), ms);

  try {
    const response = await fetch(url, {
      ...options,
      signal: controller.signal
    });
    return response;
  } finally {
    clearTimeout(id);
  }
}

b) Security/privacy

  • Don't log tokens to console
  • Don't send sensitive data in logs

c) Real headers

  • Authorization: Bearer ... (if there's auth)
  • Accept-Language (if i18n)
  • Correct Content-Type

16) Summary of key concepts

  • JSON.stringify() converts JS objects to JSON strings
  • Content-Type indicates the body format
  • response.ok is crucial to detect HTTP errors
  • Early validation prevents unnecessary errors
  • UI states (loading/error/success) improve experience
