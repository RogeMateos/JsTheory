Understanding fetch from Scratch

The fundamental tool for requesting data from the browser

🎯 What is fetch in one sentence

fetch is a function that lets you make HTTP requests

It's the fundamental tool when you want to request data from a URL from the browser.

Although we usually use it to talk to APIs, it actually works for any resource available on the web: static files, images, JSON, HTML, etc.

💡 What is an API?

An API is an Application Programming Interface

An API allows developers to access data or functionalities of a system.

For example:

  • OpenWeather API: gives you weather data
  • Google Maps API: gives you locations and maps
  • JSONPlaceholder: test API with posts, users, comments
  • PokéAPI: data about all Pokémon

1️⃣ First Contact with fetch

The most basic form

Simply pass a URL to fetch and wait for the response:

fetch('https://jsonplaceholder.typicode.com/todos')
  .then((response) => {
    console.log(response.ok)      // true if the request succeeded
    console.log(response.status)  // HTTP code, for example 200
  })

What does fetch return?

fetch immediately returns a special object called a promise.

That means it doesn't block your code: you can continue executing other instructions while the request is resolved.

2️⃣ Why Do We Say fetch is Asynchronous?

fetch works asynchronously

Because it takes time to receive the server's response.

Analogy: Ordering a pizza 🍕

  1. You place an order → you call fetch
  2. The pizzeria gets to work → the server processes
  3. You don't just stand there waiting → your code keeps running
  4. You can watch a show or do homework while you wait → do other things
  5. When the pizza arrives, they notify you → the promise resolves
  6. Then you eat it → you use the data

That "do something while you wait" is exactly asynchronous behavior

fetch tells you later when the data is ready. Your code doesn't block waiting.

☝️ Important note

There's also async/await syntax for working with asynchronous code more readably. We'll see it in depth later.

3️⃣ Reading Different Types of Responses

The Response object exposes several useful methods

Once we receive the response, we can decide what format we want to read it in:

Method What it does When to use
response.json() Interprets body as JSON APIs (most popular)
response.text() Returns as text string HTML, Markdown, text files
response.blob() Returns a Blob Images, binary files
response.arrayBuffer() Byte buffer Advanced cases

4️⃣ Example 1: Consuming a JSON API

Complete code

fetch('https://jsonplaceholder.typicode.com/todos')
  .then((response) => response.json())
  .then((todos) => {
    console.log('We have', todos.length, 'tasks available')
    console.log('First task:', todos[0])
  })
  .catch((error) => {
    console.error('We could not get the data', error)
  })

Step by step

  1. fetch(URL) → makes the request to the API
  2. .then((response) => response.json()) → reads the response as JSON
  3. .then((todos) => { ... }) → we use the data already converted to a JavaScript object
  4. .catch((error) => { ... }) → if the request fails (no connection, etc.), we handle the error

What do we get in the console?

We have 200 tasks available
First task: {
  userId: 1,
  id: 1,
  title: "delectus aut autem",
  completed: false
}

5️⃣ Example 2: Loading Local HTML

Code to load an HTML file

fetch('/legal/terms.html')
  .then((response) => response.text())
  .then((html) => {
    document.querySelector('#legal').innerHTML = html
  })

What happens here?

  1. We request the local HTML file terms.html
  2. We read it as text with response.text()
  3. We insert that HTML into a DOM element

No API involved, just a static resource

fetch works for anything available at a URL, not just APIs.

6️⃣ Example 3: Loading Local JSON Data

If you have a local data.json file

fetch('/repo/content/00-initialize-repo/jobs.json')
  .then((response) => response.json())
  .then((jobs) => {
    console.log('We have', jobs.length, 'job offers available')
    displayJobs(jobs)
  })
  .catch((error) => {
    console.error('We could not get the data', error)
  })

Now we render the data

function displayJobs(jobs) {
  const container = document.querySelector('#jobs-list')

  jobs.forEach((job) => {
    const div = document.createElement('div')
    div.innerHTML = `
      <h3>${job.title}</h3>
      <p>${job.description}</p>
      <p><strong>Salary:</strong> ${job.salary}</p>
    `
    container.appendChild(div)
  })
}

7️⃣ The Complete Structure: .then() and .catch()

Understanding the flow

fetch(URL)
  .then((response) => {
    // Here we receive the HTTP response
    // We decide how to read it: .json(), .text(), etc.
    return response.json()
  })
  .then((data) => {
    // Here we receive the data already processed
    // We do something with it
    console.log(data)
  })
  .catch((error) => {
    // If something fails in any .then(), we end up here
    console.error('Error:', error)
  })

What is .catch()?

It's a safety net. If something fails:

  • No internet connection
  • Server is down
  • URL is incorrect
  • JSON is invalid

The .catch() captures the error and handles it.

8️⃣ Checking if the Request Was Successful

Important: fetch does NOT throw error on non-2xx responses

Even if the server responds with an error (404, 500), fetch considers the promise as resolved. We need to verify manually:

fetch('https://api.example.com/data')
  .then((response) => {
    // Check if the response was successful
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`)
    }
    return response.json()
  })
  .then((data) => {
    console.log('Data received:', data)
  })
  .catch((error) => {
    console.error('Something went wrong:', error)
  })

Useful Response object properties

Property What it is Example
response.ok true if status is between 200-299 true or false
response.status HTTP status code of the response 200, 404, 500, etc.
response.headers HTTP headers of the response content-type, etc.
response.url Final URL (after redirects) Actual response URL

9️⃣ Exercise: Consuming JSONPlaceholder

The challenge

Use fetch to get users from JSONPlaceholder and show them in the console.

// API to consume:
// https://jsonplaceholder.typicode.com/users

// Hint: You'll need to:
// 1. Make fetch call to the URL
// 2. Convert the response to JSON
// 3. Show the received users in console
// 4. Catch possible errors

Solution

fetch('https://jsonplaceholder.typicode.com/users')
  .then((response) => response.json())
  .then((users) => {
    console.log('Users:', users)
    users.forEach((user) => {
      console.log(`${user.id}: ${user.name} (${user.email})`)
    })
  })
  .catch((error) => {
    console.error('Error getting users:', error)
  })

🔟 Async/Await: The Modern Way (Preview)

There's a more modern syntax: async/await

Makes asynchronous code look more synchronous (easier to read):

async function getData() {
  try {
    const response = await fetch('https://jsonplaceholder.typicode.com/todos')
    const data = await response.json()
    console.log(data)
  } catch (error) {
    console.error('Error:', error)
  }
}

getData()

Comparison: .then() vs async/await

With .then():

fetch(url)
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err))

With async/await:

async function getData() {
  const res = await fetch(url)
  const data = await res.json()
  console.log(data)
}

Both are equivalent, but async/await is more readable.

☝️ We'll learn it in depth later

For now, understand that .then() and async/await are two different ways of doing the same thing.

1️⃣1️⃣ Common Use Cases

1. Get a list of products from an API

fetch('/api/products')
  .then(res => res.json())
  .then(products => renderProducts(products))

2. Load configuration from a JSON file

fetch('/config.json')
  .then(res => res.json())
  .then(config => initApp(config))

3. Load an HTML fragment (header, footer)

fetch('/components/header.html')
  .then(res => res.text())
  .then(html => document.querySelector('header').innerHTML = html)

4. Download an image as a Blob

fetch('/images/photo.jpg')
  .then(res => res.blob())
  .then(blob => {
    const img = document.createElement('img')
    img.src = URL.createObjectURL(blob)
    document.body.appendChild(img)
  })

1️⃣2️⃣ Key Concepts to Remember

1. fetch is asynchronous

It doesn't block your code. You can do other things while waiting for the response.

2. fetch returns a promise

We use .then() to handle the result.

3. You have to read the response

You can do it with .json(), .text(), .blob(), etc.

4. Always use .catch()

To capture errors on the network, server, etc.

5. Check response.ok

fetch doesn't automatically throw an error if status is 404 or 500. You must check it manually.
