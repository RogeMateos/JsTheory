Synchronous Code

Summary of Key Concepts

This tutorial explains the fundamental difference between synchronous (blocking) code and why asynchronous programming is needed.

Topics covered

  • Behavior of synchronous code
  • Blocking problem with slow operations
  • Need for asynchronous programming

Code example

// Basic synchronous code
console.log("start");
console.log("end");

// Blocking synchronous code
console.log("start");
for (let i = 0; i < 1000000000; i++) {
  // Time-consuming operation
}
console.log("end");

Purpose: Demonstrate how slow operations completely block program execution.

Complex concepts simplified

Real-world analogy: Imagine you're cooking. In synchronous mode it would be like:

  1. Put water to boil
  2. Stand watching the pot until it boils (doing nothing else)
  3. Only then start chopping vegetables

This is inefficient because you could chop vegetables while the water boils.

Best practices mentioned

  • Any operation that takes longer than a second should be considered for asynchronous handling
  • Database queries and API calls are prime candidates for asynchronous operations
  • Synchronous blocking degrades the user experience

Suggested exercises

  1. Blocking simulator: Create a loop that counts to 100,000,000 and measure time with console.time() and console.timeEnd()
  2. Case identification: List 3 operations in a web app that would benefit from being asynchronous (e.g., image loading, form submission, etc.)

Connection to the broader context

  • React: Understand why useEffect and API calls should be asynchronous
  • User experience: Avoid freezing the UI
  • Styled-components: Load dynamic styles without blocking render
