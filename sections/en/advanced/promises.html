Asynchronous, Callbacks, Promises, Async

Asynchronous Nature of JavaScript

JavaScript is single-threaded and executes code synchronously by default. However, it can handle asynchronous operations through the browser's Web APIs and the event loop, especially when dealing with input/output operations such as reading/writing files, database access, and making HTTP requests (AJAX).

This asynchronous behavior allows JavaScript to perform other tasks while waiting for these potentially time-consuming operations to complete.

🍕 Restaurant Analogy

Synchronous: The waiter takes your order, goes to the kitchen, waits for your food to be prepared, brings it back, then takes the next customer's order. Everyone waits in line!

Asynchronous: The waiter takes your order, gives it to the kitchen, immediately takes other customers' orders, and brings food out as it becomes ready. Much more efficient!

Callbacks

Callbacks are the most traditional way of handling asynchronous operations in JavaScript. A callback is a function passed as an argument to another function, which is then invoked once the asynchronous operation completes. 


function fetchUserData(userId, callback) {
    // Simulate API call delay
    setTimeout(() => {
        if (userId > 0) {
            const userData = { 
                id: userId, 
                name: 'John Doe', 
                email: 'john@example.com' 
            };
            callback(null, userData); // Success: no error, return data
        } else {
            callback(new Error('Invalid user ID'), null); // Error case
        }
    }, 1000);
}

// Using the callback
fetchUserData(123, (error, user) => {
    if (error) {
        console.error('Failed to fetch user:', error.message);
    } else {
        console.log('User data:', user);
    }
});

console.log('This runs immediately!'); // Doesn't wait for the callback

Problems with Callbacks

  • Callback Hell: Nested callbacks become hard to read and maintain
  • Error Handling: Must remember to handle errors in every callback
  • Inversion of Control: You give up control to the callback function 

// Callback Hell Example
fetchUser(userId, (userError, user) => {
    if (userError) return handleError(userError);
    
    fetchUserPosts(user.id, (postsError, posts) => {

            if (commentsError) return handleError(commentsError);

    });
});

Promises

A Promise in JavaScript represents an eventual completion (or failure) of an asynchronous operation and its resulting value. It allows you to handle asynchronous tasks in a more manageable way than callbacks.

States of a Promise:

Pending: Initial state, neither fulfilled nor rejected.
Fulfilled: The operation completed successfully.
Rejected: The operation failed.

You can attach handlers to a Promise to perform actions when the promise is fulfilled or rejected, using .then() and .catch().

🎁 Promise Analogy

A Promise is like ordering something online:

Pending: "Your order is being processed" - you're waiting

Fulfilled: "Your package has arrived!" - you got what you wanted

Rejected: "Sorry, this item is out of stock" - something went wrong

While waiting for your package, you can still do other things like homework or play games! 


// Creating a Promise
const myPromise = new Promise((resolve, reject) => {
    const success = true;

    if (success) {
        resolve("Promise was successful!");
    } else {
        reject("Promise failed.");
    }
});

// Using the Promise
myPromise
    .then(result => {
        console.log(result); // Output: Promise was successful!
    })
    .catch(error => {
        console.log(error); // If rejected, output: Promise failed.
    });

Chaining Promises:

Promises can be chained to handle multiple asynchronous operations sequentially. 


fetch('https://api.example.com/data')
    .then(response => response.json())
    .then(data => {
        console.log(data);
        return data;
    })
    .catch(error => {
        console.error('Error:', error);
    });

Another example Promises


function addToArray(data, array) {
    return new Promise((resolve, reject) => {
        if (!array) {
            reject(new Error("Array does not exist"));
            return;
        }
        
        setTimeout(() => {
            array.push(data);
            resolve(array);
        }, 1000);
    });
}

const myArray = [1, 2, 3];

addToArray(4, myArray)
    .then(result => console.log("Updated array:", result))
    .catch(error => console.error("Error:", error.message));

Async Await

Async/Await is a way to write asynchronous code in JavaScript that looks and behaves more like synchronous code. It's built on top of Promises and provides a cleaner, more readable syntax for working with asynchronous operations.

async keyword:

  • You put this keyword before a function declaration to make it an "async function".
  • An async function always returns a Promise, even if you don't explicitly return one.

await keyword:

  • You can only use await inside an async function.
  • It tells JavaScript to wait for a Promise to resolve before moving to the next line of code.
  • It "pauses" the function execution until the Promise settles, without blocking the main thread. 

async function processData(data, array) {
    try {
        const result = await addToArray(data, array);
        console.log("Updated array:", result);
    } catch (error) {
        console.error("Error:", error.message);
    }
}

const myArray = [1, 2, 3];

processData(4, myArray);

// The addToArray function remains the same as in the Promise example

React Hook with Async/Await


const useUserData = (userId) => {
    const [state, setState] = useState({
        user: null,
        loading: false,
        error: null
    });

    useEffect(() => {
        // Can't make useEffect callback async directly
        const loadData = async () => {
            setState(prev => ({ ...prev, loading: true, error: null }));
            
            try {
                const userData = await fetchUserData(userId);
                setState(prev => ({ 
                    ...prev, 
                    user: userData, 
                    loading: false 
                }));
            } catch (err) {
                setState(prev => ({ 
                    ...prev, 
                    error: err.message, 
                    loading: false 
                }));
            }
        };

        if (userId) {
            loadData();
        }
    }, [userId]);

    return state;
};

// Using the custom hook
const UserProfile = ({ userId }) => {
    const { user, loading, error } = useUserData(userId);

    if (loading) return 
Loading...
;
    if (error) return 
Error: {error}
;
    return user ? 
Welcome, {user.name}!
 : null;
};

Parallel Execution with Promise.all


// Sequential (slower) - waits for each one
async function loadDataSequential(userId) {
    const user = await fetchUser(userId);        // Wait 1 second
    const posts = await fetchUserPosts(userId);  // Wait another 1 second
    const friends = await fetchUserFriends(userId); // Wait another 1 second
    // Total: ~3 seconds
    return { user, posts, friends };
}

// Parallel (faster) - starts all at once
async function loadDataParallel(userId) {
    const [user, posts, friends] = await Promise.all([
        fetchUser(userId),
        fetchUserPosts(userId),
        fetchUserFriends(userId)
    ]);
    // Total: ~1 second (whatever the slowest request takes)
    return { user, posts, friends };
}
