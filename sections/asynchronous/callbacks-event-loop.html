Asynchrony in JavaScript - Callbacks and Event Loop

1. Main Concepts

Callbacks

  • Definition: A function that is passed as an argument to another function and executes when an operation has finished.
  • Purpose: They were the first mechanism to handle asynchronous operations in JavaScript.

setTimeout

  • Native JavaScript callback to execute code asynchronously.
  • Executes a function after a specified time (in milliseconds).

Event Loop

  • Mechanism that manages asynchronous execution in JavaScript (which operates on a single thread).
  • Key components:
    • Call Stack: Executes synchronous code line by line
    • Web APIs/Node.js APIs: Handle asynchronous operations
    • Task Queue/Microtask Queue: Store asynchronous functions waiting to be executed

2. Code Examples Explained

Basic setTimeout Example

console.log("start");

setTimeout(() => {
  console.log("this executes after 2 seconds");
}, 2000);

console.log("end");

// Output:
// start
// end
// this executes after 2 seconds

Why this order?

  1. Synchronous code executes first: "start" and "end"
  2. The setTimeout is delegated to the Web APIs
  3. When the Call Stack is empty, the callback executes: "this executes..."

Callback Hell

function step1(callback) {
  setTimeout(() => {
    console.log("step 1 completed");
    callback();
  }, 1000);
}

function step2(callback) {
  setTimeout(() => {
    console.log("step 2 completed");
    callback();
  }, 1000);
}

function step3(callback) {
  setTimeout(() => {
    console.log("step 3 completed");
    callback();
  }, 1000);
}

// Nested calls (Callback Hell):
step1(() => {
  step2(() => {
    step3(() => {
      console.log("all steps completed");
    });
  });
});

Problem: Code becomes difficult to read and maintain when you have multiple dependent asynchronous operations.

3. Complex Concepts Simplified

Event Loop Analogy

Imagine a restaurant:

  • Call Stack = The chef cooking (can only cook one dish at a time)
  • Web APIs = The oven/microwave (cook things in the background)
  • Task Queue = Ready dishes waiting to be served
  • Event Loop = The waiter who constantly checks if the chef finished to bring the next dish

The chef (Call Stack) cooks everything they can immediately. If something needs time (like baking), they put it in the oven (Web APIs). When the chef finishes everything immediate, the waiter (Event Loop) brings them the dishes that are ready from the oven (Task Queue).

Event Loop Flow

  1. ✅ Execute synchronous code from the Call Stack
  2. ⏳ Delegate asynchronous operations to Web APIs
  3. 📥 When they finish, they go to the Task Queue
  4. 🔄 If Call Stack is empty, move tasks from the Queue to the Stack
  5. 🔁 Repeat infinitely

4. Best Practices and Common Errors

✅ Best Practices

  • Use callbacks for simple asynchronous operations
  • For multiple dependent operations, consider Promises or async/await (more advanced topics)
  • Always handle errors in callbacks

❌ Common Errors

  • Callback Hell: Nesting too many callbacks makes code unreadable
  • Assuming asynchronous code executes in the order it's written
  • Not understanding that JavaScript is single-threaded

  // Then call the callback
}

}

  // Display "🔴 Red - Stop" after 1 second
}

// Chain the lights: Green → Yellow → Red

Exercise 2: Execution Order

Predict the order of the console.log statements:

console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");

setTimeout(() => {
  console.log("D");
}, 100);

console.log("E");

// What will be the order? Why?
Answer

Order: A, C, E, B, D

Explanation:

  • A, C, E execute immediately (synchronous)
  • Both setTimeouts go to Web APIs
  • B (0ms timeout) completes first and goes to Task Queue
  • D (100ms timeout) completes later
  • Once Call Stack is empty, B executes, then D

6. Connection with Other Topics

This topic connects with:

  • Promises: The natural evolution of callbacks to avoid "callback hell"
  • Async/Await: Modern syntax that makes asynchronous code look synchronous
  • Fetch API: For making HTTP requests asynchronously
  • Event Handlers: Click events, input changes, etc., use the same Event Loop
  • Node.js: The Event Loop is fundamental to understanding how Node.js handles multiple connections

Ultra-Concise Summary

JavaScript is single-threaded but can do asynchronous things thanks to the Event Loop:

  • Callbacks were the first method to handle asynchrony
  • The Event Loop coordinates what code to execute and when
  • setTimeout allows executing code after a time period
  • Nested callbacks create "callback hell" (code difficult to maintain)
  • Modern solution: Promises and async/await (next topic to learn)
