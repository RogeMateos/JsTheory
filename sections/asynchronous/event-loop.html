The Event Loop: Step-by-Step Process

What is the Event Loop?

The Event Loop is the process that JavaScript uses to manage asynchronous programming. It's an infinite continuous loop that constantly checks how code should be executed.

This process operates fundamentally on a single execution thread and follows a constant flow (order) to handle asynchrony.

Main Components

The Event Loop works with three principal components:

  • Call Stack: Where synchronous code is executed
  • Web APIs / Node.js: Systems that handle asynchronous operations
  • Task Queue / Microtask Queue: Queues that store callbacks waiting to be executed

Step-by-Step Flow of the Event Loop

1. Execute the Call Stack

The Event Loop begins by executing code in the Call Stack (execution stack). The Call Stack is where functions and synchronous code execute in order.

2. Encounter Asynchronous Operations

If during Call Stack execution any asynchronous operation is encountered (such as server requests, timers, DOM events, or fetch/setTimeout), its management is delegated.

3. Delegation to Asynchronous Systems

The asynchronous operation is delegated to the asynchronous management system, which can be Web APIs (if running in a browser) or Node.js. This system manages these tasks.

4. Operation Completion

When the asynchronous operation finishes...

5. Queuing (Move to Task Queue)

Once the operation finishes, it's placed in the Task Queue (task queue) or the Microtask Queue (microtask queue). These queues store functions that should execute when the Call Stack is empty.

6. Check the Call Stack

The Event Loop continuously checks if the Call Stack is empty (i.e., if it has finished executing the pending synchronous code).

7. Move Tasks

If the Call Stack is empty:

  • The Event Loop will move tasks from the Microtask Queue to the Call Stack
  • Then, it will move tasks from the Task Queue to the Call Stack
  • Note: This movement (from Microtask/Task Queue to Call Stack) is done so the code can be executed

8. Repeat the Process

Since it's a "loop", the process repeats continuously, returning to step 1 to execute the tasks that have just been moved to the Call Stack.

Code Example

console.log('Start'); // 1. Call Stack - executes immediately

setTimeout(() => {
  console.log('Timeout'); // 4. Task Queue → Call Stack (last)
}, 0);

Promise.resolve().then(() => {
  console.log('Promise'); // 3. Microtask Queue → Call Stack
});

console.log('End'); // 2. Call Stack - executes immediately

// Output order:
// Start
// End
// Promise
// Timeout

Why This Order?

  1. console.log('Start') - Synchronous, executes immediately
  2. setTimeout - Delegated to Web APIs, callback goes to Task Queue
  3. Promise.resolve().then() - Delegated, callback goes to Microtask Queue
  4. console.log('End') - Synchronous, executes immediately
  5. Call Stack is empty → Event Loop checks queues
  6. Microtask Queue has priority → 'Promise' executes
  7. Then Task Queue → 'Timeout' executes

Key Takeaways

  • The Event Loop is an infinite loop that manages code execution
  • Synchronous code executes immediately in the Call Stack
  • Asynchronous operations are delegated to Web APIs/Node.js
  • Callbacks are queued in Task Queue or Microtask Queue
  • Microtask Queue has priority over Task Queue
  • The Event Loop only moves tasks when Call Stack is empty

Understanding This Flow is Fundamental

Understanding this flow is essential to comprehend how JavaScript executes asynchrony. It explains why certain code runs in a specific order and helps you write more efficient and predictable asynchronous code.
