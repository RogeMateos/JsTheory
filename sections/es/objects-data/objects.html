Objetos y valores primitivos

Objetos en JavaScript

Un objeto almacena colecciones de datos y puede tener propiedades y métodos.

  • Son mutables
  • Se almacenan/copían por referencia
  • Pueden agrupar múltiples valores
  • Pueden tener métodos

      let person = {
        name: "Alice",
        age: 30,
        greet: function() {
          console.log("Hello, I'm " + this.name);
        }
      };
      
      person.greet(); // Output: Hello, I'm Alice

Valores primitivos

Son los tipos más simples:

  • String
  • Number
  • Boolean
  • Undefined
  • Null
  • Symbol
  • BigInt

Key characteristics of primitives:

  • Inmutables
  • Se copian por valor
  • Representan un único valor

      let str = "Hello";
      let num = 42;
      let bool = true;
      let undef = undefined;
      let n = null;
      let sym = Symbol("unique");
      let bigInt = 1234567890123456789012345678901234567890n;

Diferencias principales

  1. Complejidad: primitivos son simples; objetos pueden ser complejos.
  2. Mutabilidad: primitivos inmutables; objetos mutables.
  3. Copiado: primitivos por valor; objetos por referencia.
  4. Comparación: primitivos por valor; objetos por referencia.
  5. Métodos: primitivos no tienen (JS los envuelve temporalmente); objetos sí.

      // Primitives
      let a = 5;
      let b = a;
      b = 10;
      console.log(a); // 5
      console.log(b); // 10

      // Objects
      let obj1 = {x: 5};
      let obj2 = obj1;
      obj2.x = 10;
      console.log(obj1.x); // 10
      console.log(obj2.x); // 10

Funciones Constructoras y prototype (Era Pre-ES6)

🏭 La Metáfora: Persona es una fábrica

Métodos estáticos: son herramientas de la fábrica

  • Se usan así: Persona.crearDesdeJSON(...)
  • No dependen de una persona concreta

Métodos de instancia: son habilidades que tienen todas las personas fabricadas

  • Se usan así: bruce.saludar()
  • Dependen de this (del objeto concreto)

A) Constructor (propiedades por instancia)


function Persona(nombre, edad) {
  this.nombre = nombre;
  this.edad = edad;
}

B) Método de instancia (compartido) → va en prototype


Persona.prototype.saludar = function () {
  return `Hola, soy ${this.nombre}`;
};

✅ Por qué en prototype

Persona.prototype.saludar → lo encuentran las instancias por la cadena de prototipos

Todas las instancias comparten la misma función (ahorro de memoria)

C) Método estático → va en la función Persona


Persona.crearAnonimo = function () {
  return new Persona("Anónimo", 0);
};

✅ Método estático

Persona.crearAnonimo → es de la "fábrica", no de los "productos"

D) Uso


const bruce = new Persona("Bruce", 30);

console.log(bruce.saludar());        // ✅ "Hola, soy Bruce" (método de instancia)
console.log(Persona.crearAnonimo()); // ✅ Persona { nombre: 'Anónimo', edad: 0 }

console.log(bruce.crearAnonimo);     // ❌ undefined (no es de instancia)
console.log(Persona.saludar);        // ❌ undefined (saludar no es estático)

⚠️ Error típico: "puse el método y no aparece"

Si haces esto:


Persona.saludar = function () { ... }  // ❌ Estático (error común)

Entonces:


bruce.saludar() // ❌ TypeError: bruce.saludar is not a function

Solución: Debe ir en Persona.prototype.saludar

Regla simple

  • Persona.algo = estático
  • Persona.prototype.algo = instancia

E) prototype vs __proto__ (entender la conexión)


const bruce = new Persona("Bruce", 30);

// Verificación:
console.log(Object.getPrototypeOf(bruce) === Persona.prototype);
// true

📌 Mini-diagrama

  • Persona.prototype → el objeto que será el "padre" (prototipo) de las instancias creadas con new Persona()
  • Object.getPrototypeOf(bruce) → apunta a Persona.prototype

⚠️ Evita __proto__

__proto__ se considera legado/compat

Usa en su lugar:

  • Object.getPrototypeOf(obj) para obtener el prototipo
  • Object.setPrototypeOf(obj, proto) para establecerlo (con cuidado, es lento)

F) Por qué poner métodos en prototype (performance/memoria)

❌ Definir dentro del constructor:

function Persona(nombre) {
  this.nombre = nombre;
  this.saludar = function () {
    return `Hola, soy ${this.nombre}`;
  };
}

const a = new Persona("A");
const b = new Persona("B");

console.log(a.saludar === b.saludar); // false
// 👉 Cada instancia crea una copia nueva de saludar (más memoria)
✅ Definir en prototype:

function Persona(nombre) {
  this.nombre = nombre;
}

Persona.prototype.saludar = function () {
  return `Hola, soy ${this.nombre}`;
};

const a = new Persona("A");
const b = new Persona("B");

console.log(a.saludar === b.saludar); // true
// 👉 Todas las instancias comparten la misma función

💡 Este true es el "click" para muchos juniors

Prueba que ambos objetos usan la misma función en memoria.

G) Versión moderna (class) y equivalencias


class Persona {
  constructor(nombre, edad) {
    this.nombre = nombre;
    this.edad = edad;
  }

  saludar() { // ✅ método de instancia (vive en Persona.prototype)
    return `Hola, soy ${this.nombre}`;
  }

  static crearAnonimo() { // ✅ método estático (vive en Persona)
    return new Persona("Anónimo", 0);
  }
}

const bruce = new Persona("Bruce", 30);
console.log(bruce.saludar());        // "Hola, soy Bruce"
console.log(Persona.crearAnonimo()); // Persona { nombre: 'Anónimo', edad: 0 }

📌 Equivalencias reales

  • saludar() en class → va al prototype
  • static crearAnonimo() → va al constructor/clase

class es azúcar sintáctico sobre el mismo sistema de prototipos

⚠️ Importante: NO está deprecado

Funciones constructoras y prototype NO están deprecados

  • Hoy se prefiere class por legibilidad y estándar
  • Pero prototype sigue siendo el motor real por debajo
  • En proyectos legacy verás funciones constructoras constantemente

H) Ejercicios prácticos

1️⃣ Crea Persona.desdeObjeto({nombre, edad}) como método estático


// Tu código aquí
Persona.desdeObjeto = function(obj) {
  return new Persona(obj.nombre, obj.edad);
};

// Prueba:
const p = Persona.desdeObjeto({nombre: "Ana", edad: 25});
console.log(p.saludar()); // "Hola, soy Ana"

2️⃣ Añade esMayorDeEdad() como método de instancia


// Tu código aquí
Persona.prototype.esMayorDeEdad = function() {
  return this.edad >= 18;
};

// Prueba:
const menor = new Persona("Luis", 15);
const mayor = new Persona("Ana", 25);
console.log(menor.esMayorDeEdad()); // false
console.log(mayor.esMayorDeEdad()); // true

3️⃣ Demuestra que el método de instancia es compartido


const a = new Persona("A", 20);
const b = new Persona("B", 30);

console.log(a.saludar === b.saludar); // true (si está en prototype)
console.log(a.esMayorDeEdad === b.esMayorDeEdad); // true

I) Checklist mental (3 reglas de oro)

  • ✅ Propiedades únicas por instancia → dentro del constructor
  • ✅ Métodos compartidos → en prototype
  • ✅ Métodos/propiedades de la "fábrica" → estáticos (en la función/clase)

Clases en JavaScript (ES6+)

Paso 1 — El Problema Real

Imagina que necesitas crear múltiples personas con las mismas propiedades y métodos:


// ❌ Con objetos literales, repites lógica
const p1 = {
  name: "Bryce",
  age: 37,
  greet() {
    return `Hola, soy ${this.name}`;
  }
};

const p2 = {
  name: "Ana",
  age: 22,
  greet() {
    return `Hola, soy ${this.name}`;
  }
};

// Problema: estás duplicando el método greet

El dolor del objeto literal

  • Sirve para un objeto
  • Si necesitas muchas personas con mismas propiedades y métodos, repites lógica
  • Difícil de mantener cuando cambias el comportamiento

Paso 2 — Solución Antigua: Función Constructora + prototype

Aquí es de dónde venimos y por qué existe prototype:


function Person(name, age) {
  this.name = name;
  this.age = age;
}

Person.prototype.greet = function () {
  return `Hola, soy ${this.name}`;
};

const person = new Person("Bryce", 37);
console.log(person.greet()); // "Hola, soy Bryce"

Punto clave

greet está en Person.prototype, no duplicado por instancia.

Esto ahorra memoria cuando tienes 1000 personas.

Paso 3 — Solución Moderna: class (Misma Idea, Más Legible)

ES6 introdujo la sintaxis class, que es azúcar sintáctico sobre prototipos:


class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    return `Hola, soy ${this.name}`;
  }
}

const person = new Person("Bryce", 37);
console.log(person.greet()); // "Hola, soy Bryce"

✅ Frase importante

Person.prototype.greet existe igualmente.

La sintaxis class es solo una forma más clara de escribir el mismo patrón de prototipos.

Paso 4 — Demostración: class == prototype Debajo

Ejemplo que "abre ojos":


class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    return `Hola, soy ${this.name}`;
  }
}

// Revelando la verdad:
console.log(typeof Person); // "function" ← ¡es una función!
console.log(Person.prototype.hasOwnProperty("greet")); // true

const person = new Person("Bryce", 37);
console.log(Object.getPrototypeOf(person) === Person.prototype); // true

💡 Explicación

"Una clase en JS es una función especial, y sus métodos van al prototype."

No es como Java o C#. JavaScript sigue siendo prototipal.

Paso 5 — Getters/Setters con un Caso Real

No lo menciono "por mencionar". Veamos un caso de negocio: impedir edades negativas.


class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age; // activará el setter
  }

  get age() {
    return this._age;
  }

  set age(value) {
    if (value < 0) {
      throw new Error("Age cannot be negative");
    }
    this._age = value;
  }

  greet() {
    return `Hola, soy ${this.name}`;
  }
}

const person = new Person("Bryce", 37);
console.log(person.age); // 37 (usa el getter)

person.age = 40; // usa el setter
console.log(person.age); // 40

person.age = -5; // Error: Age cannot be negative

✅ Senior tip

  • Usa _age como backing field (convención de "privado")
  • Explica que age "parece propiedad" pero es método
  • Los getters/setters permiten validación sin cambiar la API externa

Paso 6 — Privacidad: Lo Que Sí Funciona Hoy

Hay 2 vías más comunes para campos privados:

1) Campos privados reales (moderno) #

class Person {
  #ssn; // privado real

  constructor(name, age, ssn) {
    this.name = name;
    this.age = age;
    this.#ssn = ssn;
  }

  getSSNMasked() {
    return "****-" + this.#ssn.slice(-4);
  }
}

const person = new Person("Bryce", 37, "123-45-6789");
console.log(person.getSSNMasked()); // "****-6789"
console.log(person.#ssn); // SyntaxError: Private field '#ssn'

✅ Ventajas de #privateField

  • Privacidad real, no convención
  • Error en tiempo de ejecución si intentas acceder desde fuera
  • Soporte en navegadores modernos (2022+)
2) Convención _underscore (semi-privado)

class Person {
  constructor(name, age) {
    this.name = name;
    this._age = age; // convención: "no toques esto"
  }

  get age() {
    return this._age;
  }
}

const person = new Person("Bryce", 37);
console.log(person._age); // 37 (accesible, pero "no deberías")

⚠️ Importante

El _underscore es solo convención, NO es privado de verdad.

Cualquiera puede acceder a person._age.

Diferencia Clave: Método en Clase vs Función en Constructor

Muchos juniors cometen este error:

❌ Esto duplica función por instancia (MAL)

class Person {
  constructor(name) {
    this.name = name;
    this.greet = () => `Hola ${this.name}`; // ❌ copia por instancia
  }
}

const a = new Person("A");
const b = new Person("B");

console.log(a.greet === b.greet); // false ← cada instancia tiene su copia
✅ Esto comparte método (BIEN)

class Person {
  constructor(name) {
    this.name = name;
  }

  greet() {
    return `Hola ${this.name}`; // ✅ en prototype, compartido
  }
}

const a = new Person("A");
const b = new Person("B");

console.log(a.greet === b.greet); // true ← ambos usan la misma función

💡 Por qué importa (memoria/performance)

Si creas 1000 instancias:

  • ❌ Versión mala: 1000 copias de greet en memoria
  • ✅ Versión buena: 1 sola copia de greet en Person.prototype

instanceof y Cadena Prototípica

Muy útil para entender instancias:


class Person {
  constructor(name) {
    this.name = name;
  }
}

const person = new Person("Bryce");

console.log(person instanceof Person); // true
console.log(person instanceof Object); // true
console.log(person instanceof Array);  // false

// Verificar la cadena prototípica
console.log(Object.getPrototypeOf(person) === Person.prototype); // true
console.log(Object.getPrototypeOf(Person.prototype) === Object.prototype); // true

Cadena completa

person → Person.prototype → Object.prototype → null

Cuándo NO Usar Clases (JS Moderno Real)

En React/Frontend actual:

✅ Realidad del desarrollo moderno

  • Muchas veces usas funciones puras + objetos
  • Clases existen, pero no modelas todo como "entidad"
  • React Hooks usa funciones, no clases (desde 2019)
  • Programación funcional está más de moda que OOP clásico
Ejemplo: estilo funcional moderno

// En lugar de una clase Person, podrías usar:
const createPerson = (name, age) => ({
  name,
  age,
  greet: () => `Hola, soy ${name}`
});

const person = createPerson("Bryce", 37);
console.log(person.greet()); // "Hola, soy Bryce"

⚠️ Cuándo SÍ usar clases

  • Cuando modelás "entidades" con estado mutable
  • Cuando necesitas herencia (extends)
  • Cuando trabajas con librerías que las usan (algunos frameworks)
  • Cuando el equipo prefiere estilo OOP

Mini Resumen (Estilo Senior)

La verdad sobre clases en JavaScript

  • "Antes creábamos instancias con funciones constructoras y prototipos."
  • "Hoy usamos class, que es más legible, pero sigue usando prototipos por debajo."
  • "constructor inicializa estado con this."
  • "Los métodos en class se guardan en Person.prototype, así que se comparten."
  • "Se puede añadir métodos al prototype después, pero en apps reales intentamos evitarlo."
  • "Getters/setters sirven para validar o controlar acceso como si fuera una propiedad."
  • "Privacidad moderna: #privateField."

Herencia a través de Prototipos (Object.create)

🧬 PASO 1: Qué significa "heredar" en JavaScript

En JavaScript, heredar NO significa copiar propiedades.

Significa apuntarse a otro objeto para reutilizarlo.

⚠️ Esto es clave

No se copian datos, se comparten a través del prototipo.

🧩 PASO 2: Objeto base (persona)


const persona = {
  name: "Bryce",
  age: 37,
  saludar() {
    console.log(`Hola, soy ${this.name}`);
  },
  decirEdad() {
    console.log(`Tengo ${this.age} años`);
  }
};

📌 Hasta aquí:

  • Un objeto normal
  • Propiedades + métodos
  • Nada de herencia aún

🧬 PASO 3: Crear un objeto que hereda (Object.create)


const programador = Object.create(persona);

👉 Importante

Esto NO copia persona

Esto crea un objeto vacío cuyo prototipo es persona

Visualmente:


programador
   ↓ prototype
persona

🔍 PASO 4: ¿Por qué parece "vacío"?


console.log(programador); // {}

⚠️ Esto confunde mucho

El objeto está vacío, pero tiene acceso a las propiedades del prototipo.

Probemos:


programador.saludar();    // Hola, soy Bryce
programador.decirEdad(); // Tengo 37 años

✔️ Funciona

Porque JS busca en la cadena de prototipos

🔗 PASO 5: Cómo funciona la búsqueda (prototype chain)

Cuando haces:


programador.name

JavaScript hace esto:

  1. ¿name existe en programador? ❌
  2. ¿Existe en su prototipo (persona)? ✅
  3. → Se usa ese valor

💡 EL CORAZÓN del sistema de prototipos

Esta búsqueda en cadena es la base de la herencia en JavaScript.

⚠️ PASO 6: El famoso undefined (aquí hay que ser quirúrgico)

Si haces:


console.log(programador.saludar());

Obtienes:


Hola, soy Bryce
undefined

¿Por qué?

  • saludar() hace console.log
  • Pero NO retorna nada
  • Toda función que no retorna → undefined

💡 Importante decirle al junior:

Esto NO es un problema de herencia

Es cómo funcionan las funciones en JavaScript

🧪 PASO 7: Añadir propiedades al hijo


programador.lenguaje = "JavaScript";

Ahora:


console.log(programador.lenguaje); // JavaScript
console.log(persona.lenguaje);     // undefined

👉 Las propiedades nuevas NO suben al prototipo

Cada objeto mantiene sus propiedades propias separadas.

🔄 PASO 8: Qué pasa si modifico el prototipo


persona.name = "MoureDev";
programador.saludar(); // Hola, soy MoureDev

¿Por qué?

  • programador NO tiene name
  • Sigue usando el del prototipo
  • Cambias el prototipo → cambia el resultado

⚠️ Esto es potente pero peligroso

🧠 PASO 9: Pero… ¿esto es herencia "real"?

Reflexión importante

Esto NO es herencia clásica.

Es delegación a través de prototipos.

Por eso:

  • No hay copia
  • Hay dependencia
  • Cambiar el padre afecta a los hijos

🏁 PASO 10: Conclusión moderna (muy importante)

💡 Mensaje clave

  • Antes de ES6, esta era la única forma de "heredar"
  • Hoy usamos class, que por debajo sigue usando prototipos

Entender prototipos te hace mejor desarrollador, aunque uses clases todos los días.

Ejemplo completo


// Base
const persona = {
  name: "Bryce",
  age: 37,
  saludar() {
    return `Hola, soy ${this.name}`;
  }
};

// Herencia
const programador = Object.create(persona);
programador.lenguaje = "JavaScript";

// Funcionamiento
console.log(programador.saludar()); // "Hola, soy Bryce"
console.log(programador.lenguaje);  // "JavaScript"

// Verificar
console.log(programador.hasOwnProperty("lenguaje")); // true
console.log(programador.hasOwnProperty("name"));     // false
console.log(Object.getPrototypeOf(programador) === persona); // true
