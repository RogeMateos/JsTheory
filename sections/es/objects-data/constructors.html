Funciones Constructoras y prototype (Era Pre-ES6)

🏭 La Metáfora: Persona es una fábrica

Entendiendo métodos estáticos vs métodos de instancia

Métodos estáticos: son herramientas de la fábrica

  • Se usan así: Persona.crearDesdeJSON(...)
  • No dependen de una persona concreta

Métodos de instancia: son habilidades que tienen todas las personas fabricadas

  • Se usan así: bruce.saludar()
  • Dependen de this (del objeto concreto)

A) Constructor (propiedades por instancia)


function Persona(nombre, edad) {
  this.nombre = nombre;
  this.edad = edad;
}

B) Método de instancia (compartido) → va en prototype


Persona.prototype.saludar = function () {
  return `Hola, soy ${this.nombre}`;
};

✅ Por qué en prototype

Persona.prototype.saludar → lo encuentran las instancias por la cadena de prototipos

Todas las instancias comparten la misma función (ahorro de memoria)

C) Método estático → va en la función Persona


Persona.crearAnonimo = function () {
  return new Persona("Anónimo", 0);
};

✅ Método estático

Persona.crearAnonimo → es de la "fábrica", no de los "productos"

D) Uso


const bruce = new Persona("Bruce", 30);

console.log(bruce.saludar());        // ✅ "Hola, soy Bruce" (método de instancia)
console.log(Persona.crearAnonimo()); // ✅ Persona { nombre: 'Anónimo', edad: 0 }

console.log(bruce.crearAnonimo);     // ❌ undefined (no es de instancia)
console.log(Persona.saludar);        // ❌ undefined (saludar no es estático)

⚠️ Error típico: "puse el método y no aparece"

Si haces esto:


Persona.saludar = function () { ... }  // ❌ Estático (error común)

Entonces:


bruce.saludar() // ❌ TypeError: bruce.saludar is not a function

Solución: Debe ir en Persona.prototype.saludar

Regla simple

  • Persona.algo = estático
  • Persona.prototype.algo = instancia

E) prototype vs __proto__ (entender la conexión)


const bruce = new Persona("Bruce", 30);

// Verificación:
console.log(Object.getPrototypeOf(bruce) === Persona.prototype);
// true

📌 Mini-diagrama

  • Persona.prototype → el objeto que será el "padre" (prototipo) de las instancias creadas con new Persona()
  • Object.getPrototypeOf(bruce) → apunta a Persona.prototype

⚠️ Evita __proto__

__proto__ se considera legado/compat

Usa en su lugar:

  • Object.getPrototypeOf(obj) para obtener el prototipo
  • Object.setPrototypeOf(obj, proto) para establecerlo (con cuidado, es lento)

F) Por qué poner métodos en prototype (performance/memoria)

❌ Definir dentro del constructor:


function Persona(nombre) {
  this.nombre = nombre;
  this.saludar = function () {
    return `Hola, soy ${this.nombre}`;
  };
}

const a = new Persona("A");
const b = new Persona("B");

console.log(a.saludar === b.saludar); // false
// 👉 Cada instancia crea una copia nueva de saludar (más memoria)

✅ Definir en prototype:


function Persona(nombre) {
  this.nombre = nombre;
}

Persona.prototype.saludar = function () {
  return `Hola, soy ${this.nombre}`;
};

const a = new Persona("A");
const b = new Persona("B");

console.log(a.saludar === b.saludar); // true
// 👉 Todas las instancias comparten la misma función

💡 Este true es el "click" para muchos juniors

Prueba que ambos objetos usan la misma función en memoria.

G) Versión moderna (class) y equivalencias


class Persona {
  constructor(nombre, edad) {
    this.nombre = nombre;
    this.edad = edad;
  }

  saludar() { // ✅ método de instancia (vive en Persona.prototype)
    return `Hola, soy ${this.nombre}`;
  }

  static crearAnonimo() { // ✅ método estático (vive en Persona)
    return new Persona("Anónimo", 0);
  }
}

const bruce = new Persona("Bruce", 30);
console.log(bruce.saludar());        // "Hola, soy Bruce"
console.log(Persona.crearAnonimo()); // Persona { nombre: 'Anónimo', edad: 0 }

📌 Equivalencias reales

  • saludar() en class → va al prototype
  • static crearAnonimo() → va al constructor/clase

class es azúcar sintáctico sobre el mismo sistema de prototipos

⚠️ Importante: NO está deprecado

Funciones constructoras y prototype NO están deprecados

  • Hoy se prefiere class por legibilidad y estándar
  • Pero prototype sigue siendo el motor real por debajo
  • En proyectos legacy verás funciones constructoras constantemente

H) Ejercicios prácticos

1️⃣ Crea Persona.desdeObjeto({nombre, edad}) como método estático


// Tu código aquí
Persona.desdeObjeto = function(obj) {
  return new Persona(obj.nombre, obj.edad);
};

// Prueba:
const p = Persona.desdeObjeto({nombre: "Ana", edad: 25});
console.log(p.saludar()); // "Hola, soy Ana"

2️⃣ Añade esMayorDeEdad() como método de instancia


// Tu código aquí
Persona.prototype.esMayorDeEdad = function() {
  return this.edad >= 18;
};

// Prueba:
const menor = new Persona("Luis", 15);
const mayor = new Persona("Ana", 25);
console.log(menor.esMayorDeEdad()); // false
console.log(mayor.esMayorDeEdad()); // true

3️⃣ Demuestra que el método de instancia es compartido


const a = new Persona("A", 20);
const b = new Persona("B", 30);

console.log(a.saludar === b.saludar); // true (si está en prototype)
console.log(a.esMayorDeEdad === b.esMayorDeEdad); // true

I) Checklist mental (3 reglas de oro)

  • ✅ Propiedades únicas por instancia → dentro del constructor
  • ✅ Métodos compartidos → en prototype
  • ✅ Métodos/propiedades de la "fábrica" → estáticos (en la función/clase)
