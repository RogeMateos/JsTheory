Proxy en JavaScript

0) ¿Qué es un Proxy en JavaScript?

Un Proxy es un objeto especial que se coloca "en medio" entre tu código y un objeto real.

📌 Su objetivo es interceptar operaciones como:

  • leer propiedades (get)
  • escribir propiedades (set)
  • borrar (deleteProperty)
  • comprobar existencia (has)
  • ejecutar funciones (apply)
  • etc.

📌 Piensa en un Proxy como un guardia de seguridad

Cada vez que alguien intenta entrar (leer/editar) el objeto, el guardia revisa si lo permite, lo bloquea o registra algo.

1) Creamos una clase base (BankAccount)


class BankAccount {
  constructor(balance) {
    this.balance = balance;
  }
}

const account = new BankAccount(100);

console.log(account.balance); // 100

Hasta aquí normal: sin control, cualquiera puede leer y modificar:


account.balance = -9999; // nadie lo impide 😬

2) Creamos un "handler" del Proxy

El Proxy necesita un handler, un objeto con funciones especiales.

🧠 Handler básico


const handler = {
  get(target, property) {
    console.log("GET");
  },
  set(target, property, value) {
    console.log("SET");
  }
};

📌 Importante

El handler define qué hacer cuando alguien accede o cambia algo.

3) Envolvemos el objeto real con Proxy

Aquí viene lo importante:


const securedAccount = new Proxy(account, handler);
  • account = el objeto real (target)
  • handler = reglas/interceptores

4) Probamos: interceptar lectura y escritura


console.log(securedAccount.balance);
securedAccount.balance = 50;

📌 Esto imprime:


"GET"
"SET"

Pero... ¿por qué undefined al leer?

Porque en tu get() no estás devolviendo el valor.

5) Solución: devolver el valor en get()

🔑 Regla de oro

Si interceptas un get, normalmente debes devolver el valor.


const handler = {
  get(target, property) {
    console.log("GET", property);
    return target[property]; // 👈 devolvemos valor real
  },

  set(target, property, value) {
    console.log("SET", property, value);
    target[property] = value; // 👈 aplicamos cambio real
    return true;              // 👈 obligatorio en modo estricto
  }
};

const securedAccount = new Proxy(account, handler);

console.log(securedAccount.balance); // GET balance -> 100
securedAccount.balance = 50;         // SET balance 50
console.log(securedAccount.balance); // GET balance -> 50

✅ Ya funciona perfecto

6) El Proxy completo: logs + validación de saldo

Ahora vamos a hacer lo "pro":

✅ Queremos:

  • Log cada vez que se accede a una propiedad
  • No permitir saldo negativo

class BankAccount {
  constructor(balance) {
    this.balance = balance;
  }
}

const handler = {
  get(target, property) {
    console.log(`📌 Accediendo a: ${property}`);
    return target[property];
  },

  set(target, property, value) {
    console.log(`✍️ Modificando: ${property} -> ${value}`);

    if (property === "balance" && value < 0) {
      throw new Error("❌ El saldo no puede ser negativo");
    }

    target[property] = value;
    return true;
  }
};

const account = new BankAccount(100);
const securedAccount = new Proxy(account, handler);

console.log(securedAccount.balance); // 📌 Accediendo a: balance -> 100

securedAccount.balance = 50;         // ✍️ Modificando: balance -> 50
console.log(securedAccount.balance); // -> 50

securedAccount.balance = -10;        // ❌ Error: El saldo no puede ser negativo

🔥 Qué significan los parámetros del Proxy

get(target, property)

  • target: el objeto real
  • property: el nombre de la propiedad que se está leyendo (ej: "balance")

✅ Ejemplo:


securedAccount.balance;

equivale a:


property = "balance"

set(target, property, value)

  • target: el objeto real
  • property: propiedad que se quiere cambiar
  • value: nuevo valor

✅ Ejemplo:


securedAccount.balance = 50;

equivale a:


property = "balance"
value = 50

✅ ¿Cuándo usar Proxy en la vida real?

Muy útil cuando quieres control transversal sin ensuciar la clase.

Ejemplos reales:

🔐 Seguridad
  • bloquear acceso a password
  • evitar modificaciones externas en propiedades sensibles
✅ Validaciones
  • no permitir tipos incorrectos (string en vez de number)
  • no permitir negativos
  • no permitir null
📊 Auditoría / Logging
  • trackear lecturas/escrituras
  • analítica interna
🧊 Inmutabilidad (como Redux-style)
  • impedir que cambien valores

🧠 Best practices (como senior)

✅ 1) NO metas demasiada lógica dentro del proxy

Mejor delegarlo a funciones:


function validateBalance(value) {
  if (value < 0) throw new Error("Saldo negativo");
}

✅ 2) Usa Reflect para mantener comportamiento estándar

Esto es muy pro porque respeta cosas internas:


const handler = {
  get(target, prop) {
    console.log("GET", prop);
    return Reflect.get(target, prop);
  },

  set(target, prop, value) {
    if (prop === "balance" && value < 0) {
      throw new Error("Saldo negativo");
    }
    return Reflect.set(target, prop, value);
  }
};

🧪 Ejercicios para que lo domines

✅ Ejercicio 1

Haz un Proxy que:

  • loguee "Leyendo propiedad X"
  • loguee "Escribiendo propiedad X"

✅ Ejercicio 2

Haz un Proxy para un objeto user que impida:

  • leer password
  • setear email si no incluye @

const handler = {
  get(target, prop) {
    if (prop === "password") {
      throw new Error("No puedes acceder a password");
    }
    return target[prop];
  },

  set(target, prop, value) {
    if (prop === "email" && !value.includes("@")) {
      throw new Error("Email inválido");
    }
    target[prop] = value;
    return true;
  }
};

const user = { email: "test@example.com", password: "secret123" };
const securedUser = new Proxy(user, handler);

✅ Ejercicio 3

Haz un Proxy que no permita borrar propiedades:

Intercepta:


delete obj.name

(usando deleteProperty)


const handler = {
  deleteProperty(target, prop) {
    throw new Error(`No puedes borrar la propiedad ${prop}`);
  }
};

const obj = { name: "Roge" };
const protected = new Proxy(obj, handler);

delete protected.name; // ❌ Error: No puedes borrar la propiedad name

✅ Resumen

Lo que debes recordar

  • Proxy: interceptor entre tu código y un objeto
  • Handler: objeto con traps (get, set, deleteProperty, etc.)
  • get: debe devolver el valor
  • set: debe devolver true
  • Usa Reflect: para mantener comportamiento estándar
  • Casos de uso: validación, seguridad, logging, inmutabilidad

Checklist de Errores Comunes

⚠️ Errores típicos a evitar

  • ❌ No devolver valor en get
  • ❌ No devolver true en set
  • ❌ Meter demasiada lógica en el handler
  • ❌ No usar Reflect para operaciones complejas
