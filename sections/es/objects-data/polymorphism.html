Polimorfismo en JavaScript

0) Objetivo del Capítulo

Cuando termines este tema vas a poder:

  • Entender qué es polimorfismo de verdad (sin humo)
  • Implementarlo con clases y herencia
  • Ver el caso más importante: polimorfismo real = tratar objetos diferentes igual, sin if/switch
  • Entender cómo se aplica en JavaScript también con duck typing

1) ¿Qué es Polimorfismo?

Definición simple y útil

Polimorfismo = mismo método, distintos comportamientos.

👉 Ejemplo mental:

Todos los animales pueden hacer makeSound()

Pero cada uno lo hace diferente:

  • gato → "miau"
  • perro → "guau"
  • vaca → "muu"

Lo importante (visión senior)

Polimorfismo no es "hacer clases por hacer".

Es esto:

✅ Poder escribir código genérico que funcione con muchos tipos distintos, sin preguntar el tipo.

2) El Problema Típico (sin polimorfismo)

Un junior suele hacer esto:


function makeSound(animal) {
  if (animal.type === "cat") return "Miau";
  if (animal.type === "dog") return "Guau";
  return "???";
}

¿Qué está mal aquí?

Cada vez que agregas un animal nuevo (Cow, Bird...) tienes que volver a tocar esta función.

Eso rompe un principio clave:

Abierto para extensión, cerrado para modificación (Open/Closed Principle).

3) Solución con Polimorfismo (con clases)

Paso 1: Crear una clase base (simulando "abstracta")

⚠️ IMPORTANTE

En JavaScript no existen abstract classes reales, así que las simulamos.

Objetivo:

  • No permitir new Animal()
  • Obligamos a que makeSound() sea implementado por los hijos

class Animal {
  constructor(name) {
    // 🔒 Bloqueo para evitar instanciar Animal directamente
    if (new.target === Animal) {
      throw new Error("Animal es abstracta y no se puede instanciar");
    }

    this.name = name;
  }

  makeSound() {
    // Forzamos que el hijo lo implemente
    throw new Error("makeSound() debe ser implementado en la subclase");
  }
}

📌 new.target es clave aquí:

  • Si intentas instanciar Animal, lanza error
  • Si instancias una subclase como Cat, no falla

Paso 2: Crear subclases (Cat y Dog)


class Cat extends Animal {
  makeSound() {
    return "Miau 🐱";
  }
}

class Dog extends Animal {
  makeSound() {
    return "Guau 🐶";
  }
}

✅ Aquí está el polimorfismo:

  • mismo método (makeSound)
  • comportamientos diferentes (cada clase decide)

Paso 3: Crear instancias


const cat = new Cat("MoureCat");
const dog = new Dog("MoureDog");

console.log(cat.name, cat.makeSound());
console.log(dog.name, dog.makeSound());

Salida:


MoureCat Miau 🐱
MoureDog Guau 🐶

4) Aquí llega el polimorfismo REAL (lo importante)

Este es el ejemplo que debes entender sí o sí:


const animals = [
  new Cat("Luna"),
  new Dog("Rocky"),
  new Cat("Mimi"),
];

for (const animal of animals) {
  console.log(animal.name, "dice", animal.makeSound());
}

¿Qué tiene de especial?

  • Tu bucle NO SABE si es gato o perro
  • No hay if, no hay switch
  • Solo llama al mismo método

💡 Eso es polimorfismo:

el código "trata objetos diferentes de forma uniforme".

5) ¿Qué pasa si NO implemento el método?

Ejemplo:


class Bird extends Animal {}

Ahora:


const bird = new Bird("Pajaro");
console.log(bird.makeSound());

✅ ¿Qué debe ocurrir?

Lanza error:


makeSound() debe ser implementado en la subclase

📌 Esto es exactamente lo que quieres:

obligar a implementar el contrato

6) Polimorfismo en JavaScript de verdad (Duck Typing)

Esto es MUY importante

👉 En JavaScript muchas veces no te interesa herencia.

Te interesa el contrato.

Ejemplo:


function playSound(entity) {
  if (typeof entity.makeSound !== "function") {
    throw new Error("Este objeto no implementa makeSound()");
  }

  console.log(entity.makeSound());
}

Uso:


playSound(new Cat("A"));
playSound({
  makeSound() {
    return "Bip Bip 🤖";
  }
});

✅ Este objeto no extiende Animal, pero funciona

Mensaje senior:

En JavaScript, polimorfismo es "si tiene el método, me vale".

7) Bonus Senior: Una Mejora Profesional

Si quieres evitar el if en playSound(), puedes usar guard clause o fallar rápido con un error claro.

Y si quieres más elegante, puedes decir:


const makeSoundable = (obj) => typeof obj?.makeSound === "function";

function playSound(entity) {
  if (!makeSoundable(entity)) {
    throw new Error("Este objeto no implementa makeSound()");
  }
  console.log(entity.makeSound());
}

8) Cuándo usar polimorfismo (casos reales en Front-End)

✅ Casos donde sí merece la pena:

A) Renderizado de componentes por tipo

Ejemplo:

  • cada tipo de bloque tiene un método render()
  • tu sistema no pregunta tipo → solo ejecuta .render()
B) Validadores

Muchos validadores con la misma interfaz:

  • validate()
  • formatError()
C) Estrategias

Distintas formas de calcular precio:

  • calculate()
  • cada clase implementa su estrategia

9) Ejercicios para Reforzar

Ejercicio 1 (básico)

Crea Cow que herede de Animal y haga:


class Cow extends Animal {
  makeSound() {
    return "Muu 🐮";
  }
}

const cow = new Cow("Lola");
console.log(cow.makeSound()); // "Muu 🐮"

Ejercicio 2 (nivel entrevista)

Crea una función:


function playAllSounds(animals) {
  for (const animal of animals) {
    console.log(animal.name, "dice", animal.makeSound());
  }
}

// Uso:
const zoo = [
  new Cat("Luna"),
  new Dog("Rocky"),
  new Cow("Lola")
];

playAllSounds(zoo);

Ejercicio 3 (pro)

Crea un sistema de pagos polimórfico:


// PaymentMethod abstracto (simulado)
class PaymentMethod {
  constructor() {
    if (new.target === PaymentMethod) {
      throw new Error("PaymentMethod es abstracta");
    }
  }

  pay(amount) {
    throw new Error("pay() debe ser implementado");
  }
}

class CardPayment extends PaymentMethod {
  pay(amount) {
    return `Pagado ${amount}€ con tarjeta 💳`;
  }
}

class PaypalPayment extends PaymentMethod {
  pay(amount) {
    return `Pagado ${amount}€ con PayPal 🅿️`;
  }
}

class CryptoPayment extends PaymentMethod {
  pay(amount) {
    return `Pagado ${amount}€ con cripto ₿`;
  }
}

// Tu loop solo hace:
const methods = [
  new CardPayment(),
  new PaypalPayment(),
  new CryptoPayment()
];

methods.forEach((m) => console.log(m.pay(100)));

✅ Resumen del Capítulo

Lo que debes recordar

  • Polimorfismo = mismo método, comportamientos distintos
  • Se usa para evitar if/switch por tipo
  • En JS se puede hacer con:
    • Herencia + override
    • Duck typing (si tiene el método, sirve)
  • Beneficio real:
    • código más mantenible
    • más extensible (añadir nuevas clases sin tocar lógica central)

Checklist de Errores Comunes

⚠️ Errores típicos a evitar

  • ❌ Usar if (tipo === ...) en lugar de polimorfismo
  • ❌ No implementar métodos abstractos en las subclases
  • ❌ Crear clases cuando una función simple bastaría
  • ❌ Olvidar validar que el objeto tiene el método (duck typing)
