Symbol en clases JavaScript (pseudo-privado, colisiones y alternativa moderna con #private)

0) En este tutorial vas a aprender:

  • Qué es Symbol y por qué existe
  • Cómo usar Symbol dentro de una clase
  • Por qué "parece privado" pero no es privacidad real
  • Cómo proteger un valor con Object.defineProperty
  • Qué usar hoy en día: #private (ES2020+)

1) ¿Qué es un Symbol?

Symbol es un tipo de dato primitivo introducido en ES2015 (ES6).

Su objetivo principal es permitir crear identificadores únicos, sobre todo para usarlos como claves de propiedades sin riesgo de colisión.

✅ Característica clave

Cada Symbol() que creas es único aunque tenga la misma descripción:


const A = Symbol("id");
const B = Symbol("id");

console.log(A === B); // false

📌 Importante

Esto significa que es perfecto para crear claves que nadie va a pisar accidentalmente con "id", "name", etc.

2) ¿Para qué sirve realmente Symbol?

Caso real: evitar colisiones

Imagina que tú y una librería queréis añadir una propiedad id a un objeto.

  • Si ambos usáis "id" → colisión
  • Si tú usas Symbol("id") → no colisión nunca

3) Usando Symbol en una clase

Vamos a crear una clase User con:

  • name visible
  • id oculto usando Symbol

✅ Ejemplo completo


const ID = Symbol("id"); // clave privada/simbólica

class User {
  constructor(name) {
    this.name = name;
    this[ID] = Math.random(); // guardamos el id usando Symbol como clave
  }
}

const user = new User("Roge");

console.log(user.name); // Roge
console.log(user.id);   // undefined (porque NO existe "id" como string)
console.log(user[ID]);  // ✅ sí accede (si tienes el Symbol)

4) ¿Por qué user.id da undefined?

Porque id y [ID] son claves distintas:

  • user.id → busca una propiedad que se llame "id"
  • user[ID] → busca una propiedad cuya clave es el Symbol

Es como si fueran dos nombres diferentes.

5) "Parece privado"... pero NO es privado de verdad

Aquí viene lo importante para tu tutorial:

✅ Symbol no crea privacidad real

Solo crea ocultación, porque:

  • No aparece normalmente con . (dot notation)
  • No aparece en Object.keys()
  • Pero se puede descubrir

⚠️ Se puede ver con introspección


const symbols = Object.getOwnPropertySymbols(user);

console.log(symbols); // [ Symbol(id) ]
console.log(user[symbols[0]]); // accede al id oculto

📌 Conclusión

Symbol es "semi-privado": lo oculta, pero no protege.

6) Entonces... ¿se puede modificar el valor?

Sí, porque Symbol no impide reasignar el valor:


user[ID] = 123;
console.log(user[ID]); // 123

OJO: el Symbol es inmutable, pero el valor dentro de la propiedad NO.

7) Cómo hacerlo más "protegido" (writable: false)

Si quieres que el valor no pueda reasignarse fácilmente, define la propiedad manualmente:


const ID = Symbol("id");

class User {
  constructor(name) {
    this.name = name;

    Object.defineProperty(this, ID, {
      value: Math.random(),
      writable: false,      // ❌ no se puede reasignar
      enumerable: false,    // no aparece en keys
      configurable: false,  // no se puede redefinir
    });
  }

  get id() {
    return this[ID]; // acceso controlado
  }
}

const user = new User("Roge");

console.log(user.id); // ok

user[ID] = 999;       // falla (en strict lanza error)
console.log(user.id); // sigue igual

✅ Resultado

Esto ya simula bastante bien una propiedad privada "en tiempos antiguos".

8) Mejor opción moderna: #private (privado real)

Desde ES2020+ (y ya muy soportado) tenemos privados reales con #.

Esto SÍ es privacidad real:


class User {
  #id;

  constructor(name) {
    this.name = name;
    this.#id = crypto.randomUUID();
  }

  get id() {
    return this.#id;
  }
}

const user = new User("Roge");

console.log(user.id);  // ✅ funciona
console.log(user.#id); // ❌ SyntaxError: Private field '#id' must be declared in an enclosing class

✅ Ventajas de #private

  • Nadie puede acceder desde fuera
  • No se puede descubrir con introspección
  • Es el estándar moderno recomendado

9) Cuándo usar Symbol hoy en día

Aunque ya no sea el mejor para privacidad, Symbol sigue siendo útil.

✅ Úsalo cuando:

  • Necesitas evitar colisiones en objetos compartidos
  • Haces librerías/utilidades públicas
  • Quieres metadata invisible al usuario normal

10) Bonus (muy pro): Symbol.iterator

Este caso es muy útil y demuestra Symbols con valor real hoy:


class Collection {
  constructor(items) {
    this.items = items;
  }

  [Symbol.iterator]() {
    return this.items.values();
  }
}

const c = new Collection([1, 2, 3]);

for (const value of c) {
  console.log(value);
}

Salida:


1
2
3

📌 Importante

Esto sirve para que tu clase funcione en for...of.

✅ Resumen

Lo que debes recordar

  • ✅ Symbol crea claves únicas → evita colisiones
  • ✅ Oculta propiedades (no salen con . ni Object.keys)
  • ⚠️ No es privacidad real: puede descubrirse con getOwnPropertySymbols
  • ✅ Si quieres privacidad real usa #private
  • ✅ Symbol sigue siendo muy útil para features como Symbol.iterator

Checklist de Errores Comunes

⚠️ Errores típicos a evitar

  • ❌ Creer que Symbol proporciona privacidad real
  • ❌ No entender que Symbol("id") !== Symbol("id")
  • ❌ Usar Symbol cuando #private sería más apropiado
  • ❌ Olvidar que el valor almacado en Symbol puede modificarse
