Prototipos en JavaScript

Entendiendo el mecanismo de herencia y lookup de propiedades

1️⃣ ¿Qué Problema Resuelven los Prototipos?

Cuando accedes a obj.algo, el motor de JavaScript hace un lookup:

Proceso de Búsqueda:

  1. ¿Existe algo en el objeto?
  2. Si no, mira en su prototipo ([[Prototype]])
  3. Si no, sube por la cadena (prototype chain)
  4. Si no aparece, devuelve undefined

Ejemplo Claro


const person = { name: "Bryce" };

console.log(person.name);       // "Bryce" (propiedad propia)
console.log(person.toString);   // function... (viene de Object.prototype)
console.log(person.xyz);        // undefined

💡 La Idea Potente

Hay métodos que "no están" en el objeto pero funcionan. Vienen del prototipo.

2️⃣ Todo Objeto Tiene [[Prototype]]

Todo objeto en JavaScript tiene un prototipo interno llamado [[Prototype]].

Ver el Prototipo (Forma Moderna)


const person = { name: "Bryce" };

console.log(Object.getPrototypeOf(person) === Object.prototype);
// true

👉 Importante

Object.prototype es como la "base" de objetos normales en JavaScript.

⚠️ Sobre __proto__

__proto__ es legacy (heredado). Funciona, pero no se recomienda.

Forma moderna:

  • Object.getPrototypeOf(obj) para obtener el prototipo
  • Object.setPrototypeOf(obj, proto) para establecerlo (con cautela)
  • Object.create(proto) para crear objetos con un prototipo dado

3️⃣ De Dónde Salen los Métodos "Mágicos"


const person = { name: "Bryce", age: 37 };

console.log(person.toString());
// "[object Object]"

console.log(person.hasOwnProperty("name"));
// true

📌 Explicación

Estos métodos no están en person, están en Object.prototype.

El motor los encuentra siguiendo la cadena de prototipos.

Verificar Propiedades Propias


console.log(person.hasOwnProperty("toString"));
// false (viene del prototipo)

console.log(person.hasOwnProperty("name"));
// true (propiedad propia)

4️⃣ Herencia Real con Object.create

Aquí es donde los prototipos muestran su verdadero poder.


const personProto = {
  greet() {
    return `Hola, soy ${this.name}`;
  }
};

const bryce = Object.create(personProto);
bryce.name = "Bryce";
bryce.age = 37;

console.log(bryce.greet());
// "Hola, soy Bryce"

✅ Esto SÍ es Prototipos

greet no está en bryce, está en personProto, pero se encuentra por la cadena.

Verificar


console.log(bryce.hasOwnProperty("greet"));
// false

console.log(Object.getPrototypeOf(bryce) === personProto);
// true

5️⃣ Compartir Métodos (La Razón Práctica)

Si creas 1000 personas:

❌ Sin prototipos:

Si defines greet dentro de cada objeto → 1000 funciones en memoria

✅ Con prototipos:

Si greet vive en el prototipo → 1 función compartida


const personProto = {
  greet() {
    return `Hola, soy ${this.name}`;
  }
};

const a = Object.create(personProto);
a.name = "A";

const b = Object.create(personProto);
b.name = "B";

console.log(a.greet === b.greet);
// true (¡misma función compartida!)

💡 El "Click" para Juniors

Ese true demuestra que ambos objetos comparten el mismo método en memoria.

6️⃣ Entendiendo this en Métodos del Prototipo

Muchos juniors se preguntan: "¿cómo sabe el método quién es this?"


const personProto = {
  greet() {
    return `Hola, soy ${this.name}`;
  }
};

const bryce = Object.create(personProto);
bryce.name = "Bryce";

const ana = Object.create(personProto);
ana.name = "Ana";

console.log(bryce.greet()); // "Hola, soy Bryce"
console.log(ana.greet());   // "Hola, soy Ana"

📌 Justificación

El método se ejecuta con el "receiver":

  • bryce.greet() → this === bryce
  • ana.greet() → this === ana

7️⃣ Conectar con class (Forma Moderna)

Hoy en día escribimos esto con class, que es azúcar sintáctico sobre prototipos.


class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    return `Hola, soy ${this.name}`;
  }
}

const bryce = new Person("Bryce", 37);

console.log(bryce.greet());
// "Hola, soy Bryce"

console.log(Object.getPrototypeOf(bryce) === Person.prototype);
// true

👉 Importante

Los métodos en una class viven en Person.prototype.

JavaScript sigue siendo prototipal, pero hoy lo escribimos con class.

8️⃣ Diferencia Clave: prototype vs [[Prototype]]

⚠️ Muy Importante (Confusión Común)

prototype NO es una propiedad de cualquier objeto.

prototype es una propiedad de las funciones (cuando se usan como constructor) y de las clases.

✅ Diferencias Claras

  • Person.prototype → objeto usado como prototipo para instancias creadas con new Person()
  • bryce.__proto__ / Object.getPrototypeOf(bryce) → el prototipo real de esa instancia

Demostración


function Person(name) {
  this.name = name;
}

Person.prototype.greet = function() {
  return `Hola, soy ${this.name}`;
};

const bryce = new Person("Bryce");

console.log(Object.getPrototypeOf(bryce) === Person.prototype);
// true

console.log(Person.prototype.hasOwnProperty("greet"));
// true

console.log(bryce.hasOwnProperty("greet"));
// false

9️⃣ Caso Especial: Object.create(null)

A veces "prototipo nulo" es intencional.


const dict = Object.create(null);
dict.apple = 1;
dict.orange = 2;

console.log(dict.toString);
// undefined (no hereda de Object.prototype)

console.log(Object.getPrototypeOf(dict));
// null

✅ Casos de Uso

  • Objetos usados como "diccionarios puros"
  • Evitar colisiones con nombres de métodos heredados
  • Mejor rendimiento en lookups cuando no necesitas métodos heredados

Comparación


const normalObj = {};
const pureDict = Object.create(null);

console.log(normalObj.toString);   // function
console.log(pureDict.toString);    // undefined

🔟 Advertencias y Mejores Prácticas

⚠️ Object.setPrototypeOf (Performance)

Cambiar el prototipo en caliente puede afectar rendimiento/optimizaciones del motor.


// ❌ Evitar esto
const obj = { name: "test" };
Object.setPrototypeOf(obj, someProto);

✅ Mejor: Crear con el prototipo correcto desde el inicio.


// ✅ Forma recomendada
const obj = Object.create(someProto);
obj.name = "test";

👉 Recomendaciones

  • Usa class para definir "tipos" (es más clara)
  • Usa Object.create() cuando necesites herencia explícita
  • Usa Object.getPrototypeOf() en lugar de __proto__
  • Evita Object.setPrototypeOf() en código de producción

1️⃣1️⃣ Cadena de Prototipos Completa


class Animal {
  eat() {
    return "eating...";
  }
}

class Dog extends Animal {
  bark() {
    return "woof!";
  }
}

const myDog = new Dog();

console.log(myDog.bark());  // "woof!"
console.log(myDog.eat());   // "eating..."

// Cadena completa:
console.log(Object.getPrototypeOf(myDog) === Dog.prototype);
// true

console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype);
// true

console.log(Object.getPrototypeOf(Animal.prototype) === Object.prototype);
// true

console.log(Object.getPrototypeOf(Object.prototype));
// null

📌 La Cadena Completa

myDog → Dog.prototype → Animal.prototype → Object.prototype → null

1️⃣2️⃣ Resumen Mental Final

Conceptos Clave

Todo objeto tiene [[Prototype]]

  • Se accede con Object.getPrototypeOf(obj)
  • Normalmente apunta a Object.prototype

prototype es propiedad de funciones/clases

  • Define qué prototipo tendrán las instancias
  • new Person() → instancia con [[Prototype]] = Person.prototype

Ventajas de prototipos

  • Compartir métodos entre instancias
  • Ahorro de memoria
  • Herencia y reutilización de código

Forma moderna

  • Usa class para claridad
  • Usa Object.create() cuando necesites control
  • Evita __proto__ y setPrototypeOf
