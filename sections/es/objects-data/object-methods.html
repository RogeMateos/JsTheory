Métodos de Objetos (assign, keys, values, entries)

El Problema del Mundo Real

Imagina que trabajas en un sitio de analytics y necesitas construir un payload para un evento:


const baseEvent = { event: "select_item", page: "Renewals" };
const userContext = { userId: "u123", loggedIn: true };
const itemContext = { itemId: "car_456", price: 220 };

// ¿Cómo combino estos 3 objetos en uno solo?

Desafío

Necesitas combinar múltiples objetos en uno solo sin modificar los originales.

Solución 1: Spread Operator (Lo Moderno) ✅

La forma más idiomática y legible en JavaScript moderno:


const baseEvent = { event: "select_item", page: "Renewals" };
const userContext = { userId: "u123", loggedIn: true };
const itemContext = { itemId: "car_456", price: 220 };

const payload = { ...baseEvent, ...userContext, ...itemContext };

console.log(payload);
// {
//   event: "select_item",
//   page: "Renewals",
//   userId: "u123",
//   loggedIn: true,
//   itemId: "car_456",
//   price: 220
// }

✅ Ventajas del Spread

  • Más legible y moderno
  • Patrón más usado en React
  • No modifica los objetos originales

Solución 2: Object.assign() (Código Legacy)

Object.assign() copia propiedades de uno o más objetos fuente a un objeto destino.


const baseEvent = { event: "select_item", page: "Renewals" };
const userContext = { userId: "u123", loggedIn: true };
const itemContext = { itemId: "car_456", price: 220 };

// ✅ Crear nuevo objeto (destino = {})
const payload = Object.assign({}, baseEvent, userContext, itemContext);

console.log(payload);
// { event, page, userId, loggedIn, itemId, price }

Regla mnemónica

El primer parámetro es el que se modifica (si no usas {} como destino).

⚠️ Trampa 1: Mutación del Objeto Destino

Esta es la trampa más peligrosa de Object.assign():


const personCore = { name: "Roge" };
const personDetails = { age: 30, alias: "MoureDev" };

// ❌ MUTA personCore (destino = personCore)
Object.assign(personCore, personDetails);
console.log(personCore);
// { name: "Roge", age: 30, alias: "MoureDev" }
// ¡personCore se modificó!

// ✅ NO muta nada (destino = {})
const fullPerson = Object.assign({}, personCore, personDetails);
// Ahora personCore sigue intacto

🔥 Por qué importa

En aplicaciones reales, mutar objetos compartidos puede romper:

  • React (re-renders inesperados)
  • Redux/Zustand (state management)
  • Cachés y referencias compartidas

✅ Solución

Usa siempre {} como primer parámetro o mejor aún, usa spread { ...obj }

⚠️ Trampa 2: Conflictos de Claves (Gana el Último)

Si dos objetos tienen la misma propiedad, el último objeto fuente sobrescribe:


const a = { name: "Roge", role: "developer" };
const b = { name: "Otro", city: "London" };

const result = Object.assign({}, a, b);
console.log(result.name); // "Otro" ← gana b
console.log(result);
// { name: "Otro", role: "developer", city: "London" }

💡 Regla de Oro

👉 Si hay colisión, el último parámetro gana.

Mismo comportamiento con spread


const result = { ...a, ...b };
console.log(result.name); // "Otro"

⚠️ Trampa 3: Copia Superficial (Shallow Copy)

Si hay objetos anidados, NO se clonan: se copia la referencia.


const core = {
  name: "Roge",
  address: { city: "London" }  // ← objeto anidado
};

const copy = Object.assign({}, core);

// Modificamos la ciudad en la copia
copy.address.city = "Madrid";

// ¡El original también cambió! 🔥
console.log(core.address.city); // "Madrid"

🔥 Por qué pasa esto

Tanto Object.assign() como spread hacen copia superficial:

  • Las propiedades primitivas se copian
  • Los objetos/arrays anidados se copian por referencia

✅ Soluciones para copia profunda

Moderna (navegadores modernos):


const deepCopy = structuredClone(core);
deepCopy.address.city = "Madrid";
console.log(core.address.city); // "London" ✅

Legacy:


// JSON (solo funciona si no hay funciones/Date/undefined)
const deepCopy = JSON.parse(JSON.stringify(core));

// O usa librerías como lodash
import { cloneDeep } from 'lodash';
const deepCopy = cloneDeep(core);

⚠️ Trampa 4: Qué Copia Exactamente

Object.assign() copia propiedades enumerables propias (incluye símbolos enumerables), y copia valores, no descriptores.

Regla técnica

No copia getters/setters como descriptores, copia el resultado/valor según el caso.

Inspección del Objeto: keys, values, entries

Ahora que tienes tu objeto combinado, ¿cómo lo inspeccionas?


const payload = {
  event: "select_item",
  page: "Renewals",
  userId: "u123",
  loggedIn: true,
  itemId: "car_456",
  price: 220
};

// Obtener solo las claves
console.log(Object.keys(payload));
// ["event", "page", "userId", "loggedIn", "itemId", "price"]

// Obtener solo los valores
console.log(Object.values(payload));
// ["select_item", "Renewals", "u123", true, "car_456", 220]

// Obtener pares [clave, valor]
console.log(Object.entries(payload));
// [
//   ["event", "select_item"],
//   ["page", "Renewals"],
//   ["userId", "u123"],
//   ["loggedIn", true],
//   ["itemId", "car_456"],
//   ["price", 220]
// ]

Iteración Práctica con entries + for...of

La forma más útil en el mundo real:


const payload = {
  event: "select_item",
  page: "Renewals",
  userId: "u123",
  price: 220
};

// ✅ Con destructuring (lo más idiomático)
for (const [key, value] of Object.entries(payload)) {
  console.log(`${key}:`, value);
}

// Output:
// event: select_item
// page: Renewals
// userId: u123
// price: 220

✅ Esto es oro para juniors

En lugar de usar índices [0] y [1], destructura directamente como [key, value].

Casos de uso reales


// Convertir objeto a query string
const params = { page: 1, limit: 10, sort: "name" };
const queryString = Object.entries(params)
  .map(([key, value]) => `${key}=${value}`)
  .join('&');
console.log(queryString); // "page=1&limit=10&sort=name"

// Filtrar propiedades de un objeto
const user = { name: "Roge", age: 30, password: "secret123" };
const publicUser = Object.fromEntries(
  Object.entries(user).filter(([key]) => key !== 'password')
);
console.log(publicUser); // { name: "Roge", age: 30 }

Orden de las Claves (Matiz Real)

El orden suele ser estable, pero no es simplemente "el orden que escribiste":


const obj = { 2: "b", 1: "a", name: "Roge", age: 30 };

console.log(Object.keys(obj));
// ["1", "2", "name", "age"]
// ↑ Números primero (ordenados ascendente), luego strings (por inserción)

📌 Regla de ordenamiento

Las claves numéricas se ordenan primero de forma ascendente, luego strings por orden de inserción.

Diferencia con for...in

Mucha gente confunde Object.keys() con for...in:


const base = { inherited: true };
const obj = Object.create(base);
obj.own = true;

// Object.keys → solo propias
console.log(Object.keys(obj)); // ["own"]

// for...in → también recorre heredadas del prototipo
for (const k in obj) {
  console.log(k); // "own" y "inherited"
}

✅ Diferencias clave

  • Object.keys(obj) → solo propiedades propias
  • for...in → también recorre propiedades heredadas del prototipo

Si necesitas filtrar en for...in


for (const k in obj) {
  if (obj.hasOwnProperty(k)) {
    console.log(k); // solo "own"
  }
}

Resumen: Cuándo Usar Cada Uno

Combinar objetos

  • ✅ Spread { ...a, ...b } → código moderno, legible
  • ⚠️ Object.assign({}, a, b) → código legacy, menos legible

Inspeccionar objetos

  • Object.keys() → obtener solo claves
  • Object.values() → obtener solo valores
  • Object.entries() → obtener pares [clave, valor]

Iterar objetos

  • ✅ for (const [k, v] of Object.entries(obj)) → moderno, con destructuring
  • ⚠️ for...in → incluye heredados, necesita filtro con hasOwnProperty

Pitfalls Checklist

⚠️ Errores comunes a evitar

  • ❌ Mutar el objeto original con Object.assign(obj, ...)
  • ❌ Asumir que Object.assign hace copia profunda
  • ❌ No considerar colisiones de claves al combinar objetos
  • ❌ Usar for...in sin filtrar con hasOwnProperty
