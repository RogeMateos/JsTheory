Clases Abstractas en JavaScript (simuladas) + Herencia + Polimorfismo

0) Qué vas a aprender

  • Qué es una clase abstracta (concepto)
  • Por qué en JavaScript no existe abstract class "real" (en runtime)
  • Cómo simular:
    • que no se pueda instanciar la base
    • que un método "deba" implementarse en subclases
  • Cómo aplicar esto con extends, super() y polimorfismo

Paso 0) Concepto rápido (sin humo)

Una clase abstracta sirve para:

  • Definir una estructura base (propiedades comunes)
  • Definir un contrato (métodos que deben existir)
  • Evitar que alguien la use como objeto "real" (new)

Ejemplo mental:

  • "Animal" no es un animal concreto
  • "Dog" y "Cat" sí lo son

Paso 1) Empezamos con una clase normal (y vemos el problema)


class Animal {
  makeSound() {
    console.log("Emito sonido");
  }
}

const a = new Animal();
a.makeSound();

El problema

✅ Esto funciona.

❌ Pero si "Animal" debería ser abstracta... esto NO debería permitirse.

Paso 2) Bloquear new Animal() con new.target

Idea: si alguien intenta instanciar exactamente Animal, lanzamos un error.


class Animal {
  constructor() {
    if (new.target === Animal) {
      throw new Error("No se puede instanciar Animal directamente (clase abstracta).");
    }
  }

  makeSound() {
    console.log("Emito sonido");
  }
}

// const a = new Animal(); // ❌ Error

Qué es new.target

  • Es la clase/función que se está instanciando con new
  • Si haces new Animal(), entonces new.target === Animal

Paso 3) Añadir estado compartido: name

Ahora sí: "todos los animales tienen nombre".


class Animal {
  constructor(name) {
    if (new.target === Animal) {
      throw new Error("No se puede instanciar Animal directamente (clase abstracta).");
    }

    this.name = name;
  }

  makeSound() {
    console.log("Emito sonido");
  }
}

Pero aquí falta algo importante...

Paso 4) Validar parámetros (nivel "pro" pero simple)

Un tutorial bueno enseña hábitos buenos:


class Animal {
  constructor(name) {
    if (new.target === Animal) {
      throw new Error("No se puede instanciar Animal directamente (clase abstracta).");
    }

    if (!name) {
      throw new Error("El nombre es obligatorio para crear un Animal.");
    }

    this.name = name;
  }

  makeSound() {
    console.log("Emito sonido");
  }
}

Paso 5) Convertir makeSound() en "abstracto"

Queremos obligar a que Dog/Cat lo implementen.

La forma típica en JS es:


class Animal {
  constructor(name) {
    if (new.target === Animal) {
      throw new Error("No se puede instanciar Animal directamente (clase abstracta).");
    }
    if (!name) {
      throw new Error("El nombre es obligatorio para crear un Animal.");
    }
    this.name = name;
  }

  makeSound() {
    throw new Error("makeSound() debe ser implementado por la subclase.");
  }
}

✅ Esto convierte el método en "contrato"

Si no lo implementas, revienta.

Paso 6) Crear una subclase: Dog extends Animal

Aquí aparecen 2 claves:

  • extends (herencia)
  • super(name) (llama al constructor del padre)

class Dog extends Animal {
  constructor(name) {
    super(name);
  }

  makeSound() {
    console.log(`${this.name} dice: Guau!`);
  }
}

const dog = new Dog("Rocky");
dog.makeSound(); // Rocky dice: Guau!

Paso 7) Otra subclase: Cat

Mismo contrato (makeSound()), comportamiento distinto.


class Cat extends Animal {
  constructor(name) {
    super(name);
  }

  makeSound() {
    console.log(`${this.name} dice: Miau!`);
  }
}

const cat = new Cat("Milo");
cat.makeSound(); // Milo dice: Miau!

Paso 8) Demostración de polimorfismo (lo importante de verdad)

Polimorfismo = mismo método, distintas implementaciones, uso uniforme


const animals = [new Dog("Rocky"), new Cat("Milo")];

animals.forEach((a) => a.makeSound());

Salida:


Rocky dice: Guau!
Milo dice: Miau!

💡 Lo importante

Tú tratas a todos como "Animal", pero cada uno responde distinto.

Paso 9) Pruebas de que nuestra "abstracción" funciona

1) Instanciar Animal falla


const a = new Animal("Base"); // ❌ Error

2) Subclase sin implementar makeSound falla al llamarlo


class Fish extends Animal {
  constructor(name) {
    super(name);
  }
  // no makeSound()
}

const f = new Fish("Nemo");
f.makeSound(); // ❌ Error: debe ser implementado por la subclase

Paso 10) Versión final completa (lista para producción)


class Animal {
  constructor(name) {
    if (new.target === Animal) {
      throw new Error("No se puede instanciar Animal directamente (clase abstracta).");
    }

    if (!name) {
      throw new Error("El nombre es obligatorio para crear un Animal.");
    }

    this.name = name;
  }

  makeSound() {
    throw new Error("makeSound() debe ser implementado por la subclase.");
  }
}

class Dog extends Animal {
  constructor(name) {
    super(name);
  }

  makeSound() {
    console.log(`${this.name} dice: Guau!`);
  }
}

class Cat extends Animal {
  constructor(name) {
    super(name);
  }

  makeSound() {
    console.log(`${this.name} dice: Miau!`);
  }
}

// ✅ OK
const dog = new Dog("Rocky");
dog.makeSound();

const cat = new Cat("Milo");
cat.makeSound();

// ✅ Polimorfismo
const animals = [dog, cat];
animals.forEach((a) => a.makeSound());

// ❌ Debe fallar
// const a = new Animal("Base");

Bonus: Esto en TypeScript es más limpio

📌 Nota para TypeScript

En TS sí existe abstract class y el compilador te obliga a implementar métodos abstractos.

Ejemplo TypeScript equivalente:


abstract class Animal {
  constructor(public name: string) {}

  abstract makeSound(): void;
}

class Dog extends Animal {
  makeSound(): void {
    console.log(`${this.name} dice: Guau!`);
  }
}

// const a = new Animal("Base"); // ❌ Error de compilación

✅ Resumen

Lo que debes recordar

  • Clase abstracta: no se instancia directamente, solo sirve como base
  • new.target: nos dice qué clase está siendo instanciada
  • extends: crea herencia de una clase a otra
  • super(): llama al constructor del padre
  • Métodos abstractos: lanzamos error si no son implementados
  • Polimorfismo: mismo método, comportamientos diferentes

Checklist de Errores Comunes

⚠️ Errores típicos a evitar

  • ❌ Olvidar llamar super() en el constructor de la subclase
  • ❌ Llamar super() después de usar this
  • ❌ No validar parámetros obligatorios en el constructor
  • ❌ No implementar métodos "abstractos" en las subclases
