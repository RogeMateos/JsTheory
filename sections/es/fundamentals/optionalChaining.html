Optional Chaining (?.)

Acceder de forma segura a propiedades que podrían no existir

🎯 Definición Simple para Entrevistas

Optional Chaining (?.)

El operador ?. significa: "Solo accede a esto si existe"

Evita errores cuando intentes acceder a propiedades de null o undefined.

❌ El Problema que Resuelve

Cuando el elemento no existe

Imagina que buscas un botón en el DOM:

const button = document.querySelector('#boton-importante')
button.addEventListener('click', () => {
  console.log('Click')
})

Si ese botón no existe en el HTML:

button = null

// JavaScript intenta ejecutar:
null.addEventListener()

// ❌ Error:
// Uncaught TypeError: Cannot read properties of null

La aplicación se rompe 💥

Si intentas acceder a una propiedad de null o undefined, JavaScript lanza un error y el código se detiene.

📖 Solución Clásica (antes de ES2020)

Comprobar con if

Había que validar primero si existe:

const button = document.querySelector('#boton-importante')

if (button) {
  button.addEventListener('click', () => {
    console.log('Click')
  })
}

¿Qué significa?

  • Si button existe → ejecuta el código
  • Si button es null → no hace nada

Funciona, pero genera mucho código repetido.

✅ La Solución Moderna: Optional Chaining

El operador ?.

Simplemente añade ?. antes de acceder a la propiedad:

const button = document.querySelector('#boton-importante')

button?.addEventListener('click', () => {
  console.log('Click')
})

¿Qué hace?

  • Si button existe → ejecuta addEventListener
  • Si button es null → no hace nada y no hay error

✨ Mismo resultado, mucho menos código.

📊 Comparación: Sin vs Con Optional Chaining

❌ Sin Optional Chaining
const button = document.querySelector('#btn')

if (button) {
  button.addEventListener('click', handler)
}
✅ Con Optional Chaining
const button = document.querySelector('#btn')

button?.addEventListener('click', handler)

Mismo resultado, menos líneas, más legible.

🔍 También Funciona con Propiedades

Acceder a propiedades de forma segura

const button = document.querySelector('#boton-importante')

console.log(button?.textContent)  // Texto del botón
console.log(button?.id)           // ID del botón
console.log(button?.disabled)     // Si está deshabilitado

Si el botón no existe

Devuelve undefined sin error.

La aplicación NO se rompe.

⛓️ Encadenamiento (Muy Potente)

Puedes usar ?. varias veces

const container = document.querySelector('#container')

const width = container?.firstChild?.getBoundingClientRect()?.width

¿Qué significa?

  1. Si container existe
  2. Y firstChild existe
  3. Y getBoundingClientRect() existe
  4. → devuelve width

Si algo no existe → devuelve undefined sin errores.

💡 Ejemplo Práctico: API Response

Datos de una API que podrían no existir

const response = {
  data: {
    user: {
      name: 'Miguel',
      profile: {
        city: 'Madrid'
      }
    }
  }
}

// Sin optional chaining (peligroso):
console.log(response.data.user.profile.city)  // ✅ 'Madrid'

// Si profile no existe:
console.log(response.data.user.profile.city)  // ❌ Error

Con optional chaining (seguro)

// Seguro aunque algún nivel no exista:
console.log(response.data?.user?.profile?.city)  // ✅ 'Madrid' o undefined

🎯 Regla Mental Simple

?. = "solo si existe"

Cuando veas ?., piensa: "Solo accede si esto existe"

usuario?.direccion?.ciudad

// Significa:
"Dame la ciudad solo si usuario y dirección existen"

🔥 Cuándo Lo Verás (Muy Común)

Lugares donde aparece optional chaining:

  • DOM: Seleccionar elementos que podrían no existir
  • APIs: Datos que podrían estar incompletos
  • React: Props que podrían ser undefined
  • Objetos: Propiedades opcionales

Ejemplo típico en React:

// Obtener el nombre del usuario de props:
console.log(props?.user?.profile?.name)

⚡ Optional Chaining con Arrays

También funciona con índices

const items = [
  { name: 'Item 1' },
  { name: 'Item 2' }
]

// Seguro:
console.log(items?.[0]?.name)   // 'Item 1'
console.log(items?.[5]?.name)   // undefined (sin error)

Si items no existe o no tiene ese índice → undefined sin error.

✅ Conclusión

?. evita errores cuando algo puede ser null o undefined

Permite escribir código:

  • ✅ Más seguro (sin errores inesperados)
  • ✅ Más corto (menos if/else)
  • ✅ Más legible (intención clara)
