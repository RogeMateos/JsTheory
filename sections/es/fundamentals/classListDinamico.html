Aplicando Clases CSS Dinámicamente con JavaScript

Cambiar la apariencia de elementos manipulando clases en lugar de estilos inline

🎯 Definición Simple para Entrevistas

¿Cuál es la idea principal?

Usar JavaScript para añadir o quitar clases CSS en lugar de modificar estilos directamente.

De esta forma, CSS se encarga del "cómo se ve" y JavaScript del "cuándo cambiar".

💡 Concepto Clave: Separación de Responsabilidades

No hagas esto ❌

job.style.display = 'none'
job.style.display = 'flex'

Aquí mezclas CSS y lógica JavaScript. Es complicado de mantener.

Haz esto en su lugar ✅

job.classList.add('is-hidden')

JavaScript decide cuándo cambiar, CSS define cómo se ve.

La regla mental

CSS = apariencia

JavaScript = comportamiento

1️⃣ Por Qué No Conviene Usar .style Directamente

Ejemplo no recomendado

job.style.display = 'none'  // ocultar
job.style.display = 'flex'  // mostrar

Problemas con este enfoque

  • Mezcla responsabilidades (lógica y presentación)
  • Menos mantenible (si cambias el CSS, también cambias JS)
  • Más difícil de escalar a un proyecto grande
  • Más repetitivo
  • Menos legible

Mejor enfoque

Definir una clase en CSS:

.is-hidden {
  display: none;
}

Y luego en JavaScript añadir o quitar esa clase.

2️⃣ Definiendo una Clase CSS para Ocultar Elementos

Crea una clase reutilizable

.is-hidden {
  display: none;
}

¿Qué conseguimos con esto?

Ahora cualquier elemento que tenga esa clase quedará oculto:

<div class="job is-hidden">Oferta oculta</div>

Y si quitamos la clase, el elemento vuelve a mostrarse.

3️⃣ Usando classList

La propiedad classList

classList nos permite manipular las clases de un elemento HTML de forma sencilla.

Métodos más importantes

Método Qué hace
add() Añade una clase
remove() Elimina una clase
toggle() La añade o quita según exista
contains() Comprueba si existe
replace() Reemplaza una clase por otra

4️⃣ Ejemplo Real: Filtrar Ofertas de Empleo

El escenario

Tienes varias ofertas de trabajo y cada una tiene un atributo data-modalidad:

<div class="job" data-modalidad="remoto">Frontend Developer</div>
<div class="job" data-modalidad="hibrido">React Developer</div>
<div class="job" data-modalidad="presencial">UI Developer</div>

El usuario selecciona un filtro:

const selectedValue = 'remoto'

Queremos mostrar solo las ofertas cuya modalidad coincida.

5️⃣ Solución con add() y remove()

Código completo

jobs.forEach((job) => {
  const modalidad = job.getAttribute('data-modalidad')
  const isShown = selectedValue === '' || selectedValue === modalidad

  if (isShown) {
    job.classList.remove('is-hidden')
  } else {
    job.classList.add('is-hidden')
  }
})

Explicación paso a paso

  1. Recorremos cada oferta

    jobs.forEach((job) => {} - Iteramos sobre cada elemento

  2. Leemos su data-modalidad

    const modalidad = job.getAttribute('data-modalidad') - Devuelve "remoto", "hibrido", "presencial"

  3. Calculamos si debe mostrarse

    const isShown = selectedValue === '' || selectedValue === modalidad

    Si no hay filtro → mostrar todo

    Si coincide → mostrar

    Si no coincide → ocultar

  4. Añadimos o quitamos la clase

    Si debe verse → classList.remove('is-hidden')

    Si no debe verse → classList.add('is-hidden')

6️⃣ Solución Más Elegante con toggle()

La misma lógica, pero más compacta

jobs.forEach((job) => {
  const modalidad = job.getAttribute('data-modalidad')
  const isShown = selectedValue === '' || selectedValue === modalidad

  job.classList.toggle('is-hidden', !isShown)
})

Muy importante: ¿Qué hace toggle() con un segundo parámetro?

job.classList.toggle('is-hidden', !isShown)

Si el segundo parámetro es true → añade la clase

Si el segundo parámetro es false → quita la clase

¿Por qué usamos !isShown?

isShown = "¿debe verse?"

is-hidden = "¿debe estar oculto?"

Una significa mostrar y la otra ocultar, van al revés. Por eso negamos con !

Traducción mental

Si debe mostrarse:

isShown = true

!isShown = false

job.classList.toggle('is-hidden', false) → quita is-hidden


Si no debe mostrarse:

isShown = false

!isShown = true

job.classList.toggle('is-hidden', true) → añade is-hidden

7️⃣ Ventajas de Usar Clases en Lugar de style

1. Separación de responsabilidades

CSS decide cómo se ve algo

JavaScript decide cuándo cambiarlo

2. Más fácil de mantener

Si mañana quieres cambiar la forma de ocultar elementos:

.is-hidden {
  visibility: hidden;
  opacity: 0;
}

Solo tocas CSS. No tienes que modificar JavaScript.

3. Código más limpio

Con clases: job.classList.add('is-hidden')

Con estilos: job.style.display = 'none'

El primero expresa intención más claramente.

4. Reutilización

La clase .is-hidden puede usarse en cualquier parte del proyecto.

8️⃣ Otros Métodos Útiles de classList

contains() - Comprobar si un elemento tiene una clase

if (job.classList.contains('is-hidden')) {
  console.log('El elemento está oculto')
}

replace() - Sustituir una clase por otra

job.classList.replace('is-hidden', 'is-visible')

Muy útil cuando solo una de las dos debe existir.

Añadir varias clases a la vez

job.classList.add('featured', 'highlighted', 'premium')

Quitar varias clases a la vez

job.classList.remove('featured', 'highlighted', 'premium')

9️⃣ Ejemplo Completo y Realista

HTML

<select id="filter">
  <option value="">Todas</option>
  <option value="remoto">Remoto</option>
  <option value="hibrido">Híbrido</option>
  <option value="presencial">Presencial</option>
</select>

<div class="job-list">
  <div class="job" data-modalidad="remoto">Frontend Developer</div>
  <div class="job" data-modalidad="hibrido">React Developer</div>
  <div class="job" data-modalidad="presencial">UI Developer</div>
  <div class="job" data-modalidad="remoto">JavaScript Engineer</div>
</div>

CSS

.is-hidden {
  display: none;
}

JavaScript

const filter = document.querySelector('#filter')
const jobs = document.querySelectorAll('.job')

filter.addEventListener('change', () => {
  const selectedValue = filter.value

  jobs.forEach((job) => {
    const modalidad = job.getAttribute('data-modalidad')
    const isShown = selectedValue === '' || selectedValue === modalidad

    job.classList.toggle('is-hidden', !isShown)
  })
})

Flujo completo

  1. El usuario cambia el select
  2. Leemos el valor seleccionado
  3. Recorremos todas las ofertas
  4. Miramos el data-modalidad de cada una
  5. Calculamos si debe verse
  6. Añadimos o quitamos .is-hidden

🔟 Accesibilidad: Detalle Importante

Cuando ocultas con display: none

El elemento:

  • Desaparece visualmente ✅
  • Se oculta de lectores de pantalla ✅

Normalmente no necesitas añadir aria-hidden="true" porque display: none ya lo hace.

Pero hay excepciones

Cuando ocultas con técnicas como:

  • opacity: 0
  • visibility: hidden
  • Mover fuera de pantalla

Ahí sí conviene revisar accesibilidad con más cuidado y usar aria-hidden.

Ocultar con accesibilidad explícita

job.classList.add('is-hidden')
job.setAttribute('aria-hidden', 'true')

Volver a mostrar

job.classList.remove('is-hidden')
job.removeAttribute('aria-hidden')

1️⃣1️⃣ Nota Importante: Optimización

Lo que hacemos ahora

Estamos ocultando elementos que siguen en el DOM. Funciona bien para interfaces pequeñas.

Mejoras futuras

Opción 1: Filtrar en JavaScript de verdad

En vez de renderizar todo y ocultar, construye solo los elementos que deben aparecer.

Opción 2: Filtrar desde el backend

El servidor devuelve ya solo los resultados necesarios.

Esto ahorra: memoria, procesamiento, renderizados innecesarios, ancho de banda.

1️⃣4️⃣ Versión Pro del Concepto

Estados de UI, no estilos

Cuando usas classList, no estás cambiando el diseño directamente.

Estás diciendo: "Este elemento ahora está en el estado is-hidden".

Eso es más profesional porque trabajas con estados de UI, no con estilos sueltos.

Clases de estado comunes en proyectos reales:

  • is-hidden - Elemento oculto
  • is-active - Elemento activo (seleccionado)
  • is-open - Modal o menú abierto
  • is-disabled - Elemento deshabilitado
  • is-selected - Elemento seleccionado
  • is-loading - Cargando datos
  • is-error - Estado de error

El patrón profesional

JavaScript cambia el estado con classList.

CSS define cómo se ve ese estado.

HTML solo marca la estructura.
