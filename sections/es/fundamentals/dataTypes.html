Tipos de datos y tipado dinámico

El problema típico

“¿Por qué al sumar números obtuve texto?” Suele ocurrir cuando no entendemos cómo JavaScript convierte tipos automáticamente.

La idea

JavaScript agrupa datos en tipos primitivos (valores simples) y tipos de referencia (objetos). Distinguirlos te permite predecir el comportamiento de tu código.

Tipos primitivos

🏗️ Como materiales básicos

  • String: etiquetas o textos
  • Number: medidas o cantidades
  • Boolean: interruptor ON/OFF
  • null: caja vacía a propósito
  • undefined: caja nunca rellenada
  • Symbol: identificador único
  • BigInt: números enormes

// Primitivos en acción
let userName = 'Alice';         // String
let userAge = 25;               // Number
let isLoggedIn = true;          // Boolean
let data = null;                // Null (vacío a propósito)
let notAssigned;                // Undefined (sin asignar)
let uniqueId = Symbol('user');  // Symbol
let bigNumber = 123n;           // BigInt
      

// Chequeo seguro de tipos
const isString = (v) => typeof v === 'string';
const isNumber = (v) => typeof v === 'number' && !isNaN(v);
const isBoolean = (v) => typeof v === 'boolean';

function validarNombre(input) {
  if (!isString(input)) throw new Error('Debe ser string');
  if (!input.length) throw new Error('No puede ir vacío');
  return input.trim();
}

Trampas comunes

❌ Problema

let result = '5' + 3; // concatenación
console.log(result);  // "53"
✅ Mejor

let result = Number('5') + 3;
console.log(result); // 8

Tipos de referencia

Diferencia clave

Guardan una referencia (dirección) al valor en memoria.


const user = { name: 'Alice', age: 25 }; // Objeto
const hobbies = ['leer', 'jugar'];       // Array (objeto)
const greet = (name) => `Hola, ${name}!`; // Función (objeto especial)

console.log(typeof user);   // "object"
console.log(typeof hobbies); // "object"
console.log(typeof greet);   // "function"

Tipado dinámico

Qué significa

Una variable puede cambiar de tipo en tiempo de ejecución; el tipo se decide cuando el código se ejecuta.

¿Qué es “dinámico”?

  • Dynamic = can change while the program is running
  • Static = fixed/unchanging once set

What "Runtime" Means

  • Runtime = when your code is actually executing/running
  • Compile time = when code is being processed before it runs

🏷️ Storage Box Analogy

Think of a variable like a storage box with a label:

Static typing (Java/C++): The box has a permanent label "ONLY BOOKS" - you can only put books in it, forever.

Dynamic typing (JavaScript): The box just says "STORAGE" - you can put books in it today, shoes tomorrow, and toys next week! 


// JavaScript: Variables can hold any type, anytime!
let myVariable = "Hello";        // myVariable is a string
console.log(typeof myVariable);  // Output: "string"

myVariable = 42;                 // Now it's a number
console.log(typeof myVariable);  // Output: "number"

myVariable = true;               // Now it's a boolean
console.log(typeof myVariable);  // Output: "boolean"

myVariable = ["a", "b", "c"];    // Now it's an array
console.log(typeof myVariable);  // Output: "object"

// The variable name stays the same, but the type changes!

Dynamic vs Static Typing Comparison

🔴 Static Typing (Java/C++)

// Java: Types are fixed at declaration
int number = 5;        // This can ONLY hold integers
number = "hello";      // ❌ ERROR! Can't assign string to int

String text = "hello"; // This can ONLY hold strings
text = 42;             // ❌ ERROR! Can't assign number to string

// Types are checked BEFORE the program runs
🟢 Tipado dinámico (JavaScript)

// JavaScript: el tipo puede cambiar
let number = 5;        // número
number = "hola";       // ✅ ahora string

let text = "hola";     // string
text = 42;             // ✅ ahora número

// Se valida en tiempo de ejecución

🎭 Analogía del actor

Tipado estático: Un actor encasillado: si es de acción, solo hará acción.

Tipado dinámico: Un actor versátil que puede ser héroe, romance o comedia.

Por qué importa el tipado dinámico

Ventajas

  • Flexibilidad: escribir y modificar rápido
  • Menos verbo: sin declarar tipos por todos lados
  • Prototipado: cambiar estructuras sobre la marcha
  • Curva amable: menos sintaxis al inicio

Desventajas

  • Errores en ejecución: se detectan al correr
  • Debug más difícil: cambios inesperados de tipo
  • Performance: el motor checa tipos al volar
  • Documentación: menos claro qué espera cada función

// Ejemplo de tipado dinámico en código real
function procesarUsuario(userData) {
  // No sabemos el tipo hasta tiempo de ejecución
  if (typeof userData === 'object' && userData !== null) {
    return userData.name || 'Desconocido';
  }

  if (typeof userData === 'string') {
    return userData;
  }

  return 'Dato inválido';
}

console.log(procesarUsuario({ name: 'Alice' }));  // "Alice"
console.log(procesarUsuario('Bob'));              // "Bob"
console.log(procesarUsuario(null));               // "Dato inválido"
console.log(procesarUsuario(undefined));          // "Dato inválido"

Errores típicos en ejecución


// El problema de la "suma"
function addNumbers(a, b) {
    return a + b;
}

console.log(addNumbers(5, 3));        // 8 (número + número)
console.log(addNumbers("5", 3));      // "53" (string + número = concat)
console.log(addNumbers(5, "3"));      // "53" (número + string = concat)
console.log(addNumbers("5", "3"));    // "53" (string + string = concat)

// Por eso importa validar y convertir
function safeAddNumbers(a, b) {
  // Convertir a número primero
  const numA = Number(a);
  const numB = Number(b);
  
  if (isNaN(numA) || isNaN(numB)) {
    throw new Error('Ambos argumentos deben ser números');
  }
  
  return numA + numB;
}

console.log(safeAddNumbers("5", "3"));   // 8
console.log(safeAddNumbers("hello", 3)); // Error

Bug real


// Parece inocente pero tiene bug
function calculateDiscount(price, discount) {
  return price - (price * discount);
}

calculateDiscount(100, 0.1);    // 90
calculateDiscount(50, 0.2);     // 40

// ¿Y si viene de un formulario?
calculateDiscount("100", "0.1"); // 90 ✅ de suerte
calculateDiscount("abc", 0.1);   // NaN ❌

// Solución: validar y convertir
function safeCalculateDiscount(price, discount) {
  const numPrice = Number(price);
  const numDiscount = Number(discount);
  
  if (isNaN(numPrice) || isNaN(numDiscount)) {
    throw new Error('Precio y descuento deben ser números');
  }
  
  if (numDiscount < 0 || numDiscount > 1) {
    throw new Error('El descuento debe estar entre 0 y 1');
  }
  
  return numPrice - (numPrice * numDiscount);
}

Buenas prácticas con tipado dinámico

  • Valida entradas de usuarios/APIs
  • Usa typeof si dudas del tipo
  • Convierte explícitamente en vez de confiar en coerción
  • Considera TypeScript en proyectos grandes
  • Configura ESLint para atrapar errores de tipo

Reto de práctica

¡Construye un inspector de tipos!

Crea una función que reciba cualquier valor y devuelva un reporte del tipo:


function inspectType(value) {
  // Your code here!
  // Should return: { type: 'string', category: 'primitive', value: 'hello' }
}

// Test cases:
console.log(inspectType('hello'));      // string, primitive
console.log(inspectType(42));           // number, primitive  
console.log(inspectType([1, 2, 3]));    // object (array), reference
console.log(inspectType(null));         // object (pero null), primitive
💡 Pista: haz clic para ver

Usa typeof para lo básico, pero arrays y null devuelven "object". Necesitas verificaciones extras:

  • Array.isArray() para arrays
  • value === null para null
  • Primitivos: string, number, boolean, undefined, symbol, bigint
