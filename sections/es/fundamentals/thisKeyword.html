Uso de this en JavaScript

Por qué confunde

this no apunta a la función en sí, sino a quien la invoca. Cambia según el lugar y la forma en que se llama, lo que genera resultados inesperados si no se controla.

Idea clave

Piensa en this como el "dueño" de la ejecución actual. En funciones normales el dueño se decide al momento de invocar; en arrow functions el dueño es el mismo que rodea la definición.

Contexto global vs. objetos

Regla rápida

En el ámbito global del navegador, this es window; en Node.js suele ser global. Dentro de un objeto, this apunta a ese objeto si él hace la llamada.

Contexto global
function getName() {
  console.log(this.name);
}

global.name = 'Global Name'; // Node.js
getName(); // "Global Name"

// En el navegador
window.name = 'Global Name';
getName(); // "Global Name"
Dentro de un objeto
const user = {
  name: 'MyObject Name',
  getName: function() {
    console.log(this.name);
  }
};

user.getName(); // "MyObject Name"

Arrow functions y herencia de this

Sin propio contexto

Las arrow functions no crean su propio this; heredan el del entorno donde se declararon.

const myObject = {
  name: 'MyObject Name',
  getName: () => {
    console.log(this.name);
  }
};

global.name = 'Global Name';
myObject.getName(); // "Global Name" (heredado del ámbito exterior)

Truco Mental para Dominar this

Dibujito Mental

OBJETO
└── método()  ← función NORMAL
    └── arrow()  ← arrow function

Lectura correcta:

  • 🔵 método() → this = objeto
  • 🟡 arrow() → copia el this de método()

📌 Regla clave: La arrow NO mira al objeto, mira hacia arriba

Frase mágica (memorízala)

Arrow function → hereda this

Función normal → this es quien la llama

Test mental rápido (1 segundo)

obj.method();

1️⃣ ¿Tiene =>?

  • → Sí → ❌ this NO es obj
  • → No → ✅ this SÍ es obj

Regla práctica

  • ✅ Arrow → callbacks, setTimeout, map, filter
  • ❌ Arrow → métodos de objetos
  • ✅ Función normal → métodos que usan this

Ejercicio Trampa (nivel entrevista)

❓ ¿Qué imprime?

const team = {
  name: "Digital Renewals",
  show() {
    setTimeout(function () {
      console.log(this.name);
    }, 100);
  }

team.show();

🧠 Piensa con el truco

  1. 1️⃣ ¿setTimeout usa arrow? → ❌ NO
  2. 2️⃣ Función normal → pregunta: ¿quién me llama?
  3. 3️⃣ ¿Quién llama a esa función? → setTimeout
  4. 4️⃣ this ≠ team

✅ Resultado: undefined

❌ Incorrecto (función normal)
const team = {
  name: "Digital Renewals",
  show() {
    setTimeout(function () {
      console.log(this.name);
    }, 100);
  }
};

team.show(); // undefined
✅ Correcto (arrow function)
const team = {
  name: "Digital Renewals",
  show() {
    setTimeout(() => {
      console.log(this.name);
    }, 100);
  }
};

team.show(); // "Digital Renewals"

🏁 Resumen Final

  • 🔸 Arrow mira hacia arriba
  • 🔸 Función normal mira quién la llama
  • 🔸 Métodos de objetos → función normal
  • 🔸 Callbacks → arrow

✅ Respuesta: Roge

📌 Por qué:

  • saludar es función normal

  • Arrow hereda ese this
  • Sigue siendo user después de 1s

const user = {
  name: "Roge",
  saludar() {
    setTimeout(function () {
      console.log(this.name);
    }, 1000);
  }

user.saludar();

❓ Pregunta: ¿Qué imprime?

✅ Respuesta: undefined

📌 Por qué:

  • Función normal
  • setTimeout llama la función
  • this ya no es user

🏆 REGLA FINAL PARA SIEMPRE

🟢 Función normal → this depende de quién llama

🔵 Arrow function → this depende de dónde se define

Cambiar el contexto explícitamente

function getName() {
  console.log(this.name);
}

const myObject = { name: 'MyObject Name' };

getName.call(myObject);  // "MyObject Name"
getName.apply(myObject); // "MyObject Name"

function getName() {
  console.log(this.name);
}

const myObject = { name: 'MyObject Name' };
const boundGetName = getName.bind(myObject);

boundGetName(); // "MyObject Name" siempre

Funciones anidadas y solución con bind

const account = {
  owner: 'Ada',
  printOwner() {
    function inner() {
      console.log(this.owner);
    }
    inner.call(this); // o inner.bind(this)()
  }
};

account.printOwner(); // "Ada"
