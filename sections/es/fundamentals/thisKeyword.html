Uso de this en JavaScript

Por qué confunde

this no apunta a la función en sí, sino a quien la invoca. Cambia según el lugar y la forma en que se llama, lo que genera resultados inesperados si no se controla.

Idea clave

Piensa en this como el "dueño" de la ejecución actual. En funciones normales el dueño se decide al momento de invocar; en arrow functions el dueño es el mismo que rodea la definición.

🧠 Idea Visual Fundamental

Function normal

👉 this = quien ejecuta la función

Arrow function

👉 this = el this del entorno donde fue creada

🧠 Analogía definitiva

Imagina this como el "jefe":

  • Function normal → El jefe es quien te llama al despacho
  • Arrow function → El jefe es quien te contrató originalmente

💥 Frase que debes recordar

Function normal → this es dinámico

Arrow → this es léxico

📊 Estructura visual: Función normal vs Arrow

HANDLER (objeto)
│
├── name: "Brais"
│
└── greeting()   ← FUNCIÓN NORMAL
     │
     └── arrowGreeting()  ← ARROW FUNCTION

🔍 Lectura correcta:

  • greeting(): cuando se ejecuta, this = handler ✅
  • arrowGreeting(): hereda this de greeting(), entonces this = handler ✅

🔗 Cómo fluye this a través del scope

handler (objeto raíz)
│
├─ name: "Brais"
│
└─ greeting() (función NORMAL)
     │
     ├─ this ─────► handler (se decide aquí)
     │
     └─ arrowGreeting() (arrow function)
          │
          └─ this (heredado) ─────► handler

⚡ El flujo de this:

En funciones NORMALES: this se decide en el momento de ejecución

En arrow functions: this se hereda del scope donde fueron definidas

En este caso, ambas apuntan a handler porque la arrow function está dentro de una función normal ejecutada por handler.

¿Qué significa "ejecutar una función"?

Una función no hace nada hasta que alguien la llama

Definirla ≠ Ejecutarla

1️⃣ Definir una función
function saludar() {
  console.log("Hola");
}

// Aquí solo la estás guardando en memoria
// Todavía no se ejecuta
2️⃣ Ejecutar una función
saludar();

// Los paréntesis () significan:
// 👉 "Ejecuta lo que hay dentro"
// Ahora sí se corre el código

🔥 Entonces… ¿qué significa "quién ejecuta"?

Significa:

¿Desde qué objeto o contexto se está llamando la función?

Porque eso determina el valor de this.

Paso a paso: persona.saludar()

const persona = {
  nombre: "Roge",
  saludar: function () {
    console.log("Hola soy", this.nombre);
  }
};

persona.saludar();

🔎 Desglose

1️⃣ persona.saludar

Significa:

  • 👉 Ve al objeto persona
  • 👉 Busca la propiedad saludar

2️⃣ persona.saludar()

El () significa:

  • 👉 Ejecuta la función
  • 👉 Pero ejecútala como método de persona

Lo importante:

Cuando una función se llama usando punto (objeto.funcion()):

👉 El objeto a la izquierda del punto es quien ejecuta

En este caso: persona es quien ejecuta

Por lo tanto: this === persona

📌 ¿Por qué se dice "quien ejecuta"?

Porque JavaScript internamente hace algo parecido a esto:

persona.saludar()

// Se interpreta como:
// "Llama a saludar con persona como contexto"
// O: "Ejecuta esta función y usa persona como this"

📦 Visualízalo así

Imagina esto como una orden:

persona → "Oye saludar, ejecútate"

Entonces dentro de saludar:
👉 this apunta a quien dio la orden: persona

🔥 Ahora mira qué pasa si cambiamos la forma de llamar

const fn = persona.saludar;

fn();

// Ahora:
// fn() → Ya no hay punto
// Ya no hay objeto a la izquierda
// 👉 Nadie específico la está ejecutando
// 👉 this ya no es persona

🎯 Regla mental definitiva

Si hay punto:

objeto.metodo()
// 👉 this = objeto

Si NO hay punto:

funcion()
// 👉 this = window (en navegador)
// 👉 o undefined (en modo estricto)

🧠 Analogía sencilla

Imagina que la función es un empleado.

Si el jefe dice:

Persona: ejecuta esto
// El empleado sabe que su jefe es persona

Si alguien grita desde la nada:

¡Ejecuta!
// El empleado no sabe quién es el jefe

💡 Resumen ultra claro

"Ejecutar" significa:

  • 👉 Invocar la función usando ()
  • 👉 Y el valor de this depende de cómo la invocas

No depende de dónde está escrita.

Depende de cómo la llamas.

💥 Dinámico vs Léxico: La Diferencia Fundamental

💥 "Function normal → this es dinámico"

¿Qué significa dinámico?

Que cambia dependiendo de cómo se ejecute la función.

  • No está fijado cuando se define
  • Se decide en el momento de invocar

🔎 Ejemplo claro

function mostrar() {
  console.log(this.nombre);
}

const obj1 = { nombre: "Roge", mostrar };
const obj2 = { nombre: "Carlos", mostrar };

obj1.mostrar(); // Roge
obj2.mostrar(); // Carlos

👉 Es la misma función.

👉 Pero this cambia.

Eso es dinámico.

💥 "Arrow → this es léxico"

¿Qué significa léxico?

"Léxico" significa:

Depende del lugar donde fue escrita la función.

  • No cambia aunque la llames diferente
  • Se queda con el this del entorno que la rodea

🔎 Ejemplo claro

const nombre = "Global";

const obj = {
  nombre: "Roge",
  mostrar: () => {
    console.log(this.nombre);
  }
};

obj.mostrar();

// Resultado en navegador:
// Global

¿Por qué?

Porque la arrow fue definida en el scope global.

Entonces hereda ese this.

No importa que la llames como obj.mostrar().

🎯 Diferencia visual brutal

Function normal

obj.metodo()
👉 this = obj

Si haces:
const fn = obj.metodo;
fn();
👉 this cambia
Arrow Function

const obj = {
  metodo: () => {
    console.log(this);
  }
};

👉 this NO es obj
👉 Es el this del lugar donde se creó
👉 Y no cambia nunca

🧠 Analogía poderosa

Function normal

Es como un actor freelance.

Trabaja para quien lo contrate ese día.

Arrow

Es como un empleado fijo.

Siempre responde al mismo jefe (el contexto donde nació).

🔥 El ejemplo que lo deja todo claro

const persona = {
  nombre: "Roge",
  normal: function () {
    console.log("Normal:", this.nombre);
  },
  arrow: () => {
    console.log("Arrow:", this.nombre);
  }
};

persona.normal();  // Normal: Roge
persona.arrow();   // Arrow: undefined

🧠 Tabla Comparativa Dinámico vs Léxico

                    Function normal    Arrow
¿Cuándo se decide?   En la ejecución     En la definición
¿Puede cambiar?      Sí                  No
Tipo de this         Dinámico            Léxico

🎯 Frase final que debes grabarte

Function normal → this depende de cómo la llamas.

Arrow → this depende de dónde la escribes.

Ejemplo 1 — Caso más simple (objeto)

✅ Function normal

const persona = {
  nombre: "Roge",
  saludar: function () {
    console.log("Hola soy", this.nombre);
  }
};

persona.saludar();

🔎 ¿Qué pasa?

persona.saludar()

Quien ejecuta la función es persona

👉 this === persona

Resultado: Hola soy Roge

❌ Arrow function (mismo código pero con arrow)

const persona = {
  nombre: "Roge",
  saludar: () => {
    console.log("Hola soy", this.nombre);
  }
};

persona.saludar();

🔎 ¿Qué pasa?

Arrow function no tiene su propio this

Toma el this del contexto exterior

En navegador, normalmente será window

👉 this.nombre será undefined

Resultado: Hola soy undefined

⚠️ Aquí empieza la confusión.

Ejemplo 2 — Cambia el invocador

Aquí es donde las function normales "cambian de dueño".

Función extraída (sin objeto)

function mostrar() {
  console.log(this);
}

mostrar();

🔎 ¿Quién la ejecuta?

Nadie en concreto → llamada directa.

En navegador:

👉 this === window

Ahora asigna la función a un objeto

const objeto = {
  mostrar: mostrar
};

objeto.mostrar();

🔎 Ahora ¿quién ejecuta?

objeto

👉 this === objeto

💡 MISMA FUNCIÓN, distinto this.

Esto es lo que más confunde.

Ejemplo 3 — El clásico problema con setTimeout

Function normal dentro de método

const contador = {
  numero: 0,
  incrementar: function () {
    setTimeout(function () {
      console.log(this.numero);
    }, 1000);
  }
};

contador.incrementar();

🔎 ¿Qué pasa?

La función dentro de setTimeout es normal

La ejecuta el sistema (window)

👉 this === window

Resultado: undefined

🔥 Ahora con arrow

const contador = {
  numero: 0,
  incrementar: function () {
    setTimeout(() => {
      console.log(this.numero);
    }, 1000);
  }
};

contador.incrementar();

🔎 ¿Qué cambia?

Arrow no crea nuevo this

Hereda el this de incrementar

Y incrementar fue llamada por contador

👉 this === contador

Resultado: 0

💡 Este es uno de los usos más importantes de arrow functions.

Ejemplo 4 — Método extraído (confusión real)

Función extraída del objeto

const usuario = {
  nombre: "Roge",
  decirNombre: function () {
    console.log(this.nombre);
  }
};

const fn = usuario.decirNombre;

fn();

🔎 ¿Qué pasa?

Ahora no se ejecuta como usuario.decirNombre()

Se ejecuta como fn()

👉 this ya no es usuario

Resultado: undefined

⚠️ Aquí se ve claramente: En funciones normales, this depende de cómo se llama.

Ejemplo 5 — Arrow dentro de clase (muy importante para React)

Arrow methods en clases

class Persona {
  constructor(nombre) {
    this.nombre = nombre;
  }

  saludar = () => {
    console.log(this.nombre);
  };
}

const p = new Persona("Roge");
const fn = p.saludar;
fn();

🔎 ¿Qué pasa?

Arrow guarda el this del constructor

No importa cómo la invoques

Resultado: Roge

🔥 Por eso en React moderno se usan arrow methods.

📊 Diagrama Mental: Estructura de this

Cómo funciona this en una estructura anidada

OBJETO
└── método()  ← función NORMAL
    ├── this = objeto ✅
    └── arrow()  ← arrow function
        └── this = (hereda del método) ✅

📌 Lectura correcta:

  • 🔵 método() → this = objeto (porque la llamó el objeto)
  • 🟡 arrow() → copia el this de método() (porque está dentro)

La arrow NO mira al objeto, mira hacia arriba ⬆️

Ejemplo visual con resultado

const handler = {
  name: "Brais",
  greeting() {
    const arrowGreeting = () => {
      console.log(`Hola, ${this.name}`);
    };
    arrowGreeting();
  }
};

handler.greeting(); // ✅ Hola, Brais

Arrow functions y herencia de this

Sin propio contexto

Las arrow functions no crean su propio this; heredan el del entorno donde se declararon.

const myObject = {
  name: 'MyObject Name',
  getName: () => {
    console.log(this.name);
  }
};

global.name = 'Global Name';
myObject.getName(); // "Global Name" (heredado del ámbito exterior)

Truco Mental para Dominar this

Dibujito Mental

OBJETO
└── método()  ← función NORMAL
    └── arrow()  ← arrow function

Lectura correcta:

  • 🔵 método() → this = objeto
  • 🟡 arrow() → copia el this de método()

📌 Regla clave: La arrow NO mira al objeto, mira hacia arriba

Frase mágica (memorízala)

Arrow function → hereda this

Función normal → this es quien la llama

Test mental rápido (1 segundo)

obj.method();

1️⃣ ¿Tiene =>?

  • → Sí → ❌ this NO es obj
  • → No → ✅ this SÍ es obj

Regla práctica

  • ✅ Arrow → callbacks, setTimeout, map, filter
  • ❌ Arrow → métodos de objetos
  • ✅ Función normal → métodos que usan this

🏆 REGLA FINAL PARA SIEMPRE

🟢 Función normal → this depende de quién llama

🔵 Arrow function → this depende de dónde se define

Cambiar el contexto explícitamente

function getName() {
  console.log(this.name);
}

const myObject = { name: 'MyObject Name' };

getName.call(myObject);  // "MyObject Name"
getName.apply(myObject); // "MyObject Name"

function getName() {
  console.log(this.name);
}

const myObject = { name: 'MyObject Name' };
const boundGetName = getName.bind(myObject);

boundGetName(); // "MyObject Name" siempre

Funciones anidadas y solución con bind

const account = {
  owner: 'Ada',
  printOwner() {
    function inner() {
      console.log(this.owner);
    }
    inner.call(this); // o inner.bind(this)()
  }
};

account.printOwner(); // "Ada"
