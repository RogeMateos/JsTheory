Entendiendo fetch desde cero

La herramienta fundamental para pedir datos desde el navegador

🎯 Qué es fetch en una frase

fetch es una función que te permite hacer solicitudes HTTP

Es la herramienta fundamental cuando quieres pedir datos a una URL desde el navegador.

Aunque solemos usarla para hablar con APIs, en realidad sirve para cualquier recurso disponible en la web: archivos estáticos, imágenes, JSON, HTML, etc.

💡 ¿Qué es una API?

Una API es una interfaz de programación de aplicaciones

Una API permite a los desarrolladores acceder a una fuente de datos o funcionalidades de un sistema.

Por ejemplo:

  • OpenWeather API: te da datos de clima
  • Google Maps API: te da ubicaciones e mapas
  • JSONPlaceholder: API de prueba con posts, usuarios, comentarios
  • PokéAPI: datos de todos los Pokémon

1️⃣ Primer Contacto con fetch

La forma más básica

Simplemente pasamos una URL a fetch y esperamos la respuesta:

fetch('https://jsonplaceholder.typicode.com/todos')
  .then((response) => {
    console.log(response.ok)      // true si la petición salió bien
    console.log(response.status)  // código HTTP, por ejemplo 200
  })

¿Qué es lo que devuelve fetch?

fetch devuelve inmediatamente un objeto especial llamado promesa.

Eso significa que no bloquea tu código: puedes seguir ejecutando otras instrucciones mientras la petición se resuelve.

2️⃣ ¿Por Qué Decimos que fetch es Asíncrono?

fetch funciona de manera asíncrona

Porque tarda un tiempo en recibir la respuesta del servidor.

Analógía: Pedir una pizza 🍕

  1. Haces el pedido → llamas a fetch
  2. La pizzería se pone manos a la obra → el servidor procesa
  3. Tú no te quedas cruzado de brazos → tu código sigue ejecutándose
  4. Puedes ver una serie o hacer deberes mientras esperas → seguir con otras cosas
  5. Cuando la pizza llega, te avisan → la promesa se resuelve
  6. Entonces la comes → usas los datos

Ese "haz algo mientras esperas" es exactamente el comportamiento asíncrono

fetch te avisa más tarde cuando los datos están listos. Tu código no se bloquea esperando.

☝️ Nota importante

También existe la sintaxis async/await para trabajar con código asíncrono de forma más legible. La veremos en profundidad más adelante.

3️⃣ Leer Diferentes Tipos de Respuesta

El objeto Response expone varios métodos útiles

Una vez recibimos la respuesta, podemos decidir en qué formato queremos leerla:

Método Qué hace Cuándo usar
response.json() Interpreta el cuerpo como JSON APIs (la opción más popular)
response.text() Devuelve como cadena de texto HTML, Markdown, archivos de texto
response.blob() Entrega un Blob Imágenes, archivos binarios
response.arrayBuffer() Buffer de bytes Casos avanzados

4️⃣ Ejemplo 1: Consumir una API JSON

Código completo

fetch('https://jsonplaceholder.typicode.com/todos')
  .then((response) => response.json())
  .then((todos) => {
    console.log('Tenemos', todos.length, 'tareas disponibles')
    console.log('Primera tarea:', todos[0])
  })
  .catch((error) => {
    console.error('No pudimos obtener los datos', error)
  })

Paso a paso

  1. fetch(URL) → hace la solicitud a la API
  2. .then((response) => response.json()) → lee la respuesta como JSON
  3. .then((todos) => { ... }) → usamos los datos ya convertidos a objeto JavaScript
  4. .catch((error) => { ... }) → si la petición falla (sin conexión, etc.), manejamos el error

¿Qué recibimos en la consola?

Tenemos 200 tareas disponibles
Primera tarea: {
  userId: 1,
  id: 1,
  title: "delectus aut autem",
  completed: false
}

5️⃣ Ejemplo 2: Cargar HTML local

Código para cargar un archivo HTML

fetch('/legal/terminos.html')
  .then((response) => response.text())
  .then((html) => {
    document.querySelector('#legal').innerHTML = html
  })

¿Qué pasa aquí?

  1. Pedimos el archivo HTML local terminos.html
  2. Lo leemos como texto con response.text()
  3. Insertamos ese HTML en un elemento del DOM

Ninguna API, solo un recurso estático

fetch sirve para cualquier cosa disponible en una URL, no solo APIs.

6️⃣ Ejemplo 3: Cargar datos JSON locales

Si tienes un archivo data.json local

fetch('/repo/content/00-initialize-repo/jobs.json')
  .then((response) => response.json())
  .then((jobs) => {
    console.log('Tenemos', jobs.length, 'ofertas disponibles')
    mostrarOfertas(jobs)
  })
  .catch((error) => {
    console.error('No pudimos obtener los datos', error)
  })

Ahora renderizamos los datos

function mostrarOfertas(jobs) {
  const container = document.querySelector('#jobs-list')

  jobs.forEach((job) => {
    const div = document.createElement('div')
    div.innerHTML = `
      <h3>${job.title}</h3>
      <p>${job.description}</p>
      <p><strong>Salario:</strong> ${job.salary}</p>
    `
    container.appendChild(div)
  })
}

7️⃣ La Estructura Completa: .then() y .catch()

Entendiendo el flujo

fetch(URL)
  .then((response) => {
    // Aquí recibimos la respuesta HTTP
    // Decidimos cómo leerla: .json(), .text(), etc.
    return response.json()
  })
  .then((data) => {
    // Aquí recibimos los datos ya procesados
    // Hacemos algo con ellos
    console.log(data)
  })
  .catch((error) => {
    // Si algo falla en cualquier .then(), llegamos aquí
    console.error('Error:', error)
  })

¿Qué es .catch()?

Es una red de seguridad. Si algo falla:

  • No hay conexión a internet
  • El servidor está caído
  • La URL es incorrecta
  • El JSON es inválido

El .catch() captura el error y lo maneja.

8️⃣ Comprobando si la Petición Fue Exitosa

Importante: fetch NO lanza error en respuestas no-2xx

Aunque el servidor responda con un error (404, 500), fetch considera la promesa como resuelta. Necesitamos verificar manualmente:

fetch('https://api.example.com/data')
  .then((response) => {
    // Verificar si la respuesta fue exitosa
    if (!response.ok) {
      throw new Error(`Error HTTP! status: ${response.status}`)
    }
    return response.json()
  })
  .then((data) => {
    console.log('Datos recibidos:', data)
  })
  .catch((error) => {
    console.error('Algo salió mal:', error)
  })

Propiedades útiles del objeto response

Propiedad Qué es Ejemplo
response.ok true si status está entre 200-299 true o false
response.status Código HTTP de la respuesta 200, 404, 500, etc.
response.headers Encabezados HTTP de la respuesta content-type, etc.
response.url URL final (después de redirecciones) URL real de la respuesta

9️⃣ Ejercicio: Consumir JSONPlaceholder

El reto

Usa fetch para obtener los usuarios de JSONPlaceholder y muéstralos en la consola.

// API a consumir:
// https://jsonplaceholder.typicode.com/users

// Pista: Tendrás que:
// 1. Hacer fetch a la URL
// 2. Convertir la respuesta a JSON
// 3. Mostrar en consola los usuarios obtenidos
// 4. Capturar posibles errores

Solución

fetch('https://jsonplaceholder.typicode.com/users')
  .then((response) => response.json())
  .then((users) => {
    console.log('Usuarios:', users)
    users.forEach((user) => {
      console.log(`${user.id}: ${user.name} (${user.email})`)
    })
  })
  .catch((error) => {
    console.error('Error al obtener usuarios:', error)
  })

🔟 Async/Await: La Forma Moderna (Avance)

Existe una sintaxis más moderna: async/await

Hace que el código asíncrono se vea más síncrono (más fácil de leer):

async function obtenerDatos() {
  try {
    const response = await fetch('https://jsonplaceholder.typicode.com/todos')
    const data = await response.json()
    console.log(data)
  } catch (error) {
    console.error('Error:', error)
  }
}

obtenerDatos()

Comparación: .then() vs async/await

Con .then():

fetch(url)
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err))

Con async/await:

async function getData() {
  const res = await fetch(url)
  const data = await res.json()
  console.log(data)
}

Ambas son equivalentes, pero async/await es más legible.

☝️ Lo aprenderemos en profundidad más adelante

Por ahora, entiende que .then() y async/await son dos formas diferentes de hacer lo mismo.

1️⃣1️⃣ Casos de Uso Comunes

1. Obtener lista de productos de una API

fetch('/api/products')
  .then(res => res.json())
  .then(products => renderProducts(products))

2. Cargar configuración desde un archivo JSON

fetch('/config.json')
  .then(res => res.json())
  .then(config => initApp(config))

3. Cargar un fragmento HTML (header, footer)

fetch('/components/header.html')
  .then(res => res.text())
  .then(html => document.querySelector('header').innerHTML = html)

4. Descargar una imagen como Blob

fetch('/images/photo.jpg')
  .then(res => res.blob())
  .then(blob => {
    const img = document.createElement('img')
    img.src = URL.createObjectURL(blob)
    document.body.appendChild(img)
  })

1️⃣2️⃣ Conceptos Clave para Recordar

1. fetch es asíncrono

No bloquea tu código. Puedes hacer otras cosas mientras esperas la respuesta.

2. fetch devuelve una promesa

Usamos .then() para manejar el resultado.

3. Hay que leer la respuesta

Podemos hacerlo con .json(), .text(), .blob(), etc.

4. Siempre usa .catch()

Para capturar errores en la red, servidor, etc.

5. Verifica response.ok

fetch no lanza error automáticamente si el status es 404 o 500. Debes verificarlo manualmente.

1️⃣3️⃣ Resumen Visual

El flujo de fetch


Usuario:     fetch(URL)
              ↓
Navegador:   Hace solicitud HTTP
              ↓
Servidor:    Procesa y responde
              ↓
Navegador:   Recibe respuesta
              ↓
Tu código:   .then() → Procesa datos
              ↓
HTML/DOM:    Se actualiza

Estructura básica

fetch(URL)
  .then(response => response.json())  // ← Leer como JSON
  .then(data => console.log(data))    // ← Usar datos
  .catch(error => console.error(error)) // ← Manejar errores
