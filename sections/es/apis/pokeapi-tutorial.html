Tutorial paso a paso: consumir la PokeAPI con JavaScript (fetch + async/await)

Proyecto práctico completo

Qué vas a aprender

  • Cómo funciona un endpoint REST con versionado (/api/v2)
  • Cómo hacer una petición GET con fetch
  • Cómo convertir la respuesta a JSON
  • Cómo navegar un JSON (propiedades y arrays)
  • Cómo extraer y mostrar name y abilities
  • Cómo manejar errores de verdad (404, 429, red)
  • Cómo mejorar la UX con validación, cancelación (AbortController) y transformación de datos

1) Preparación rápida: qué endpoint vamos a usar

La PokeAPI funciona por endpoints. El que nos interesa para buscar un Pokémon es:

GET https://pokeapi.co/api/v2/pokemon/{name-or-id}/

Ejemplos:

  • .../pokemon/pikachu/
  • .../pokemon/25/

Nota: No necesitas autenticación (sin API key) para este endpoint.

2) Paso 1 — Tu primera petición con fetch (la versión "mínima")

Esto es lo más básico:

async function getPokemonBasic() {
  const res = await fetch("https://pokeapi.co/api/v2/pokemon/pikachu/");
  const data = await res.json();
  console.log(data);
}

getPokemonBasic();

Qué está pasando:

  • fetch(...) hace la petición HTTP
  • res.json() transforma el body a un objeto JavaScript (JSON)
  • console.log(data) te deja ver el "tocho" de información

3) Paso 2 — Entender el JSON: navegar por propiedades (dot notation)

Una vez tienes data, puedes acceder a propiedades con el punto:

async function showName() {
  const res = await fetch("https://pokeapi.co/api/v2/pokemon/pikachu/");
  const data = await res.json();

  console.log("Nombre:", data.name); // "pikachu"
}

showName();

Idea clave:

Si el JSON tiene una propiedad name, en JS accedes con data.name.

4) Paso 3 — Acceder a arrays: abilities y forEach

En el JSON, abilities es un array. Cada elemento tiene estructura parecida a:

  • ability.name (dentro de cada item)

Ejemplo:

async function showAbilities() {
  const res = await fetch("https://pokeapi.co/api/v2/pokemon/pikachu/");
  const data = await res.json();

  console.log("Habilidades de:", data.name);

  data.abilities.forEach((item) => {
    console.log("-", item.ability.name);
  });
}

showAbilities();

Qué aprendes aquí:

  • data.abilities es un array
  • forEach recorre cada elemento
  • dentro del elemento navegas a item.ability.name

5) Paso 4 — Convertirlo en una función reutilizable (base "pro")

En un tutorial serio, no queremos repetir fetch por todas partes. Creamos una función reutilizable:

const API_BASE = "https://pokeapi.co/api/v2";

function normalizePokemonQuery(value) {
  return value.trim().toLowerCase();
}

async function getPokemon(rawQuery) {
  const query = normalizePokemonQuery(rawQuery);

  if (!query) {
    throw new Error("Introduce el nombre o id de un Pokémon.");
  }

  const url = `${API_BASE}/pokemon/${encodeURIComponent(query)}/`;
  const res = await fetch(url);

  // Importante: fetch NO lanza error por 404/500 automáticamente
  if (!res.ok) {
    if (res.status === 404) throw new Error(`No existe "${query}" en la PokeAPI.`);
    if (res.status === 429) throw new Error("Demasiadas peticiones. Espera y vuelve a intentar.");
    throw new Error(`Error HTTP ${res.status} (${res.statusText})`);
  }

  return res.json();
}

Por qué esto es mejor:

  • trim() y toLowerCase() evitan fallos por escribir "Pikachu " o "PIKACHU"
  • encodeURIComponent evita problemas con caracteres raros
  • res.ok es la diferencia entre "demo" y "producción"
  • throw new Error(...) te deja controlarlo con try/catch

6) Paso 5 — Usar try/catch (manejo de errores real)

Ahora consumimos la función:

async function demo() {
  try {
    const data = await getPokemon("Pikachu");

    console.log("Nombre:", data.name);
    console.log("Habilidades:");
    data.abilities.forEach((item) => console.log("-", item.ability.name));
  } catch (err) {
    console.error("Falló la petición:", err.message);
  }
}

demo();

Diferencias importantes:

  • 404 → lo mostramos como error "humano"
  • 429 → "estás haciendo demasiadas peticiones"
  • error de red → también cae aquí (ej: sin internet)

7) Paso 6 — No acoples tu UI a un JSON enorme (transformación)

En apps reales, no quieres pasar el "tocho" completo a tu UI. Mejor crear un "view model" (objeto limpio):

function mapPokemonToViewModel(pokemon) {
  return {
    id: pokemon.id,
    name: pokemon.name,
    height: pokemon.height,
    weight: pokemon.weight,
    abilities: pokemon.abilities.map((a) => a.ability.name),
    sprite: pokemon.sprites?.front_default ?? null,
  };
}

Uso:

async function demoViewModel() {
  try {
    const data = await getPokemon("pikachu");
    const pokemon = mapPokemonToViewModel(data);

    console.log(pokemon);
    // pokemon.abilities ya es un array de strings
  } catch (err) {
    console.error(err.message);
  }
}

demoViewModel();

Esto te da:

  • datos mínimos y claros
  • menos riesgo de "romper" UI si cambia algo
  • código más fácil para un junior

8) Paso 7 — Extra: cancelar peticiones (AbortController)

Si haces un buscador y el usuario escribe rápido, puede pasar esto:

  • pides "pi"
  • luego "pika"
  • pero "pi" responde después y pisa el resultado correcto

Solución: cancelar la petición anterior.

let controller = null;

async function searchPokemon(query) {
  try {
    if (controller) controller.abort();
    controller = new AbortController();

    const data = await getPokemonWithSignal(query, controller.signal);
    return mapPokemonToViewModel(data);
  } catch (err) {
    if (err.name === "AbortError") return null; // ignorar
    throw err;
  }
}

async function getPokemonWithSignal(rawQuery, signal) {
  const query = normalizePokemonQuery(rawQuery);

  if (!query) throw new Error("Introduce el nombre o id de un Pokémon.");

  const url = `${API_BASE}/pokemon/${encodeURIComponent(query)}/`;
  const res = await fetch(url, { signal });

  if (!res.ok) {
    if (res.status === 404) throw new Error(`No existe "${query}" en la PokeAPI.`);
    if (res.status === 429) throw new Error("Demasiadas peticiones. Espera y vuelve a intentar.");
    throw new Error(`Error HTTP ${res.status} (${res.statusText})`);
  }

  return res.json();
}

9) Errores típicos (y cómo evitarlos)

❌ "Mi catch no se ejecuta con 404"

Causa: Porque fetch no hace throw por 404.

Solución: if (!res.ok) throw ...

❌ "Me da undefined en sprites"

Causa: Algunos campos pueden ser null.

Solución: pokemon.sprites?.front_default ?? null

❌ "El usuario escribe con espacios o mayúsculas y falla"

Solución: trim() + toLowerCase()

❌ "Demasiadas peticiones"

Causa: Puede aparecer 429 si spameas.

Solución: debounce, cache, paginar, o esperar.

✅ Resumen de conceptos clave

  • Endpoint versionado: /api/v2/pokemon/
  • fetch + async/await: forma moderna de hacer peticiones
  • res.ok: verifica que la respuesta sea exitosa (200-299)
  • Normalización: trim() y toLowerCase() para inputs de usuario
  • View Model: transforma datos complejos en objetos simples para UI
  • AbortController: cancela peticiones pendientes
  • Manejo de errores específicos: 404, 429, errores de red
