Introducción a las APIs REST (Paso a Paso)

Cuando empezamos a desarrollar aplicaciones, nos encontramos rápidamente con una realidad: hay muchísimos lenguajes, muchísimos frameworks y muchísimas herramientas.

Entonces surge una pregunta clave:

👉 ¿Cómo se comunican entre sí sistemas diferentes?

Aquí es donde entran en juego las APIs.

1. ¿Qué es una API?

Una API (Application Programming Interface) es un contrato que permite que dos sistemas se comuniquen entre sí.

  • Un frontend (por ejemplo, una app en JavaScript)
  • Un backend (por ejemplo, en Python, Java o Node.js)

No necesitan estar escritos en el mismo lenguaje.
Solo necesitan hablar el mismo idioma.

Ese idioma son los estándares.

2. Tipos de APIs (visión general)

Existen diferentes tipos de APIs:

  • SOAP (muy usado hace 15–20 años)
  • REST (el más común en desarrollo web)
  • GraphQL
  • gRPC

En este tutorial nos vamos a centrar en APIs REST, porque son las más utilizadas en aplicaciones web modernas.

3. ¿Qué es una API REST?

REST no es una tecnología concreta, es un estilo arquitectónico.

En la práctica, una API REST suele cumplir estas características:

  • Usa el protocolo HTTP
  • Accede a datos mediante URLs
  • Trabaja con recursos (no con acciones)
  • Es stateless (sin estado)
  • Normalmente intercambia datos en formato JSON

4. HTTP y URLs: la base de todo

Cuando entras en una web, ya estás usando HTTP:

  • Protocolo: https://
  • Dirección: www.ejemplo.com

Las APIs REST usan exactamente lo mismo.

Ejemplos de URLs en una API:

  • /users
  • /users/42
  • /products
  • /orders/123

Cada URL representa un recurso.

5. Qué es un recurso (concepto clave)

Un error muy común al empezar es pensar que una URL es una función.

En REST, una URL representa un sustantivo, no un verbo.

Ejemplos correctos:

  • /users
  • /users/10
  • /todos

Ejemplos incorrectos:

  • /getUsers
  • /createUser
  • /deleteProduct

👉 Las acciones las define el método HTTP, no el nombre de la URL.

6. Métodos HTTP y su significado

Los métodos HTTP indican qué queremos hacer con el recurso.

Los más importantes:

  • GET → Obtener datos
  • POST → Crear un recurso
  • PUT → Reemplazar un recurso completo
  • PATCH → Modificar parcialmente
  • DELETE → Eliminar un recurso

Ejemplos:

  • GET /users → obtener todos los usuarios
  • GET /users/5 → obtener el usuario 5
  • POST /users → crear un usuario
  • PATCH /users/5 → modificar el usuario 5
  • DELETE /users/5 → borrar el usuario 5

7. JSON: el formato para intercambiar datos

Las APIs REST suelen intercambiar datos usando JSON
(JSON = JavaScript Object Notation).

JSON es:

  • Texto plano
  • Ligero
  • Fácil de leer
  • Independiente del lenguaje

Ejemplo de JSON:

{
  "id": 1,
  "name": "Roge",
  "email": "roge@email.com"
}

Aunque se parece a un objeto JavaScript, no es un objeto JS, es texto con reglas.

8. Request y Response (cómo fluye la comunicación)

Una comunicación REST siempre sigue este flujo:

  1. El cliente envía una request
  2. El servidor procesa la petición
  3. El servidor responde con una response

Ejemplo real

Request:

  • Método: GET
  • URL: /users/1

Response:

  • Status: 200 OK
  • Body:
{
  "id": 1,
  "name": "Roge"
}

9. Status Codes (importantísimo)

Los status codes indican qué ha pasado con la petición.

Algunos esenciales:

  • 200 OK → Todo correcto
  • 201 Created → Recurso creado
  • 204 No Content → Éxito sin contenido
  • 400 Bad Request → Datos incorrectos
  • 401 Unauthorized → No autenticado
  • 403 Forbidden → Sin permisos
  • 404 Not Found → No existe
  • 500 Internal Server Error → Error del servidor

👉 El frontend no debería adivinar qué pasó: el status code lo dice.

10. Stateless: sin estado

Una API REST suele ser stateless.

Esto significa que:

  • Cada request es independiente
  • El servidor no "recuerda" peticiones anteriores
  • Toda la información necesaria viaja en cada request

Ejemplo:

  • El token de autenticación se envía en cada request
  • El servidor no depende de una sesión en memoria

Esto hace que las APIs REST sean escalables y simples.

11. Headers más comunes

Además del body, las requests incluyen headers.

Algunos muy habituales:

  • Content-Type: application/json
  • Accept: application/json
  • Authorization: Bearer TOKEN

Muchísimos problemas reales vienen de headers mal configurados.

12. Ejemplo completo de API REST

Obtener tareas

GET /todos

Response:

[
  { "id": 1, "title": "Comprar pan", "done": false },
  { "id": 2, "title": "Estudiar REST", "done": true }
]

Crear una tarea

POST /todos

Request body:

{
  "title": "Ir al gym",
  "done": false
}

Response:

  • Status: 201 Created
{
  "id": 3,
  "title": "Ir al gym",
  "done": false
}

13. Por qué REST funciona tan bien

REST se ha convertido en el estándar de facto porque:

  • Se basa en HTTP (ya existente)
  • Es simple de entender
  • Es flexible
  • Funciona igual entre cualquier lenguaje
  • Es ideal para aplicaciones web y móviles

Un frontend en JavaScript puede comunicarse sin problemas con un backend en Python, Java o Go gracias a estos estándares.

14. Resumen final

  • Una API es un contrato entre sistemas
  • REST es un estilo para diseñar APIs
  • Usa HTTP, URLs y métodos estándar
  • Trabaja con recursos
  • Intercambia datos normalmente en JSON
  • Es simple, escalable y muy usada en la web moderna
