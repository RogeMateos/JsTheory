Métodos HTTP adicionales: PATCH y OPTIONS

Hasta ahora hemos visto los métodos HTTP más comunes:

  • GET → Obtener datos
  • POST → Crear un recurso
  • PUT → Actualizar un recurso completo
  • DELETE → Eliminar un recurso

Pero el protocolo HTTP define más métodos, y dos de los más importantes que también se usan en APIs REST son:

  • PATCH
  • OPTIONS

Vamos a ver qué hacen y cuándo usarlos, con un ejemplo sencillo.

1️⃣ PATCH – Actualizar parcialmente un recurso

¿Qué significa "actualizar parcialmente"?

Actualizar parcialmente un recurso significa modificar solo una parte concreta del recurso, sin tener que enviar todos sus datos.

📌 Ejemplo real:

Tienes un post con muchos campos:

  • id
  • title
  • body
  • author
  • date

Y solo quieres cambiar el título.

PATCH vs PUT (diferencia clave)

PUT (actualización completa)

  • Se envía todo el objeto
  • Si falta un campo, puede sobrescribirse o perderse
  • Ideal cuando reemplazas el recurso entero

PATCH (actualización parcial)

  • Se envía solo lo que cambia
  • El resto del recurso permanece igual
  • Ideal para cambios pequeños y específicos

👉 Esta diferencia también ayuda a los desarrolladores a entender la intención de la operación solo viendo el método HTTP.

2️⃣ Ejemplo práctico: actualizar solo el título de un post

Paso 1: URL correcta

Cuando actualizamos un recurso, ya no usamos solo /posts, sino:

/posts/10 → para actualizar el post con id 10

Paso 2: Método HTTP

Usamos PATCH, porque la actualización es parcial.

Paso 3: Body de la petición

Como solo queremos cambiar el título, no enviamos el objeto completo.

Ejemplo conceptual del body:

{
  "title": "Nuevo título del post"
}

Eso es todo.
No enviamos body, ni author, ni nada más.

Paso 4: Respuesta del servidor

El servidor:

  • Mantiene todos los datos originales
  • Actualiza únicamente el campo title
  • Devuelve el recurso completo ya actualizado

📌 Resultado esperado:

  • El post sigue teniendo el mismo contenido
  • El título ahora es el nuevo

3️⃣ Código completo con fetch (PATCH)

async function updatePostTitle(postId, newTitle) {
  const url = `https://jsonplaceholder.typicode.com/posts/${postId}`;

  const response = await fetch(url, {
    method: 'PATCH',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      title: newTitle
    })
  });

  if (!response.ok) {
    throw new Error(`HTTP error ${response.status}`);
  }

  const updatedPost = await response.json();
  console.log('Post actualizado:', updatedPost);
  return updatedPost;
}

// Usar la función
updatePostTitle(1, 'Mi nuevo título increíble');

4️⃣ OPTIONS – Descubrir qué métodos acepta un endpoint

¿Qué hace OPTIONS?

OPTIONS es un método que pregunta al servidor:
"¿Qué operaciones puedo hacer en este endpoint?"

No modifica datos, solo devuelve información sobre:

  • Qué métodos HTTP están permitidos (GET, POST, PUT, PATCH, DELETE...)
  • Qué headers son aceptados
  • Si permite CORS

¿Cuándo se usa?

  • CORS preflight: El navegador envía automáticamente una petición OPTIONS antes de hacer POST/PUT/DELETE desde otro dominio
  • Exploración de API: Para saber qué puedes hacer sin tener que probar
  • Debugging: Para validar configuración de CORS

5️⃣ Ejemplo con OPTIONS

async function checkEndpointOptions(url) {
  const response = await fetch(url, {
    method: 'OPTIONS'
  });

  // Ver qué métodos están permitidos
  const allowedMethods = response.headers.get('Allow');
  console.log('Métodos permitidos:', allowedMethods);

  // Ver headers CORS
  const corsHeaders = response.headers.get('Access-Control-Allow-Methods');
  console.log('CORS permite:', corsHeaders);
}

checkEndpointOptions('https://jsonplaceholder.typicode.com/posts/1');

Respuesta típica de OPTIONS:

Allow: GET, POST, PUT, PATCH, DELETE, OPTIONS
Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization

6️⃣ Tabla resumen de métodos HTTP

Método Propósito Body Idempotente
GET Leer datos No Sí
POST Crear recurso Sí No
PUT Reemplazar completo Sí Sí
PATCH Actualizar parcial Sí No*
DELETE Eliminar No Sí
OPTIONS Consultar métodos No Sí

* PATCH puede ser idempotente dependiendo de la implementación

7️⃣ Cuándo usar cada método (guía práctica)

Usa GET cuando:

  • Solo quieres leer información
  • No vas a modificar nada en el servidor

Usa POST cuando:

  • Creas un recurso nuevo
  • Ejecutas una acción que no es idempotente

Usa PUT cuando:

  • Reemplazas un recurso completo
  • Tienes todos los datos del recurso

Usa PATCH cuando:

  • Solo modificas algunos campos
  • No quieres enviar el objeto completo

Usa DELETE cuando:

  • Quieres eliminar un recurso

Usa OPTIONS cuando:

  • Necesitas saber qué métodos acepta un endpoint
  • Debugueas problemas de CORS

8️⃣ Resumen clave

  • PATCH es ideal para actualizaciones parciales (solo envías lo que cambia)
  • PUT es para reemplazar el recurso completo
  • OPTIONS te dice qué puedes hacer en un endpoint
  • Usar el método correcto hace tu código más claro y semántico
