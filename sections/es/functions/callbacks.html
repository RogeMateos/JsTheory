Callbacks en JavaScript

¿Qué es un Callback?

Un callback es una función que se pasa como argumento a otra función, para ejecutarse más tarde (normalmente cuando algo termina).

Es como decir: "Cuando estés listo, llama a ESTA función".

Ejemplo Simple (sin asincronía)


function procesarDato(dato, callback) {
  callback(dato);
}

procesarDato("Hola", (mensaje) => {
  console.log("Mensaje:", mensaje);
});
// Output: Mensaje: Hola

¿Qué pasa aquí?

  1. Llamas procesarDato("Hola", ...)
  2. callback es la función que pasaste
  3. Dentro se ejecuta: callback(dato)
  4. Imprime: Mensaje: Hola

💡 Ver explicación detallada en ChatGPT

Código Síncrono vs Asíncrono

Código Síncrono (bloquea el hilo)

El código se ejecuta línea por línea, y cada línea "termina" antes de pasar a la siguiente.


console.log("A");
console.log("B");
console.log("C");

// Output:
// A
// B
// C

Código Asíncrono (no bloquea)

Hay operaciones que JavaScript no ejecuta en ese momento, sino que dice: "esto lo haré más tarde, cuando pueda".

Ejemplos típicos:

  • Temporizadores (setTimeout)
  • Peticiones a red (fetch)
  • Eventos (click)
  • Lectura de archivos (Node.js)

Primer Contacto con Asincronía: setTimeout

setTimeout recibe:

  • Función callback (lo que quieres ejecutar)
  • Tiempo en ms (cuándo)

setTimeout(() => {
  console.log("Esto se ejecuta después");
}, 2000);

El Ejemplo Clave: ¿Por qué sale "Inicio, Fin, Esto..."?


console.log("Inicio");

setTimeout(() => {
  console.log("Esto se ejecuta");
}, 0);

console.log("Fin");

Salida real:

Inicio
Fin
Esto se ejecuta

Corrección Importante

Esto NO es ejecución "síncrona".
setTimeout siempre es asíncrono (aunque pongas 0).

Las Piezas del Motor: Call Stack, Web APIs, Task Queue, Event Loop

1. Call Stack (Pila de llamadas)

  • Donde se ejecuta el código síncrono
  • Es una pila: el último que entra, sale primero

2. Web APIs

El navegador (o Node) ofrece "herramientas externas" como:

  • setTimeout
  • fetch
  • Eventos del DOM

JavaScript dice: "Oye navegador, encárgate tú del temporizador".

3. Task Queue (Cola de tareas / MacroTasks)

Cuando el temporizador termina, su callback no se ejecuta directamente.
Se mete en una cola esperando turno.

4. Event Loop

Es como el "controlador de tráfico":

  • Mira si el Call Stack está vacío
  • Si lo está, toma una tarea de la cola y la mete al Call Stack

Paso a Paso del Ejemplo "Inicio / Fin / Esto..."


console.log("Inicio");

setTimeout(() => {
  console.log("Esto se ejecuta");
}, 0);

console.log("Fin");

Paso 1

console.log("Inicio") entra al Call Stack → se ejecuta → sale

Imprime: Inicio

Paso 2

setTimeout(...) entra al Call Stack → registra el temporizador en Web APIs → sale

⚠️ El callback NO se ejecuta aquí.

Paso 3

console.log("Fin") entra al Call Stack → se ejecuta → sale

Imprime: Fin

Paso 4

Ahora el Call Stack está vacío.
El temporizador ya terminó (0ms) → su callback está en Task Queue.
Event Loop lo mete al Call Stack.

Se ejecuta: Esto se ejecuta

✅ Por eso sale al final.

setTimeout con Tiempo Real (2 segundos)


console.log("Inicio");

setTimeout(() => {
  console.log("Esto se ejecuta después de 2s");
}, 2000);

console.log("Fin");

Salida:

Inicio
Fin
(espera 2s)
Esto se ejecuta después de 2s

Encadenar Tareas Asíncronas con Callbacks

Vamos a crear tres funciones asíncronas:


function stepOne(callback) {
  setTimeout(() => {
    console.log("Paso 1 completado");
    callback();
  }, 1000);
}

function stepTwo(callback) {
  setTimeout(() => {
    console.log("Paso 2 completado");
    callback();
  }, 1000);
}

function stepThree(callback) {
  setTimeout(() => {
    console.log("Paso 3 completado");
    callback();
  }, 1000);
}

Caso A: Lanzarlas "en paralelo" (no dependen)


stepOne(() => console.log("Termina stepOne"));
stepTwo(() => console.log("Termina stepTwo"));
stepThree(() => console.log("Termina stepThree"));

Esto puede terminar en orden distinto dependiendo del tiempo de cada una.

Caso B: Dependen (1 → 2 → 3)

Aquí nace el patrón típico:


stepOne(() => {
  stepTwo(() => {
    stepThree(() => {
      console.log("Todos los pasos completados");
    });
  });
});

Salida (aprox):

Paso 1 completado
Paso 2 completado
Paso 3 completado
Todos los pasos completados

Resultado

✅ Funciona perfecto.
❌ Pero el código empieza a "irse a la derecha" (anidación).

Callback Hell: Qué es y Por Qué Pasa

Definición

Callback Hell ocurre cuando:

  • Tienes varias tareas asíncronas
  • Cada una depende de la anterior
  • Y las encadenas con callbacks anidados

Resultado:

  • Código difícil de leer
  • Difícil de mantener
  • Difícil de depurar
  • Difícil de manejar errores

Ejemplo "infierno" (más realista):


login(user, () => {
  getProfile(() => {
    getOrders(() => {
      processPayment(() => {
        console.log("todo listo");
      });
    });
  });
});

No es que sea imposible:
es que para humanos es una pesadilla.

Por Qué Esto Empuja a Promesas

Para solucionar el caos:

  • Nacen las Promesas
  • Y después llega async/await

Así se vería con promesas (solo como adelanto):


stepOnePromise()
  .then(stepTwoPromise)
  .then(stepThreePromise)
  .then(() => console.log("Todos los pasos completados"));

💡 Y con async/await es todavía más legible (lo verás en el siguiente capítulo).

Resumen Final

Conceptos Clave

  • Callback: función pasada a otra función para ejecutarse después
  • setTimeout es asíncrono siempre, incluso con 0
  • Call Stack ejecuta lo síncrono
  • Web APIs manejan timers/red/eventos
  • Task Queue guarda callbacks listos
  • Event Loop mete tareas al stack cuando está vacío
  • Callback Hell = demasiada anidación por dependencias

Pregunta de Entrevista

¿Por qué setTimeout(..., 0) no se ejecuta "al instante"?

Porque setTimeout siempre es asíncrono. El callback se registra en Web APIs, luego pasa a la Task Queue, y el Event Loop solo lo ejecuta cuando el Call Stack está vacío.
