Event Bubbling y Event Delegation

Entendiendo cómo se propagan los eventos en JavaScript

🎯 Definición Simple para Entrevistas

Event Bubbling (Propagación de Eventos)

Cuando haces click en un elemento, el evento sube por el árbol del DOM.

Es como lanzar una piedra en un estanque: las olas suben desde el elemento clicado hacia sus padres.

Event Delegation (Delegación de Eventos)

En vez de poner un listener en cada elemento, pones UN SOLO listener en el padre y dejas que el bubbling te diga qué elemento fue clicado.

Es como un portero: en vez de tener un portero en cada puerta, tienes uno en la entrada que dice "por cuál puerta entró la gente".

🌊 Event Bubbling (Propagación de Eventos)

¿Qué sucede cuando haces click?

El evento no se queda en el elemento donde hiciste click. Sube hacia los elementos padres.

<div class="contenedor">
  <button class="boton">Haz click</button>
</div>

Orden del bubbling

Cuando haces click en el botón:

1. Click en button
2. Sube a div.contenedor
3. Sube a body
4. Sube a html
5. Llega a document

Ejemplo práctico

// Si pones listeners en todos los niveles:

document.addEventListener('click', () => {
  console.log('1. document')
})

document.body.addEventListener('click', () => {
  console.log('2. body')
})

document.querySelector('.contenedor').addEventListener('click', () => {
  console.log('3. contenedor')
})

document.querySelector('.boton').addEventListener('click', () => {
  console.log('4. boton')
})

// Al hacer click en el botón, ve esto en consola:
// 4. boton
// 3. contenedor
// 2. body
// 1. document

⚡ Punto clave

El bubbling ocurre siempre, aunque no haya listeners arriba.

Es un comportamiento del navegador, no del JavaScript.

🧠 Event Delegation (Delegación de Eventos)

❌ El problema sin delegación

Imagina que tienes una lista de 100 botones:

<ul class="jobs-list">
  <li><button class="button-apply">Aplicar</button></li>
  <li><button class="button-apply">Aplicar</button></li>
  <li><button class="button-apply">Aplicar</button></li>
  <!-- ... 97 botones más -->
</ul>

Enfoque tradicional (ineficiente)

const botones = document.querySelectorAll('.button-apply')

botones.forEach((boton) => {
  boton.addEventListener('click', function () {
    boton.textContent = '¡Aplicado!'
    boton.disabled = true
  })
})

// Problema: 100 listeners para 100 botones
// Y si agregas dinámicamente un nuevo botón... no tiene listener

✅ Solución: Delegación de Eventos

En vez de listeners en cada botón, un solo listener en el contenedor padre.

const jobsList = document.querySelector('.jobs-list')

jobsList.addEventListener('click', function (event) {
  // Busca el botón más cercano al elemento clicado
  const boton = event.target.closest('.button-apply')

  // Si no es un botón, sal
  if (!boton) return

  // Si es un botón, haz algo
  boton.textContent = '¡Aplicado!'
  boton.disabled = true
})

🎯 ¿Por qué funciona?

  • Haces click en el botón
  • El evento bublea hacia arriba
  • Llega al contenedor que tiene el listener
  • El listener pregunta: "¿Es un .button-apply?"
  • Si sí → ejecuta el código

🧰 Herramientas importantes: event.target vs event.currentTarget

¿Qué es event.target?

El elemento donde realmente hiciste click.

<div class="contenedor">
  <button class="boton">Haz click</button>
</div>
document.querySelector('.contenedor').addEventListener('click', (event) => {
  console.log(event.target) // ← El botón
})

¿Qué es event.currentTarget?

El elemento que tiene el listener.

document.querySelector('.contenedor').addEventListener('click', (event) => {
  console.log(event.currentTarget) // ← El contenedor
})

📝 Resumen mental

target = Dónde hiciste click

currentTarget = Dónde está el listener

🎯 .closest() — La herramienta clave para delegación

⚠️ El problema

Si el botón tiene un elemento dentro (como un span), event.target será el span, no el botón:

<button class="button-apply">
  <span>Aplicar</span>
</button>
// Si haces click en el span:
event.target // ← Es el <span>, no el <button>

// Esto falla:
if (event.target.classList.contains('button-apply')) {
  // No entra porque event.target es el span
}

✅ Solución: .closest()

.closest() sube por el DOM hasta encontrar el elemento que buscas.

const boton = event.target.closest('.button-apply')

// Esto funciona aunque hayas clicado en el span
// Porque .closest() sube hasta encontrar .button-apply

Cómo funciona .closest()

event.target = <span>
     ↓
.closest('.button-apply')
     ↓
Sube hasta encontrar un elemento con esa clase
     ↓
Devuelve <button class="button-apply">

⚡ stopPropagation() — Detener el bubbling

¿Qué hace?

Detiene que el evento siga subiendo por el DOM.

boton.addEventListener('click', (event) => {
  event.stopPropagation()
  // El evento NO sigue subiendo
  // El listener del padre NO se ejecuta
})

✔️ Cuándo usarlo

  • Modales (para que no cierren cuando haces click dentro)
  • Dropdowns (para mantenerlos abiertos)
  • Componentes aislados

❌ Cuándo evitarlo

Si usas mucho stopPropagation(), puedes romper lógica global:

// Listener global para cerrar menú
document.addEventListener('click', cerrarMenu)

// Si detienes el bubbling aquí...
boton.addEventListener('click', (event) => {
  event.stopPropagation()
})

// ❌ El listener global nunca se ejecuta

🏆 Patrón Profesional de Delegación

Separar lógica

// 1. Función que maneja la lógica
function handleApplyClick(boton) {
  boton.textContent = '¡Aplicado!'
  boton.disabled = true
}

// 2. Listener delegado que usa esa función
const jobsList = document.querySelector('.jobs-list')

jobsList.addEventListener('click', (event) => {
  const boton = event.target.closest('.button-apply')
  if (!boton) return

  handleApplyClick(boton)
})

¿Por qué es mejor?

  • ✅ Código más limpio
  • ✅ Fácil de testear
  • ✅ Reutilizable
  • ✅ Mantenible

📊 Comparación: Cuándo usar qué

🟢 Usa Delegación
  • Listas dinámicas
  • 10+ elementos
  • Apps escalables
  • UI que cambia
🔵 Usa Listeners individuales
  • 1–3 elementos
  • Elementos estáticos
  • Prototipos rápidos
  • Elementos únicos
