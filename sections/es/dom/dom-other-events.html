Más eventos en JavaScript

input, blur, submit, preventDefault y keydown

🔄 Introducción

Más allá de click y change

Por ahora hemos visto los eventos click y change pero existen muchos más eventos que podemos usar para interactuar con el usuario. No vamos a poder verlos todos, pero vamos a ver algunos importantes y vamos a explicar el concepto de preventDefault.

♿ Una nota sobre accesibilidad

🏷️ El label es esencial

Por temas de accesibilidad, cada elemento input debería tener asociada una etiqueta label para que los lectores de pantalla y otras tecnologías asistivas puedan identificar correctamente el propósito del campo.

Este elemento es el más importante a la hora de crear formularios accesibles.

<label for="input-nombre">Nombre</label>
<input type="text" id="input-nombre" />

O también podés anidar el input dentro del label:

<label>
  Nombre
  <input type="text" id="input-nombre" />
</label>

En los ejemplos de este curso obviamos las etiquetas label para mantener el código más simple y evitar repetición, pero en producción siempre deberías usarlas.

⌨️ Evento input

¿Cuándo se dispara?

El evento input se ejecuta cuando el usuario escribe en un input.

<input type="text" id="input-nombre" />

✅ Ejemplo

const inputNombre = document.getElementById('input-nombre')

inputNombre.addEventListener('input', function () {
  console.log('Escribiendo...')
})

⚠️ Tené en cuenta

Por "escribir" también se entiende que el usuario está borrando el texto. El evento input se dispara con cualquier cambio en el contenido del campo.

👁️ Evento blur

¿Cuándo se dispara?

El evento blur se ejecuta cuando el usuario pierde el foco del input. Es muy útil, por ejemplo, para validar que el usuario ha rellenado todos los campos del formulario antes de enviarlo.

<input type="text" id="input-nombre" />

✅ Ejemplo

const inputNombre = document.getElementById('input-nombre')

inputNombre.addEventListener('blur', function () {
  console.log('Perdió el foco')
})

🔄 El evento contrario: focus

El evento contrario a blur es focus, que se ejecuta cuando el input recibe el foco del usuario.

📤 Evento submit

¿Cuándo se dispara?

El evento submit se ejecuta cuando el usuario envía el formulario.

<form id="formulario">
  <input name="nombre" type="text" id="input-nombre" />
  <button type="submit">Enviar</button>
</form>

✅ Escuchando el submit

const formulario = document.getElementById('formulario')

formulario.addEventListener('submit', function (event) {
  console.log('Formulario enviado')
})

🤔 ¿Cómo se hace submit de un formulario?

Hay principalmente dos formas:

  • Pulsando el botón de tipo submit que esté dentro del formulario.
  • Pulsando la tecla Enter mientras un input dentro del formulario tiene el foco.

❌ El problema: la página se recarga

Si probás el código anterior, te vas a encontrar con que al hacer submit la página se recarga y añade en la URL el valor del input nombre.

Este es el comportamiento por defecto del navegador y, aunque en JavaScript hayamos escuchado el evento submit, el navegador sigue recargando la página.

🛑 event.preventDefault()

✅ La solución

Para evitar la recarga, podemos usar el método preventDefault del evento:

formulario.addEventListener('submit', function (event) {
  event.preventDefault()
  console.log('Formulario enviado')
})

💡 ¿Qué hace exactamente?

Esto quiere decir que queremos prevenir el comportamiento por defecto del evento.

Esto no es único de los formularios. Por ejemplo, los enlaces por defecto al hacer click sobre ellos hacen que el navegador se dirija a la URL del enlace, pero también podemos prevenir ese comportamiento.

🎹 Evento keydown

¿Cuándo se dispara?

El evento keydown se ejecuta cuando el usuario presiona una tecla.

<input type="text" id="input-nombre" />

✅ Ejemplo

// Al escuchar directamente en el documento, podemos escuchar todas las teclas
// que se pulsen independientemente de dónde esté el foco
document.addEventListener('keydown', function (event) {
  console.log('Tecla presionada:', event.key)
})

🔄 El evento contrario: keyup

El evento contrario a keydown es keyup, que se ejecuta cuando el usuario suelta una tecla.

📋 Propiedades del evento de teclado

El evento nos trae información importante sobre la tecla:

  • event.key: La tecla presionada.
  • event.code: El código de la tecla.
  • event.shiftKey: Si se está presionando la tecla Shift.
  • event.ctrlKey: Si se está presionando la tecla Ctrl.
  • event.altKey: Si se está presionando la tecla Alt.
  • event.metaKey: Si se está presionando la tecla Meta (Cmd en Mac).
