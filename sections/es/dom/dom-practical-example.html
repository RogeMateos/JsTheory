Proyecto práctico: HTML + JavaScript + DOM

Configuración real de un proyecto con el DOM

Concepto clave (antes de empezar)

El DOM solo existe en el navegador.

JavaScript puede ejecutarse en muchos entornos (Node.js, navegador, etc.), pero document solo existe cuando el JS se ejecuta dentro de una página web.

1️⃣ Crear la estructura básica del proyecto

Creamos una carpeta con dos archivos:

dom-example/
 ├── dom-example.html
 └── dom-example.js

2️⃣ Crear el HTML (dom-example.html)

Este HTML será simple pero real, suficiente para practicar DOM.

<!doctype html>
<html lang="es">
  <head>
    <meta charset="UTF-8" />
    <title>HTML de ejemplo</title>

    <!-- Cargamos el JS externo -->
    <script src="./dom-example.js" defer></script>
  </head>

  <body>
    <h1 id="title">Mi título</h1>
    <button id="btn">Mi botón</button>
  </body>
</html>

🧩 Qué está pasando aquí

  • <!doctype html> → indica que es HTML moderno
  • <meta charset="UTF-8"> → soporta acentos y caracteres especiales
  • id="title" y id="btn" → nos permiten acceder a estos elementos desde JS
  • defer → garantiza que el DOM esté cargado antes de ejecutar el JS

👉 Buena práctica moderna: usar defer en scripts externos.

3️⃣ Servir el HTML en el navegador (Live Server)

¿Por qué no basta con abrir el archivo?

Aunque podrías abrir el HTML directamente, trabajar con servidor local es lo correcto.

Pasos:

  1. Instala la extensión Live Server en VS Code
  2. Click derecho sobre dom-example.html
  3. Selecciona "Open with Live Server"

Resultado:

  • ✅ Se abre el navegador
  • ✅ URL tipo: http://127.0.0.1:5500/dom-example.html
  • ✅ Ves el título y el botón

✅ Ya tienes una página web real.

4️⃣ Primer contacto con JavaScript y el DOM

Abrimos dom-example.js:

console.log("Mi script cargó");

¿Dónde aparece este log?

  • ❌ NO en la terminal de VS Code
  • ✅ SÍ en el navegador → Inspect → Console

🔑 Regla de oro:

Si el JS se carga desde HTML, se ejecuta en el navegador.

5️⃣ Acceder al documento (document)

Ahora sí: el DOM existe.

console.log(document);

Qué estás viendo

  • document representa toda la página HTML
  • Es un objeto con nodos, propiedades y métodos
  • Es la puerta de entrada al DOM

6️⃣ Acceder a un elemento del DOM

Vamos a buscar el <h1> usando su id.

const title = document.querySelector("#title");
console.log(title);

Qué devuelve querySelector

  • Devuelve el primer elemento que coincide
  • Si no existe → devuelve null

Por eso siempre es buena práctica comprobar:

if (!title) {
  console.error("No se encontró el elemento #title");
}

7️⃣ Leer y modificar contenido del DOM

Leer el texto

console.log(title.textContent);

Salida:

Mi título

Modificar el texto

title.textContent = "Mi nuevo título";

🔄 Al refrescar la página:

  • El texto cambia en tiempo real
  • El HTML original no se modifica, solo el DOM en memoria

8️⃣ Interacción real: eventos del usuario

Ahora vamos a reaccionar a una acción del usuario.

const btn = document.querySelector("#btn");

btn.addEventListener("click", () => {
  title.textContent = "Has hecho click ✅";
});

Qué está pasando aquí

  1. Escuchamos el evento click
  2. Cuando ocurre:
    • Se ejecuta la función
    • Se modifica el DOM

Esto es JavaScript interactuando con la web

9️⃣ Código final completo (JS)

console.log("Mi script cargó");

const title = document.querySelector("#title");
const btn = document.querySelector("#btn");

if (!title || !btn) {
  console.error("Faltan elementos en el HTML");
} else {
  console.log("Texto inicial:", title.textContent);

  title.textContent = "Mi nuevo título";

  btn.addEventListener("click", () => {
    title.textContent = "Has hecho click ✅";
  });
}

🔥 Error típico: "document is not defined"

❌ Esto NO funciona:

node dom-example.js

❓ Por qué falla

  • Node.js no tiene DOM
  • document solo existe en el navegador
  • El contexto lo crea el HTML

✅ El HTML carga al JavaScript, no al revés.
