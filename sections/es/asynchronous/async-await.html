Async/Await en JavaScript 🚀

Por qué

Esperar resultados (APIs, archivos, DB) sin bloquear el hilo. Async/await simplifica leer/escribir código asíncrono.

Reglas de oro

  1. async hace que la función devuelva una promesa.
  2. await pausa hasta que la promesa se resuelve/rechaza.
  3. Solo se usa await dentro de funciones async.

Helper de espera

const wait = (ms) => new Promise(res => setTimeout(res, ms));

Ejemplo básico

async function process() {
  console.log("Inicio");
  await wait(2000); // espera 2s
  console.log("Fin (tras 2s)");
}

process();

Varios awaits

async function steps() {
  console.log("Paso 1");
  await wait(1000);
  console.log("Paso 2");
  await wait(500);
  console.log("Paso 3");
}

Consumir APIs

async function getData() {
  try {
    const res = await fetch('https://api.example.com/data');
    if (!res.ok) throw new Error(res.status);
    const data = await res.json();
    console.log(data);
  } catch (err) {
    console.error("Error:", err.message);
  }
}

En paralelo con Promise.all

async function loadAll(userId) {
  const [user, posts, friends] = await Promise.all([
    fetchUser(userId),
    fetchPosts(userId),
    fetchFriends(userId)
  ]);
  return { user, posts, friends };
}

Comparación

// Con promesas
fetch('url')
  .then(r => r.json())
  .then(data => console.log(data))
  .catch(console.error);

// Con async/await
async function getData() {
  try {
    const r = await fetch('url');
    const data = await r.json();
    console.log(data);
  } catch (e) {
    console.error(e);
  }
}

Errores

  • Olvidar await (obtienes la promesa, no el valor)
  • No usar try/catch (errores no controlados)
  • Cadenas secuenciales innecesarias: usa Promise.all cuando sean independientes
