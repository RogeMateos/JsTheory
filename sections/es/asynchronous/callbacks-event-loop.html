Asincronía: callbacks y event loop

Conceptos base

Callbacks

  • Definición: función pasada como argumento que se ejecuta al terminar la operación.
  • Uso: primer mecanismo para manejar asíncronos en JS.

setTimeout

  • API nativa para ejecutar código después de un tiempo.
  • El callback se encola; no bloquea el hilo.

Event Loop

  • Coordina la ejecución en un solo hilo.
  • Call Stack: código síncrono
  • Web APIs/Node APIs: manejan tareas async
  • Task Queue / Microtask Queue: callbacks esperando

Ejemplos

setTimeout básico

console.log("start");

setTimeout(() => {
  console.log("se ejecuta después de 2s");
}, 2000);

console.log("end");
// start
// end
// se ejecuta después de 2s

Orden: start/end se ejecutan en stack; el callback va a Web APIs y luego a la cola cuando el stack esté libre.

Callback hell

step1(() => {
  step2(() => {
    step3(() => {
      console.log("completado");
    });
  });
});

Problema: difícil de leer/mantener.

Analogía del restaurante

  • Call Stack: chef
  • Web APIs: horno/micro
  • Task Queue: platos listos
  • Event Loop: mesero que trae el siguiente plato cuando el chef queda libre

Flujo del loop

  1. Ejecuta síncrono en Stack
  2. Delegar async a Web APIs
  3. Callbacks a colas (micro / macro)
  4. Si Stack vacío, mueve microtareas y luego tareas
  5. Repetir

Buenas prácticas

  • Callbacks para casos simples
  • Para dependencias múltiples, usar Promesas o async/await
  • Manejar errores siempre en callbacks

Errores comunes

  • Callback hell (anidación excesiva)
  • Suponer que async corre en el orden escrito
  • Olvidar que JS es single-thread

Ejercicio rápido

console.log("A");

setTimeout(() => console.log("B"), 0);
console.log("C");
setTimeout(() => console.log("D"), 100);
console.log("E");
// Orden: A, C, E, B, D

Conecta con: Promesas, async/await, Fetch API, y el event loop en Node.js.
